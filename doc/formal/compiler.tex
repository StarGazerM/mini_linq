\begin{abstract}
Query compilation combines declarative relational meaning with operational
choices about storage, traversal and host computation. MiniLinq exposes this
combination as independently usable languages embedded in Rust: conjunctive
queries with host expressions, named relational plans, index requirements,
local access plans and iterator pipelines. We ask what each compilation edge
must preserve for its implementation to be replaceable. An executable
walkthrough follows a computed join key, guard and result through every
existing boundary. Administrative rules specify graph reduction, semijoin
planning, dependency-constrained clauses, retention, indexing and staged
lowering, with conditional relational and finite-cursor proofs.
We distinguish relation abstraction from enumeration and client observations:
equal answer sets do not imply equal partial-demand or effect behavior.
Executable witnesses show that lazy and materialized evaluation can produce
different answer sets with stateful Rust clauses, even without changing their
written order. A finite state-and-trace model explains this distinction and
isolates an interchange condition; a dynamic provenance model distinguishes
value, control and state dependencies from recorded execution order.
The artifact pairs rules with implementation symbols and combines independent
valuation and graph oracles with compiled end-to-end tests. The account
explicitly separates proved mathematical properties, bounded implementation
evidence, and unresolved source-effect, Rust-adequacy and conformance
obligations. It does not assert a compiler-correctness theorem for arbitrary
accepted Rust expressions.
\end{abstract}
