# Planning coverage from the notes to passes and code

This inventory covers notes 1.3 and 2.1–2.5 at the revision recorded in
[TERMINOLOGY.md](TERMINOLOGY.md). “Implemented” identifies a corresponding
algorithm; it does not discharge the Rust conformance or host-semantics
obligations. The formal TeX files describe the underlying logical ideas;
the implementation column identifies the current CQ-NF → VO → RA chain.
For physical choices after planning, see the
[IX section](ix_physical_contract.tex) and the [Physical](../../languages/cq-lang-physical/src/lib.rs) and
[Structures](../../languages/cq-lang-structures/src/lib.rs) crate documentation.

| Concept and note | Formalization and translation to RA | Implementation and boundary |
| --- | --- | --- |
| Valuations, conjunction, and ordered answers ([1.3][note-1.3]) | [foundations.tex](foundations.tex) defines valuation relations, natural join, positional renaming, projection and ordered head rendering. A VO plan specifies the valuation-building steps; elaboration turns those steps into named RA and a final head projection. | [Normalization](../../languages/cq-lang-cq/src/normal.rs) creates CQ-NF; [ordering](../../passes/cq-order/src/lib.rs), [reduction](../../passes/cq-reduce/src/lib.rs) and [elaboration](../../passes/cq-elaborate/src/lib.rs) carry its structural content; elaboration's separate check compares fixed occurrences, equality closure, relational constraints, Rust ancestry and Before facts. Correctness is refinement of desugared written order in bottom + finite Set under Leibniz identity and functional extensionality. |
| Binary logical join plan ([1.3][note-1.3]) | A Coarse VO plan has one full subatom per atom occurrence, so each later atom combines with the current valuation prefix. Fine splits atoms into variable-at-a-time subatoms. | [VO](../../languages/cq-lang-vo/src/lib.rs) records the plan; [elaboration](../../passes/cq-elaborate/src/lib.rs) emits natural joins and partial-subatom checks. The valuation order differs from the join tree used for reduction and from the RA dependency DAG. |
| SIP adjacency and full shared-variable labels ([2.2][note-2.2]) | The shared-variable label is the full nonempty intersection after expanding relational variable equality classes. Rust-free blocks contribute their free/interface heading. Guards and bindings contribute no SIP vertices. | [`cq::hypergraph::Analysis`](../../languages/cq-lang-cq/src/hypergraph.rs) records clause variables and incidence. There is no separate SIP-graph IR. SIP adjacency alone neither chooses a VO order nor decides alpha-acyclicity: star and triangle bodies can both have SIP graph K3. |
| Occurrence hypergraph and whole-tuple constraints ([2.3][note-2.3]) | Each atom keeps its clause identity, ordered positional mapping and entire variable set; a ternary tuple constraint is not replaced by pairwise witnesses. | [Normal form](../../languages/cq-lang-cq/src/normal.rs) makes atom arguments distinct variables, [analysis](../../languages/cq-lang-cq/src/hypergraph.rs) records each occurrence, and [elaboration](../../passes/cq-elaborate/src/lib.rs) renames the complete source relation at its first mention. |
| Repeated relation occurrences, equal hyperedges, and reversed arguments ([2.3][note-2.3]) | Equal variable sets do not identify atom occurrences; positional mappings distinguish `road(a,b)` from `road(b,a)`. | VO subatoms carry clause indices, including for self-joins. Repeating a variable within an atom, as in `road(x,x)`, is normalized to a fresh atom variable plus a relational identity at the atom position. Equality classes preserve connectivity in graph analysis. |
| Matched columns, new columns, Cartesian products, and joins that only filter ([2.1][note-2.1], [2.4][note-2.4]) | For headings V and W, matched columns are V intersect W and new columns are W minus V. A natural join with no matched columns is a product; a partial subatom with no new columns tests existing valuations. | [Elaboration](../../passes/cq-elaborate/src/lib.rs) emits natural joins or semijoins from VO steps. [IX analysis](../../passes/cq-index-policy/src/lib.rs) records demands, including empty-column demands; [physical lowering](../../passes/cq-physical-lowering/src/lib.rs) selects concrete operators later. |
| Constants and their graph marks ([1.3][note-1.3], [2.2][note-2.2], [2.4][note-2.4]) | The note's SIP definition includes constant marks. In CQ-NF, a literal becomes a fresh atom argument constrained by relational literal equality at that atom's position. | [`normalize`](../../languages/cq-lang-cq/src/normal.rs) appends literal identities after their atoms; there is no global literal-binding prefix. [Hypergraph analysis](../../languages/cq-lang-cq/src/hypergraph.rs) uses atom variables, not constants as separate vertices. |
| Selection and filter pushdown ([2.4][note-2.4], [2.5][note-2.5]) | Central comparisons may move earlier and restrict a complete binder occurrence. Opaque guards and binds retain one written chain and every relational predecessor. | [`cq-order`](../../passes/cq-order/src/lib.rs) checks readiness and Before; [`cq-elaborate`](../../passes/cq-elaborate/src/lib.rs) pushes relational constraints to eligible earlier flat binders. `cq-reduce::Pushdown::Atoms` is a compatibility spelling that moves no Rust guard. No general predicate-placement search exists. |
| Pruning at the last remaining use, including any completed subtree ([2.4][note-2.4]) | [planning.tex](planning.tex) describes why projected witnesses can merge under set semantics and how a retained heading can be justified. | Current [elaboration](../../passes/cq-elaborate/src/lib.rs) projects partial subatoms, block interfaces/domains, reduction supports and the final head; [Structures](../../languages/cq-lang-structures/src/filtered.rs) can record checked filtered payloads. The pass chain does not implement general last-use pruning over completed RA subtrees. |
| Join trees, alpha-acyclicity, and GYO ([2.5][note-2.5]) | Running intersection characterizes a join tree; GYO removes private variables and contained residual edges to decide alpha-acyclicity. | [`cq::hypergraph::Analysis`](../../languages/cq-lang-cq/src/hypergraph.rs) records GYO steps, acyclicity and the join tree when present. Residual edge removal never deletes an executable atom. |
| Pairwise support versus complete support; YA reduction ([2.5][note-2.5]) | A full reducer semijoins along the join tree upward and downward, using all shared variables on each edge. Pairwise support alone is not complete support for a cyclic body. | [`cq-reduce`](../../passes/cq-reduce/src/lib.rs) inserts `Reductions::Tree` only for acyclic plans; [`cq-elaborate`](../../passes/cq-elaborate/src/lib.rs) emits semijoins over current clause relations. This does not assert projected-output-linear enumeration. |
| Connected, disconnected, and cyclic shapes ([2.2][note-2.2], [2.5][note-2.5]) | A disconnected acyclic body can have empty separators; a later natural join with no shared variables is a product. Cyclicity does not make the CQ invalid. | Analysis distinguishes acyclic from cyclic bodies. The external Hypergraph planner selects Tree when acyclic; when blocks exist it also inserts direct atom-to-block cuts, including on cyclic bodies. The default facade performs no reduction. |
| Choosing an order versus checking its legality ([2.1][note-2.1], [2.5][note-2.5]) | VO makes the valuation order explicit: Written, Prefix with Connected/GreedyWidth/Auto ranking, or Elimination; Coarse and Fine set its granularity. | [`cq-order`](../../passes/cq-order/src/lib.rs) compiles the selected options and checks the resulting VO contract. Its separate `check` validates preservation, split granularity and Written introducing-subatom order; it does not replay Prefix/Elimination rankings. [Analysis](../../languages/cq-lang-cq/src/hypergraph.rs) supplies the elimination order. These heuristics make no cost-optimality guarantee. |
| Logical heading arity ([2.4][note-2.4]) | [planning.tex](planning.tex) distinguishes heading arity of named RA results from cardinality and elimination width. | Current [hypergraph analysis](../../languages/cq-lang-cq/src/hypergraph.rs) records elimination width plus one, a different measure. Current [VO](../../languages/cq-lang-vo/src/lib.rs) and [RA](../../languages/cq-lang-ra/src/lib.rs) contracts validate headings but do not expose a maximum-arity rejection option. |
| Cardinality, logical row-volume W0, and data-dependent order choices ([2.1][note-2.1], [2.5][note-2.5]) | [planning.tex](planning.tex) defines cardinality separately and W0 as a sum of RA natural-join output cardinalities on an instance. | These are analysis and example measures; no cardinality estimator or W0-minimizing order option is implemented. Neither W0 nor heading arity is a runtime-cost theorem. |
| Physical tuple bytes and graph-decomposition widths ([2.4][note-2.4], further directions in [2.5][note-2.5]) | The notes distinguish logical arity, tuple cardinality, physical bytes and decomposition widths. | No byte-width cost model, fractional-width optimizer or WCOJ performance claim is established here. Fine VO plans provide variable-at-a-time generic join steps; the Structures language binds reads to host keys or built types ([cq-lang-structures](../../languages/cq-lang-structures/src/lib.rs)). |
| Arbitrary Rust expressions and directional requirements | A computed atom argument becomes an opaque bind before or after its atom; local computations additionally require a relational identity. Computed heads become final binds. | [Normalization](../../languages/cq-lang-cq/src/normal.rs) fixes the desugared reference positions; [ordering](../../passes/cq-order/src/lib.rs) retains free-variable binders, one Rust chain and Before. [constraint_planning.tex](constraint_planning.tex) illustrates an accepted authored plan. An undirected edge does not encode computation direction. |
| From logical matches to concrete access ([2.1][note-2.1], [2.5][note-2.5]) | [ix_physical_contract.tex](ix_physical_contract.tex) gives RA → IX, preserving exact index demands; Physical and Structures then fix operators and reads ([cq-lang-physical](../../languages/cq-lang-physical/src/lib.rs), [cq-lang-structures](../../languages/cq-lang-structures/src/lib.rs)). | [Index analysis](../../passes/cq-index-policy/src/lib.rs), [physical lowering](../../passes/cq-physical-lowering/src/lib.rs), [structure selection](../../passes/cq-structure-selection/src/lib.rs) and the [printer](../../passes/cq-physical-realization/src/lib.rs) implement these boundaries; the [full-chain test](../../facade/mini-linq/tests/physical_query.rs) compares supported output with an independent oracle. |
| Union, fallback and external surface consumers | Core blocks project to common free/interface headings; union combines answers and ordered fallback chooses the first nonempty arm. Multi-rule heads desugar hygienically into core union. | [CQ blocks](../../languages/cq-lang-cq/src/blocks.rs) and [sugar](../../languages/cq-lang-cq/src/sugar.rs) feed recursive VO schedules, RA prime union/anti, IX anti demands and recorded Physical execution. Negation, aggregation, correlated subqueries and recursion live in [external consumers](../../features/extensions/Cargo.toml); remaining extension clauses fail core checking. |

Evidence includes the [normal-form and VO contracts](../../languages/cq-lang-vo/tests/valuation_language.rs),
[hypergraph tests](../../languages/cq-lang-cq/tests/hypergraph_analysis.rs),
[ordering tests](../../passes/cq-order/tests/order.rs),
[reduction tests over the shared cases](../../passes/cq-reduce/tests/reduce.rs),
[elaboration tests](../../passes/cq-elaborate/tests/elaborate.rs), and the
separate [full-chain test](../../facade/mini-linq/tests/physical_query.rs).
Normalization checks the CQ-NF contract. Order, reduction and elaboration
`compile` functions check their targets; separately callable `check` functions
validate source/target correspondence, with options for order and reduction.
Reduction checking permits dependency-respecting tree sibling orders, recursively
checks block cuts, and preserves every non-reduction step. Elaboration compares
declarations, head and fixed structural facts; it performs no homomorphism search.
The exact obligations are in [pass_contracts.tex](pass_contracts.tex). Logical oracle checks do not certify physical execution of every
authored plan. See
[evaluation.tex](evaluation.tex) for physical validation boundaries and
[foundations.tex](foundations.tex) for the semantic assumptions.
