\section{Computed arguments constrain planning}
\label{sec:constraint-planning}
An undirected hyperedge cannot express the direction of Rust computation.
In the paper's \code{constraint_planning} driver:
\begin{lstlisting}
answer(a,w) :- R(a,x), S(a,y), T(y,z),
  let k:i32 = combine(*x,*y),
  let p:i32 = left_key(k,*y), let q:i32 = right_key(*x,*z),
  U(p,q,w), if *x > 0, if permitted(k,*z), V(w);
\end{lstlisting}
The bindings require $\{x,y\}$, $\{k,y\}$ and $\{x,z\}$ respectively;
none supplies an inverse recovering its arguments. The opaque
\code{permitted} guard requires $\{k,z\}$ and follows the three binds in
one written Rust chain. The comparison $x>0$ is central and may move earlier,
shrinking those bindings' evaluation domains.

The independently authored RA retains the $R,S,T$ prefix before the binds,
selects $x>0$ on $R$, computes $k,p,q$ in order, then keeps
$\{a,p,q,k,z\}$. It joins with $U(p,q,w)\ltimes V(w)$ before applying
\code{permitted}; moving $V$ earlier is permitted. This retains every source
Before obligation and the guard's inputs. Its final projection keeps $a,w$.
The example calls \code{cq_elaborate::check} against the supplied VO; it
illustrates structural acceptance of an authored lower-language plan, not
search for an optimal placement. The compiler cannot move \code{combine}
before written $T$, even if its free variables are already bound, or swap
\code{permitted} with an earlier opaque bind.

For a computed atom argument, \code{S(f(k),z)} produces a bind before $S$
when $k$ is prefix-bound. In \code{S(k,f(k))}, the argument depends on a
name newly supplied by $S$, so normalization emits a bind after the atom and
a relational identity with its fresh column. These positions define the
written reference; availability alone is not a later movement license.

The driver checks automatic and authored RA/IX contracts and elaboration
correspondence. Separately, its whole-tuple oracle uses wrapping arithmetic
on eight input presentations (base, duplicate, all-empty, and five individual
empty inputs). It compares no generated-query execution with that oracle and
measures no intermediate runtime work. The \code{argument_placement} driver
checks the before/after placement of \code{g()} and \code{f(x)} structurally.
