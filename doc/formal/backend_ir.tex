\section{Sequence: the back-end level (design)}
\label{sec:backend-ir}\label{sec:sequence}
The structural contracts and machine grading of this section are implemented
by \code{cq-lang-sequence}; their rules are linked in the inventory. Runtime
trait premises and emitter correctness remain obligations. Sequence adds
one level below Structures, shared by every back end,
and states what below it is not a level: placement is a grading on Sequence
terms, the machine is a parameter of that grading, and each emitter is a
translation. The level names no data structure, no algorithm and no machine.

\subsection{Why one level, and why this one}
A level is justified when its denotation changes: it adds or forgets an
observable, so that a different class of programs becomes equal. Below
Structures exactly one such change happens. Every level through Structures
denotes a function into $T X=\bot+\mathrm{Set}_{\rm fin}(X)$ composed in
written order (Section~\ref{sec:denotation}); the sequential pull runtime
makes nothing else observable, so order, multiplicity before \code{canon},
evaluation counts, sizes and placement are all the emitter's to choose. A
parallel runtime makes positions and sizes decisions that change the
program (which positions form the parallel domain; what must be allocated
before it runs), and makes placement and partiality constraints on whether
a term can run at all (where a value is visible; that device code cannot
unwind). Positions and sizes change the objects: that is the Sequence
level. Placement and partiality constrain terms without changing their
values: that is a type-and-effect grading, not a level. Kernels, barriers
and launch shapes are derived from the grading: not a level, not syntax.

This is deliberately not progressive lowering in the MLIR sense. A pass
takes a whole program at one level to a whole program at the next; no
program mixes levels; the composition theorem of
Section~\ref{sec:composition} depends on that. A back end that needs a
construct the shared level lacks defines a complete diverged variant with
its own check, as \code{diverged-ra} does; nothing is mixed into the shared
level.

\subsection{Objects: the sequence monad and its morphisms}
Let $\mathrm{Seq}$ be the finite-sequence monad: $\eta(x)=\langle x\rangle$,
$\mathsf{map}$ its functor action, $\mathsf{flatten}:\mathrm{Seq}(\mathrm{Seq}\,X)\to\mathrm{Seq}\,X$
its join. $\mathrm{Bag}$ and $\mathrm{Set}$ are monads likewise, and the
forgetful maps are monad morphisms:
\[
 \mathrm{Seq}\xrightarrow{\ \alpha\ }\mathrm{Bag}\xrightarrow{\ \mathrm{supp}\ }\mathrm{Set},
 \qquad \alpha\circ\mathsf{flatten}=\mathsf{join}_{\rm Bag}\circ\alpha\circ\mathrm{Seq}(\alpha),
 \quad \alpha\circ\mathsf{map}\,f=\mathrm{Bag}(f)\circ\alpha .
\]
The front end computes in $\bot+\mathrm{Set}$; Sequence computes in
$\bot+\mathrm{Seq}$; the refinement obligation is that the morphism of the
result equals the front-end value. Parallel admissibility is exactly the
structure $\mathrm{Bag}$ has and $\mathrm{Seq}$ lacks: its monoid is
commutative, so a fold over it is schedule-independent, and $\alpha$
forgets the order a schedule imposes.

A Sequence object is a nested sequence of \emph{coded} rows together with
its shape. Its type carries its lengths as symbolic expressions over input
lengths and earlier scans (size-dependent types in the sense of
Lift and Futhark~\cite{paper-lift,paper-futhark}); a term whose length is
not expressible is given a declared capacity. A codec
$\kappa=(\mathsf{enc},\mathsf{dec})$ with $\mathsf{dec}\circ\mathsf{enc}=\mathrm{id}$
on its domain refines row values; $\alpha$ applies $\mathsf{dec}$ per
column. A \emph{space} is a shape considered on its own: a finite index set
with lexicographic order and nesting.

\subsection{Terms}
$f$ ranges over per-position maps built from the total Physical kernels
(rename, project, relational select, point and range reads, semi and anti
tests over admissible keys; ST-Total). $b$ ranges over providers.
\begin{lstlisting}
t ::= rows r                     // the positions of a retained result or host
    | map f t                    // per-position total map
    | flatten t                  // join; offsets are the scan of lengths
    | compact p t                // total filter, order-preserving
    | tile n t                   // view: regroup into runs of n
    | lookup b [K] t             // per-position bucket of provider b
    | fold (o,e) t               // monoid fold
    | canon t                    // support
    | store t                    // materialize (the only non-view)
    | choose [ g => t ]*         // size-guarded equal alternatives
\end{lstlisting}
\code{tile}, \code{flatten} over known offsets, \code{lookup} over a range
cursor and the gathers inside $f$ are \emph{views}: bijections on positions
that change addressing and materialize nothing (Lift's layout patterns,
Descend's views~\cite{paper-lift,paper-descend}). Only \code{store}
materializes; a segmented stored \code{flatten} retains offsets (BE-Offsets).
Under BE-Alpha, constructors are lifted through outer tile levels:
\code{map}, \code{compact}, \code{lookup}, \code{fold}, \code{canon} and
\code{store} operate on innermost rows and preserve those outer partitions;
\code{flatten} joins the two innermost levels. Thus a lookup followed by
flatten under a tile preserves that tile. Analysis records lengths at every
level (a tile has $\lceil L/n\rceil$ parts and at most $n$ rows per part),
while $\alpha$ forgets all partition levels. A collaborative store can hold
one part; a separated store publishes the concatenation of its outer parts.
\begin{mathpar}
\Rule{BE-Alpha}{}
 {\alpha(\mathsf{map}\,f\,t)=\mathrm{Bag}(f)(\alpha t)\quad
  \alpha(\mathsf{flatten}\,t)=\alpha t\quad\alpha(\mathsf{tile}_n t)=\alpha t\quad
  \alpha(\mathsf{compact}\,p\,t)=\alpha t|_p\quad\alpha(\mathsf{store}\,t)=\alpha t}

\Rule{BE-Bind}{}
 {\sem{\mathsf{probe}[K](l,b)}=\mathrm{supp}\,\alpha\big(\mathsf{flatten}(\mathsf{map}\,(x\mapsto x\bowtie\mathsf{lookup}_b[K]\,x)\,l)\big)}

\Rule{BE-Partition}{\{P_k\}\text{ disjoint}\quad\textstyle\bigcup_kP_k=[0,|t|)\quad
 (\oplus,e)\text{ commutative}}
 {\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t)=\textstyle\bigoplus_k\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t|_{P_k})}

\Rule{BE-Offsets}{o=\mathsf{scan}_{(+,0)}(|t_0|,\ldots,|t_{|t|-1}|)}
 {(\mathsf{flatten}\,t)_j=(t_i)_{j-o_i}\text{ for the unique }i\text{ with }o_i\le j<o_{i+1}}

\Rule{BE-Canon}{\alpha t=B}
 {\alpha(\mathsf{canon}\,t)=\iota(\mathrm{supp}\,B)\quad
  \mathsf{canon}(\textstyle\biguplus_kB_k)=\mathsf{canon}(\textstyle\biguplus_k\mathsf{canon}\,B_k)}

\Rule{BE-Code}{\mathsf{dec}\text{ injective on }K\text{ (both sides)}\quad
 \mathsf{enc}\text{ monotone on }c}
 {\text{equality, hashing and canon on }K\text{, and order reads on }c\text{, act on codes}}

\Rule{BE-Choose}{t_1,\ldots,t_n\text{ have checked equal support}\quad
 \text{guards }g_i\text{ over lengths, exhaustive}}
 {\mathsf{choose}\,[g_i\Rightarrow t_i]\text{ denotes any }t_i\text{; which runs is free}}
\end{mathpar}
BE-Bind is the Kleisli bind of Section~\ref{sec:denotation} restated: a
probe is a flatten of per-row lookups, so a join nest is a nested flatten
and flattening it (NESL~\cite{paper-nesl,paper-ndp-gpu}) is what removes
irregular nesting. A sequentially evaluated flatten of lookups needs only
exact buckets, including when its rows are stored. The contiguous-range
capability (rangeCursor) is required for a segmented flatten, a domain
consumed by a \code{Distribute} tile, or lengths folded collectively below
host. A \code{Strip} tile and an ordinary row store do not introduce this
requirement. Structural inference is shared by every machine; grading adds
only the range obligations of the actual distributed execution context,
not of unused child levels in the machine.
A \code{flatten} or \code{fold} graded at a
leaf level (one sequential executor) is a loop, not a collective; BE-Collective
constrains only terms graded at a level whose members jointly evaluate them. BE-Partition is the law every schedule relies on; it
holds for partial $f$ (one undistinguished $\bot$) but licenses no early
stop and is stated on bags: a lost or duplicated position changes
$\alpha$. BE-Canon makes per-part canon a sound prefilter that replaces
the global boundary only when equal rows meet in one part. BE-Choose is
incremental flattening~\cite{paper-futhark-flatten}: the right
decomposition depends on lengths known at run time, so several equal
decompositions may be recorded under thresholds that are tuning
parameters, not meaning.

\paragraph{Providers and codecs are capabilities.} A provider is read
through \code{lookup} and the term records only what the read requires:
exact bucket, contiguous range (rangeCursor), membership, order. Its type
is an opaque token discharged by runtime traits, as Structures does today
(STR-Key, STR-SortedRun); the same holds for codecs (BE-Code's premises
are trait obligations, like Leibniz admissibility) and for \code{canon}.

\subsection{Placement: a grading over a machine parameter}
\begin{definition}[Machine model]
A finite tree of \emph{levels} $\ell$, each labelled: \emph{collaborative}
(members share storage and may synchronize; collectives are available) or
\emph{separated} (members share nothing and exchange only through a store
at a common ancestor, at a boundary); scheduling static or dynamic; and a
failure channel to the root. The root is $\mathsf{host}$.
\end{definition}
\begin{center}
\begin{tabular}{@{}p{0.16\linewidth}p{0.4\linewidth}p{0.2\linewidth}p{0.16\linewidth}@{}}
\toprule
 & GPU (SIMT, cooperative groups) & tasks (Rayon) & sequential\\
\midrule
levels & host $>$ device $>$ block $>$ warp $>$ lane & host $>$ pool $>$ task & host\\
collaborative & block (shared memory, barrier), warp (lockstep) & none & —\\
separated & device/host; block/block (no forward progress) & task/task (join) & —\\
scheduling & blocks dynamic, order undefined & work stealing & fixed\\
failure & flag read by host & panic at join & unwind\\
\bottomrule
\end{tabular}
\end{center}
A Sequence term is \emph{graded}: each subterm carries the level that
evaluates it, each \code{store} the level that holds it, and \code{tile}
descends one level. The grading is a type-and-effect discipline, not a
language: it is checked against the machine parameter and changes no value.
Execution resources in the sense of Descend~\cite{paper-descend} are the
GPU instance of the grade.
\begin{mathpar}
\Rule{BE-Scope}{\mathsf{store}\,t\text{ at }\ell\quad\text{a read at }\ell'\le\ell\text{ lexically inside its extent}}
 {\text{the read is admissible}}

\Rule{BE-Collective}{\mathsf{fold}/\mathsf{scan}/\mathsf{flatten}\text{ at }\ell\quad\ell\text{ has members}\quad\ell\text{ collaborative}\quad
 \text{the whole of }\ell\text{ participates}\quad\oplus\text{ associative}}
 {\text{equals the sequential fold; commutative }\oplus\text{ makes it schedule-independent}}

\Rule{BE-Separate}{\ell_1,\ell_2\text{ separated siblings}}
 {\text{they exchange only through a store at a common ancestor; nothing else is observable across them}}

\Rule{BE-Length}{\mathsf{store}\,t\text{ at a separated level (host stores need no bound)}}
 {|t|\text{ is in its type before the write (a scan), or a capacity with an overflow flag}}

\Rule{BE-Boundary}{\text{a maximal segment of total terms between stores at a separated level}}
 {\text{is one unit of dispatch (a kernel, a task); its domain is the outer stored space; derived, not written}}

\Rule{BE-Partial}{\text{opaque Rust }e}
 {e\text{ runs at }\mathsf{host}\text{ only: closed }e\text{ once before dispatch (IF-Parameter); row-dependent }e\text{ never below host}}

\Rule{BE-Abort}{\bot\text{ raised below }\mathsf{host}}
 {\text{a once-set flag on the failure channel, mapped to }\bot\text{ at the next host boundary; no truncated success}}

\Rule{BE-Resource}{d\text{ a checked dispatch at }\ell\quad
 \mathsf{layout}_M(\mathsf{shape}(d))\le\mathsf{capacity}_M(\ell)}
 {\text{the dispatch fits the bounded resource of its machine level}}
\end{mathpar}
The resource shape records every branch, payload lookup, live parent column
with its checked type and codec facts, fold, tile and item count. Byte layout
and alignment belong to the target-supplied machine, not to the language.
An unbounded level imposes no capacity premise. A bounded level without a
layout model, arithmetic overflow, or an oversized layout is rejected before
translation, including for explicitly advised programs. Resource recovery
enumerates checked alternatives in fixed order: nested inner-flatten
segmentation at preferred geometry, smaller item counts, then smaller strips
derived by halving the machine width. Only after these fail may it add
dispatch-splitting publications. Every candidate satisfies all grading and
catalog premises, including BE-Resource; PL-Cost compares the legal segmented
and plain schedules at the first feasible geometry. If none fits, rejection
retains all diagnostics from every attempted candidate.

The laws mention only labels of the machine parameter. A term that uses a
collective at a level the target marks separated is rejected for that
target, not reinterpreted. BE-Boundary derives kernels (GPU) and tasks
(Rayon) from the grading: the domain of a dispatch is the type of its outer
stored space, which replaces the current printer's
\code{driver.len.div\_ceil(1024)}; storing the H05 Customer level as
offsets makes the next dispatch span every customer. Written order has no
force below host: nothing partial is there (BE-Partial), so inside a
dispatch the full set algebra applies.
A store at a separated level is publication: a depth-zero producer is one
part at its unique child. Its outermost tile in dataflow order distributes parts over that
child; further tiles in the same definition strip-mine jointly at the
current effective level, and \code{items} assigns positions per member
without adding a level. A tile in a non-separated definition also
strip-mines; distribution to a deeper level requires a separately graded
definition. Analysis records each tile's interpretation and the dispatch's
producer level, outer tile width and concatenation protocol (count/scan,
reserve or bounded); publication concatenates the parts in part order.
The same publication rule applies to non-final stores. In
\code{p = t} graded at an explicit descendant execution extent and
\code{s = store p} graded at host, the producer executes at its recorded
grade and the completed store is published at host. Only the store encloses
that execution; a plain host reference to a descendant value is still
ill-scoped. Factoring a producer into a fresh name changes neither rows nor
support (EXT-SeqStore). Independent arm stores can therefore be published
by separate dispatches and concatenated by a host \code{union}, without a
dispatch spanning two outer stored spaces.
Conversely, a separated descendant store may name a host-graded producer.
The host producer is evaluated first, its completed length is known before
the write, and the projected rows are transferred into the descendant store.
This downward publication is an upload, not a GPU query dispatch; subsequent
lookup execution uses the stored layout without re-evaluating its predicate.

\paragraph{Output.} The final \code{flatten} into one stored sequence of
unknown length is one term with several interpretations, equal under
$\alpha$: lengths computed first by a count pass (purity, premise~3,
licenses running the map twice), reservation by a commutative concatenation
(schedule-dependent positions, same bag), or a bounded buffer with retry.
Which is recorded, because it changes the program. Parts write only
positions they own by a view, or buffers they allocated; nothing reads
another part's fresh allocation before a boundary. That is
disentanglement~\cite{paper-disentangle}, the memory property that makes
these protocols lock-free.

\paragraph{Cost.} The set model has no cost; Sequence has work and
span~\cite{paper-nesl}: work the number of positions evaluated, span the
longest dependency chain. Plan R's two schedules have equal work; a
one-part schedule has span proportional to work, a grid-wide one span
logarithmic. Cost is not meaning; it is what a decomposition pass argues
with, and lengths in types are what make it computable.

\subsection{Decomposition}
A planner is an advice generator, not another interpretation of Sequence.
Its inputs are a Sequence program $t$, a machine $M$, and an ordered catalog
$K$ of target-supplied provider, codec and canon tokens with capabilities
and admissible levels. The catalog is data: shared planning and checking
do not depend on a target implementation. A successful result is a graded
program together with a replayable trace of the existing Sequence rewrites.
Let $t_0=t$, $t_i=r_i(t_{i-1})$, and let $A(t)$ record authored choices.
\begin{mathpar}
\Rule{PL-Closure}{\mathsf{plan}(t,M,K)=(t', [r_1,\ldots,r_n])}
 {t'=t_n\quad
  \forall i.\ \mathsf{check\_rewrite}(t_{i-1},t_i)\quad
  \mathsf{check\_grading}(t',M)}

\Rule{PL-Precedence}{\mathsf{plan}(t,M,K)=(t',\rho)}
 {A(t')|_{\mathrm{dom}(A(t))}=A(t)}

\Rule{PL-Det}{(t,M,K)\text{ fixed}\quad
  \text{candidate and catalog order fixed}}
 {\mathsf{plan}(t,M,K)\text{ has one result (or one rejection)}}

\Rule{PL-Select}{s'=\mathsf{retainUnsupportedHostReads}(s,K)\quad
 e\in\mathsf{Structures}(s')\quad
 k=\mathsf{first}\{k\in K\mid \mathsf{needs}(e)\subseteq\mathsf{caps}(k),
 \ \mathsf{levels}(k)\ne\varnothing,\
 \mathsf{elements}(e)\subseteq\mathsf{acceptedElements}(k)\}}
 {\mathsf{select}(s,K):\
 e.\mathsf{type}\gets k.\mathsf{type}\quad\text{by checked retention, index construction and retype}}

\Rule{PL-Cost}{C=(c_1,\ldots,c_k)\text{ admissible, preserving }A(t)\quad
  \kappa(c)=(W(c),I(c),S(c),\#\mathsf{stores}(c),\#\mathsf{dispatches}(c))}
 {c^*=\mathsf{foldl}\bigl(
   (a,b)\mapsto\text{if }\kappa(b)\prec\kappa(a)\text{ then }b\text{ else }a,
   c_1,(c_2,\ldots,c_k)\bigr)}
\end{mathpar}
Catalog levels describe where a provider may be read, not where its owner is
constructed. Building an index from host rows does not certify a host read.
Placement must select a supported read level; authored unsupported grades are
rejected rather than silently reinterpreted.

PL-Closure inherits its value laws from BE-* and the Sequence extension
rewrites; it adds no new equality of values. PL-Precedence preserves
authored grades, tiles, stores, choices, output protocols and codec/canon
tokens: planning fills missing decisions rather than optimizing them away.
PL-Det includes rejection when no catalog token satisfies a recorded
obligation. PL-Cost uses the work and span of the preceding Cost paragraph,
not a semantic preference. Here $\prec$ is provable strict lexicographic
symbolic cost dominance: work first, then Lookup/Expand inversions $I$,
span, stores and dispatches. An inversion is a Lookup evaluated after an
upstream Expand in the same pipeline; retained references begin new pipelines.
Bounds and coefficient dominance establish comparisons; unresolved
comparisons, like equal costs, retain the earlier candidate.
Resource recovery first preserves the machine's preferred item count and
distributing width, trying nested segmentation before reducing either.
At each geometry PL-Cost compares admissible segmented and plain candidates;
strict improvement replaces the earlier candidate, preserving stable ties.
Dispatch splitting is a last resort, never a substitute for an admissible
single-dispatch segmentation. All tiers retain authored tiles, grades and stores.

A planning invocation may reuse a structural proof only for an equal complete
Structures prefix and equal Sequence and evidence syntax. Machine grading is
checked separately for every requested grade. The join-support certificate
interns relation and column names into invocation-local integer identities;
its cache keys retain the complete ordered graph, headings and query atoms.
Neither a hash collision nor evidence establishes an equality. Syntax trees
remain the source of spans and opaque Rust equality; proof comparison does
not require rendering those trees to token strings.

PL-Select is an explicit Structures selection operation before decomposition,
not an implicit override by PL-Precedence. It visits built indexes, sets,
row buffers and canon providers in recorded entry order, selecting the first
catalog token satisfying all reads of that entry; host scan adapters are unchanged.
Unsupported integral keyed host stream reads first use the checked Physical
\code{build\_host\_reads} retention rewrite, then receive a built index
checked by Structures. Obsolete keyed host fallback entries are removed;
the original host scan adapters remain unchanged. A built index supplies
the keyed obligation rather than claiming that column encoding supplies
an unavailable provider capability.
Structures has no machine grading, so selection requires host publication.
Later Sequence planning validates every actual execution level.
Provider tokens may restrict scalar row element types; an omitted restriction
accepts any type. Both built-index selection and host-fallback retention
check the recorded stored-row layout (including checked filtered projection),
and final catalog discharge checks it again at the actual execution grade.
A numeric-only device provider cannot be selected
for a row carrying a \code{String}; a compatible host token or a rejection
is required.
Each substitution uses the existing source/target Structures retype checks;
an absent token or inadmissible retention rejects with the obligation.
Placement propagates opaque evaluation and its unstored feeds to host before
assigning descendant work. String-literal predicates and operations reading
or producing String-bearing rows likewise stay host through the projection
that publishes a numeric-only row. Independent named union arms with distinct stored
domains are published separately, then concatenated at host; neither rule
weakens BE-Partial or BE-Boundary.
An already-checked Sequence store cuts opaque Physical provenance, including
for lookup providers: descendant reads consume the materialized rows rather
than re-evaluating the host guard. This requires no asserted totality marker.
Guard-result carriers project away columns absent from the checked downstream
required-column set. The guard still receives its complete required input;
this representation projection happens after evaluation and does not change
its written domain or assert totality.
Unknown lengths remain type-length expressions rather than measured input
data or invented cardinalities. Work counts evaluated constructor positions;
aliases, tiles and stores add no evaluation work, with stores a separate
cost tier. Span follows dependencies, taking the maximum over branches.
An actual graded distribution introduces a symbolic maximum-part length
constrained by its driver, rows and machine width, not by multiplying tile
width by items.

The decision procedure is bounded enumeration. Host rows remain at host;
publication and stores consumed by lookup or canon use the deepest
admissible level, while intervening terms inherit producer placement.
Below host, the first fanout in a flatten chain uses the distributing
machine level's static width, if available. It first tries nested stores and
inner tiles with preferred items, then plain tiling at the same geometry.
Only if neither fits does it halve items to one, then halve the machine-derived
strip width to one. If every geometry fails, named publication boundaries
split dispatches, with choice/union publications as the last tier. Where separate
rewrites cannot express this decomposition, the checked \code{segment}
rewrite pairs an inner-flatten store with an outer tile, justified by
BE-Offsets and BE-Partition and exposed through both the library and macro.
Recorded output protocols, including count inserted by lowering, are preserved. Only absent
protocols are filled: count when the final length depends only on input
lengths, otherwise reserve; a bounded protocol requires an authored
capacity. Reported provider, canon and codec obligations are validated
against catalog capabilities at their levels. Structures already records
provider and canon types; planning does not replace them or add selection
syntax. Codec laws remain abstract runtime premises; planning validates
catalog support, not those laws. Every proposed rewrite and the resulting
grade are checked; no emitter decision is introduced.


\subsection{Refinement and the emitter}
\begin{definition}[Sequence refinement]
A graded Sequence program $t$ over Structures $s$ refines $s$ for machine
$M$ when, for every input and every schedule $M$ admits under
BE-Partition, BE-Scope, BE-Collective, BE-Separate and BE-Abort,
$\mathrm{supp}\,\alpha(\mathsf{run}_M(t))=\sem s$ whenever $\sem s\ne\bot$,
and $\mathsf{run}_M(t)$ aborts only if some sequential schedule of $s$ panics.
\end{definition}
The obligation splits per construct: BE-Alpha for the shape terms, storage
laws for provider and codec interpretations, BE-Partition and
BE-Collective for the schedule. An emitter is a translation from graded
terms to the target (loops, assignments, barriers, launches), in the sense
of DPIA's strategy-preserving compilation~\cite{paper-dpia}: correct per
construct, race-free by construction from the views, deciding nothing. A
construct without a translation is rejected. Lift derives allocation and
barriers from its types~\cite{paper-lift}; here they are derived from the
grading, lengths and views.

\paragraph{Sequential translation.}
\begin{mathpar}
\Rule{T-Pull}{t\text{ checked}\quad\text{every grade is }\mathsf{host}}
 {\mathsf{run}_{\rm seq}(t)=\text{the fold: }\mathsf{rows}\mapsto\text{host rows},\
  \mathsf{map}/\mathsf{compact}\mapsto\text{the Physical row function},\
  \mathsf{lookup}\mapsto\text{the recorded capability},\
  \mathsf{flatten}\mapsto\text{iterator concatenation},\
  \mathsf{tile}/\mathsf{choose}\mapsto\text{identity (one part, else arm)},\
  \mathsf{fold}\mapsto\oplus,\ \mathsf{canon}\mapsto\text{the recorded provider},\
  \mathsf{store}\mapsto\text{intermediate }\code{Vec}\text{ or final count iterator}}
\end{mathpar}
The host-only translation leaves the final store with \code{output count}
as a lazy pull iterator (BK-Dual); it does not collect the output into a
\code{Vec}. Intermediate stores materialize, and rows escaping block-local
storage may be collected to preserve their lifetime. The target-hook
\code{translate_with} path remains materializing for task and GPU targets.
The sequential interpretation preserves support under the provider laws and
propagates Rust failure by unwinding.

\subsection{Passes}
\begin{mathpar}
\Rule{L-Sequence}{s\text{ checked Structures}}
 {\mathsf{lower}(s):\ \text{host rename}\mapsto\mathsf{rows};\
  \text{unary step}\mapsto\mathsf{map}/\mathsf{compact};\
  \text{probe, merge}\mapsto\mathsf{flatten}(\mathsf{lookup});\
  \text{semi, anti}\mapsto\mathsf{compact}(\mathsf{lookup}_{\rm membership});\
  \text{union}\mapsto\mathsf{union};\
  \text{let}\mapsto\mathsf{store};\ \text{canon}\mapsto\mathsf{canon};\
  \text{return}\mapsto\mathsf{store}\text{ with }\mathsf{output}\ \mathsf{count};\ \text{no tile, no grade}}
\end{mathpar}
The checker re-derives this construction and compares it structurally.
\begin{itemize}
\item Structures $\to$ Sequence: the default lowering records ``one part,
nothing stored'': every result is a view or a device/host store as its
Physical mode says, no tiles. The shipped CPU target checks sequential grading
and translates this Sequence program to a pull iterator, with an optional
profile-counter variant.
\item Sequence $\to$ Sequence rewrites, advice-driven as the existing
rewrites are (Section~\ref{sec:structures}), each with a law: store a
flatten level (BE-Offsets), tile a space (BE-Partition), record a
size-guarded alternative (BE-Choose), choose the output interpretation,
record codecs and canon.
\item Grading: assign levels against a named machine model; checked by
BE-Scope through BE-Abort.
\item Translation per machine.
\end{itemize}
This mirrors the algorithm/schedule separation of Halide and
Exo~\cite{paper-exo}: the pipeline's advice is the schedule, each primitive
is an equivalence-preserving rewrite with a stated law.

The external \code{cq-sequence-rewrites} passes check both programs and
construction-based support equality:
\begin{mathpar}
\Rule{EXT-SeqStore}{d=\mathsf{flatten}\,t}{d:=\mathsf{store}(\mathsf{flatten}\,t)\quad\text{(BE-Offsets)}}

\Rule{EXT-SeqTile}{n>0\quad d\text{ not an unbounded unknown-length store}}{d:=\mathsf{tile}_n\,d\quad\text{(BE-Partition)}}

\Rule{EXT-SeqChoose}{a,b\text{ have checked equal support}\quad\text{guards exhaustive}}{d:=\mathsf{choose}[g\Rightarrow a,\ \mathsf{else}\Rightarrow b]\quad\text{(BE-Choose)}}

\Rule{EXT-SeqOutput}{p\in\{\mathsf{count},\mathsf{reserve},\mathsf{bounded}\}\quad p=\mathsf{bounded}\Rightarrow\text{capacity declared}}{\mathsf{output}:=p}

\Rule{EXT-SeqGrade}{\text{machine }M\text{ named}\quad\text{placements }d_i\ \mathsf{at}\ \ell_i}{\mathsf{graded}\ M\{\ldots\}\text{ extended; the construction is unchanged}}
\end{mathpar}
\code{grade} records advice only: the facade's grading phase checks the
machine and BE-Scope through BE-Abort.

\subsection{Lookup and Expand}
\label{sec:lookup-expand}
Lookup and Expand separate the shrinking and growing parts of a join
\cite[Sections~3.2--3.4 and~4]{paper-diamond}.
Sequence already supplies both: a \code{lookup} names matching positions,
\code{compact(lookup)} tests their existence, and \code{flatten} expands
them. A stored filtered relation with an indexed provider carries the
forward phase across a publication boundary. No additional Sequence
constructor is introduced.

The join graph is extracted from checked Physical dependencies, using
shared attribute equivalence classes as edge weights. LargestRoot constructs
a maximum-weight spanning tree, rooted at the largest relation according to
available count evidence \cite[Section~3.1, Lemma~3.2]{paper-rpt}.
Unknown sizes retain deterministic syntax order, not invented cardinalities.
A projected index need not forbid its relation from becoming this root.
When its unfrozen Physical producer is a rename or a selection (including
point and range), and every consumer belongs to the replaced join region,
the rewrite can recover that producer's full-row stream using its existing
scan adapters. It removes the now-unread projected index and rebuilds any
opposite-side provider through the same catalog selection. It does not scan
or reinterpret the projected payload. Independently consumed, frozen and
union index producers retain their representation and remain ineligible for
this recovery. Structures liveness and the full support certificate are
checked again after the orientation change.
Among equally weighted parents the deepest parent wins, the chaining
forward-tree tie-break of ATP \cite[Section~3]{paper-rpt-plus}.
The forward phase retains predicate-bearing relations and bridge relations,
filtering before building the next provider. This restricted transfer
heuristic does not claim full semijoin reduction without its premises.
The scan root retains its authored streaming mode unless a keyed consumer
requires its retention. Root forward filters also stream: each has exactly
one consumer and never supplies a keyed child provider. Nonroot forward
filters remain retained for those provider builds. Resource decomposition
may subsequently introduce checked publications. Along a positive left spine, an existing
join or semijoin against the same named provider on all requested keys already
witnesses membership. The scheduler omits a repeated forward or Lookup filter
there, without dropping the later Expand. This local optimization stops at
opaque operators and never uses estimated keys, counts or selectivities as
proof. The complete rewritten construction still satisfies
\textsc{EXT-SeqLookup}.
If eliminating witnessed Lookups leaves the complete Physical program
unchanged, this ordering pass returns the original checked Sequence and
Structures verbatim. It does not use a no-op ordering decision to prune or
replace authored provider entries: representation-only rewrites remain
outside the join-reexpression certificate.

Expands are placed at the first consumer requiring the payload.
Cycle-closing lookups wait for the Expands that supply their keys
\cite[Section~4.2]{paper-diamond}; a spanning tree of a cyclic graph is
not asserted to be a join tree. In the acyclic case, tree-connected
subjoins satisfy the SafeSubjoin criterion
\cite[Section~3.2]{paper-rpt}. Evidence may prefer early Expand or a
different Lookup order but is never used to delete a required join.
Opaque Rust nodes remain pinned to their written Before domains.
A provider requiring another key layout may name a fresh retained identity
projection after that pinned prefix. Keeping the complete checked input
heading preserves support and positions; the support certificate treats only
such full-heading projections as transparent aliases. Other projections
remain opaque certificate nodes. Each provider name then has one recorded
layout, without requiring an interpreter to choose among layouts.
In particular, a predicate-bearing leaf is authored by putting its
predicate after that atom, not by a planner asserting the predicate total.

\begin{mathpar}
\Rule{EXT-SeqLookup}{t,t'\text{ checked}\quad
 \text{join/semijoin constructions have equal support}\quad
 \text{Rust Before domains preserved}}
 {t\rightsquigarrow_{\mathsf{lookup\_first}}t'
  \quad\text{(Motion, BE-Offsets, BE-Scope)}}

\Rule{EXT-SeqAdaptive}{s\text{ is a published filtered store}\quad
 \mathrm{supp}(\alpha(a))=\mathrm{supp}(\alpha(b))\quad k\text{ is advice}}
 {d:=\mathsf{choose}[
   \mathsf{len}(s)<k\Rightarrow a,\ \mathsf{else}\Rightarrow b]}

\Rule{PL-Evidence}{E\text{ is syntactically well-formed advice}\quad
 (t',\rho)=\mathsf{plan}(t,M,K,E)}
 {\mathrm{supp}(\alpha(t'))=\mathrm{supp}(\alpha(t))\quad
  \rho\text{ satisfies PL-Closure independently of the truth of }E}
\end{mathpar}

Evidence records row counts, keys, foreign keys, selectivities, bounds and
sortedness beside the analysis obligations, not as correctness premises.
Its consumers select the root, Lookup order, early Expand, and whether a
transfer filter is worth its cost. The RPT+ selective-filter heuristic
\cite[Sections~3.6 and~5]{paper-rpt-plus} uses static selectivity evidence
when present; otherwise a \code{choose} reads an already-published count.
The alternatives retain the exact joins, so even false evidence changes
execution time only. This is a boundary-count adaptation, not a claim to
implement RPT+'s in-flight sampling or cancellation.

The \code{Planner} interface accepts $(t,M,K,E)$ and returns a program and
replayable advice trace. Serialized author advice and generated advice use
the same checked operations. The facade's Sequence-input \code{plan = path}
phase may replace the rule-based implementation with an ordinary custom
pass; PL-Closure and the conformance harness remain unchanged.

\paragraph{GPU translation.}
\begin{mathpar}
\Rule{T-Gpu}{t\text{ checked against }\mathsf{host}>\mathsf{device}(\text{separated, dynamic})>\mathsf{block}(\text{collaborative})>\mathsf{lane}}
 {\mathsf{run}_{\rm gpu}(t)=
  \text{one query kernel per BE-Boundary dispatch};\
  \mathsf{tile}\mapsto\text{recorded distribution or strip-mining};\
  \mathsf{flatten}\mapsto\text{block scan and owner search};\
  \mathsf{store}\mapsto\text{shared storage or device publication};\
  \mathsf{canon}\mapsto\text{packed radix sort and unique}}
\end{mathpar}
Range providers are built before their query dispatches using stable radix
ordering and lower-bound directories. Membership searches within those
recorded ranges. The output protocol and sticky failure flags discharge
BE-Length and BE-Abort; bounded output retries rather than publishing a
truncated result. No target-side join order, uniqueness or tile choice is
inferred by the translation.

The CUDA machine bounds block shared storage by 101,376 bytes. Its single
layout implementation starts with 48 bytes, records each materialized lookup's
256 begins and 257 offsets as four-byte entries, and stores each live parent
column for 256 members using its target carrier width (four-byte certified
narrow codes, otherwise eight bytes). A fold reserves 256 eight-byte values.
Every allocation retains its alignment and every choice arm is represented;
the final size is aligned to sixteen bytes. The same layout implementation
supplies BE-Resource and emitted offsets, so resource failure cannot select
an alternative algorithm inside the interpreter.

For the GPU instance of E-Neg (and RA-Anti), the checked Physical provenance
of \code{compact(lookup)} records the negative polarity. Let
$m(\rho)$ be the provider's membership result on the recorded key columns.
The lane keep bit is $\mathsf{live}(\rho)\land\neg m(\rho)$ for anti,
and $\mathsf{live}(\rho)\land m(\rho)$ for semi. Both polarities use the
same membership probe; neither expands witnesses. Empty provider ranges,
absent directory keys, and existential wildcard columns follow the same
equation. The translator reads this polarity, rather than choosing it.


\subsection{Grouped folds}
\label{sec:grouped-fold}
A rule head may contain \code{count()}, \code{sum(e)}, \code{min(e)}, and
\code{max(e)}. Its remaining variables form the ordered key $K$. Let $V$
contain every named body variable, excluding anonymous wildcard witnesses,
and let $D=\delta(\pi_V\llbracket B\rrbracket)$ be the set of body valuations.
All aggregates consume this same domain. For $k\in\pi_K D$, write
$D_k=\{\rho\in D\mid\rho|_K=k\}$ and let
$[e(\rho)\mid\rho\in D_k]$ be a \emph{bag}: distinct valuations with equal
expression values contribute separately. This is SQL grouping over
\code{SELECT DISTINCT} of all named body columns, not an aggregate with
\code{DISTINCT} applied to its argument.
\begin{mathpar}
\Rule{RA-Group}{D=\delta(\pi_V\llbracket B\rrbracket)
 \qquad G=\pi_KD\text{ if }K\ne\varnothing,\quad G=\{()\}\text{ otherwise}}
 {\mathsf{group}_{K;(e_i,M_i)_i}(D)
  =\{(k,(\bigoplus_{M_i,\rho\in D_k}e_i(\rho))_i)\mid k\in G\}}
\end{mathpar}
Count uses $(\mathbb N,+,0)$ and $e(\rho)=1$; sum uses the declared additive
commutative monoid. Min and max use the option lifting of the declared
total order, with \code{None} as identity and \code{Some} as injection.
Thus empty keyed input has no answer, while empty global input has one
answer containing zero counts/sums and absent extrema. These laws assume
the declared operations satisfy their monoid premises; an expression
failure propagates the single $\bot$ before any result is published.

Let $S$ be a store of distinct valuations, partitioned by key, and let
$o_k,o_{k+1}$ be the owner offsets of key $k$ in the grouped store.
\begin{mathpar}
\Rule{BE-Group}{\alpha(S)=D\qquad
 S[o_k:o_{k+1}]\text{ enumerates }D_k\text{ exactly once}}
 {\mathsf{segfold}_{K;(e_i,M_i)_i}(S)
  =[(k,(\mathsf{fold}_{M_i}(\mathsf{map}_{e_i}
       S[o_k:o_{k+1}]))_i)\mid k\in G]}
\end{mathpar}
Existing whole-sequence fold cannot introduce a data-dependent partition.
A segmented-fold term therefore records the keyed store and its per-owner
fold; its input canonicalization is over $V$, never over aggregate values.
The host hash-grouped implementation fuses store construction and segment
fold without changing this equation. The Tasks interpretation performs this
operation at the host join, not as a collective at the separated pool.

\paragraph{GPU machine instance of BE-Group.}
The recorded canonical provider publishes the distinct complete valuations
before the grouped boundary. Stable radix ordering of their key codes gives
a permutation $\pi$; adjacent unequal keys mark owner offsets. Thus each
half-open segment of $\pi$ enumerates exactly $D_k$, and the same BE-Group
equation applies, without a new rewrite or a translator-selected plan.
Each owner is reduced collaboratively using the declared integer monoid:
count and sum have zero identity; extrema carry a separate validity bit
and retain the full-width value, including both signed endpoints.
Codec widths constrain the result (in particular unsigned 32-bit sums
cannot silently become signed 64-bit sums). Arithmetic failure is published
as bottom through the output status, together with ancestor failures.
Empty keyed input publishes zero owners; an empty global key publishes one
owner with count/sum zero and invalid extrema. Values, validity, and logical
output count remain resident until the explicit typed host decode.

\subsection{The H05 reference as a term}
The hand-written kernels (\code{experiments/gpu/h05-reference}) are
\[
 \mathsf{canon}\big(\mathsf{flatten}(\mathsf{map}\,g\,(\mathsf{tile}_{256}\,C))\big),\quad
 C=\mathsf{store}\big(\mathsf{flatten}(\mathsf{lookup}_{\rm Customer}[\mathit{nation}]\,
 \mathsf{flatten}(\mathsf{lookup}_{\rm Nation}[\mathit{region}]\,(\mathsf{rows}\ \mathrm{Region}_{\rm ASIA})))\big)\text{ at the separated level}
\]
with $C$ the Customer positions of ASIA nations, kept as offsets (the
reference's \code{segments}), and $g$, per customer position, two further
flattens (Orders by customer, Lineitem by order) tiled at 1024 at the collaborative level with 4 items
per lane, a membership test (Supplier), and the output flatten interpreted
by a collaborative scan plus one reservation per tile. $C$ is stored as
offsets, not rows (BE-Offsets). Every provider is read as a range cursor;
every column is a dense code of one join domain; \code{canon} is a fold on
a packed code. Compiled plan R records the same Physical program; what it
lacks is \code{store} of $C$ and the tiles, which the current printer
decides for itself. Those are the terms a rewrite must record.

\subsection{Related work}
NESL and flattening~\cite{paper-nesl,paper-ndp-gpu} give the objects and
BE-Offsets. Lift/RISE~\cite{paper-lift} give views, lengths in types and
derived barriers, but encode the OpenCL hierarchy in the terms; here the
hierarchy is the machine parameter. DPIA~\cite{paper-dpia} gives the
emitter as a proved translation. Descend~\cite{paper-descend} gives
execution resources as terms and collectives only on whole resources; here
that is the GPU instance of the grading. Futhark~\cite{paper-futhark,paper-futhark-flatten}
gives size types and BE-Choose. Halide and Exo~\cite{paper-exo} give the
schedule-as-rewrites discipline the pipeline already follows.
Disentanglement~\cite{paper-disentangle} names the memory property behind
the output protocols. What none of them covers: relations under a set
denotation with a canonical boundary (BE-Alpha, BE-Canon), joins as
flattens of lookups into indexes built in a prior phase (BE-Bind), and a
partial host fragment with written-order meaning above a total device
fragment.

\paragraph{Invocation-local proof reuse.}
Planner enumeration may share a checked Structures prefix, its support graph,
and immutable structural analysis between candidates. Cache hits require
complete syntax equality; interned proof identities are introduced only after
that comparison. Evidence changes revalidate evidence obligations, and grading
is always checked against the requested machine. Preparing common placement
once and batching nonsemantic grades therefore preserves PL-Closure and PL-Det;
the replay trace still contains the individual checked decisions.

Catalog read-level premises apply to the consuming row layout as well as the
indexed payload. A host-only row cannot acquire a descendant-only read token
merely because its lookup key is numeric. A checked publication of numeric
rows before a host consumer is an alternative under BE-Scope and PL-Precedence,
not an exception to the catalog premise. Resource-rejected dispatches may
instead publish named inner flatten levels using EXT-SeqStore; every resulting
tile/item candidate still satisfies BE-Resource before PL-Cost selection.
