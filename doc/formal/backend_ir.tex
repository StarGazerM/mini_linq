\section{Sequence: the back-end level (design)}
\label{sec:backend-ir}\label{sec:sequence}
The structural contracts and machine grading of this section are implemented
by \code{cq-lang-sequence}; their rules are linked in the inventory. Runtime
trait premises and emitter correctness remain obligations. Sequence adds
one level below Structures, shared by every back end,
and states what below it is not a level: placement is a grading on Sequence
terms, the machine is a parameter of that grading, and each emitter is a
translation. The level names no data structure, no algorithm and no machine.

\subsection{Why one level, and why this one}
A level is justified when its denotation changes: it adds or forgets an
observable, so that a different class of programs becomes equal. Below
Structures exactly one such change happens. Every level through Structures
denotes a function into $T X=\bot+\mathrm{Set}_{\rm fin}(X)$ composed in
written order (Section~\ref{sec:denotation}); the sequential pull runtime
makes nothing else observable, so order, multiplicity before \code{canon},
evaluation counts, sizes and placement are all the emitter's to choose. A
parallel runtime makes positions and sizes decisions that change the
program (which positions form the parallel domain; what must be allocated
before it runs), and constrains placement by value visibility and recorded
representation capabilities. Positions and sizes change the objects: that is
the Sequence level. Representation and scope constrain terms without changing
their values: that is a type-and-effect grading, not a level.
Kernels, barriers and launch shapes are derived from the grading: not a level, not syntax.

This is deliberately not progressive lowering in the MLIR sense. A pass
takes a whole program at one level to a whole program at the next; no
program mixes levels; the composition theorem of
Section~\ref{sec:composition} depends on that. A back end that needs a
construct the shared level lacks defines a complete diverged variant with
its own check, as \code{diverged-ra} does; nothing is mixed into the shared
level.

\subsection{Objects: the sequence monad and its morphisms}
Let $\mathrm{Seq}$ be the finite-sequence monad: $\eta(x)=\langle x\rangle$,
$\mathsf{map}$ its functor action, $\mathsf{flatten}:\mathrm{Seq}(\mathrm{Seq}\,X)\to\mathrm{Seq}\,X$
its join. $\mathrm{Bag}$ and $\mathrm{Set}$ are monads likewise, and the
forgetful maps are monad morphisms:
\[
 \mathrm{Seq}\xrightarrow{\ \alpha\ }\mathrm{Bag}\xrightarrow{\ \mathrm{supp}\ }\mathrm{Set},
 \qquad \alpha\circ\mathsf{flatten}=\mathsf{join}_{\rm Bag}\circ\alpha\circ\mathrm{Seq}(\alpha),
 \quad \alpha\circ\mathsf{map}\,f=\mathrm{Bag}(f)\circ\alpha .
\]
The front end computes in $\mathrm{Set}$; Sequence computes in
$\mathrm{Seq}$ under the same pure-total Rust premises; the morphism of the
result must equal the front-end value. Parallel admissibility is exactly the
structure $\mathrm{Bag}$ has and $\mathrm{Seq}$ lacks: its monoid is
commutative, so a fold over it is schedule-independent, and $\alpha$
forgets the order a schedule imposes.

A Sequence object is a nested sequence of \emph{coded} rows together with
its shape. Its type carries its lengths as symbolic expressions over input
lengths and earlier scans (size-dependent types in the sense of
Lift and Futhark~\cite{paper-lift,paper-futhark}); a term whose length is
not expressible is given a declared capacity. A codec
$\kappa=(\mathsf{enc},\mathsf{dec})$ with $\mathsf{dec}\circ\mathsf{enc}=\mathrm{id}$
on its domain refines row values; $\alpha$ applies $\mathsf{dec}$ per
column. A \emph{space} is a shape considered on its own: a finite index set
with lexicographic order and nesting.

\subsection{Terms}
$f$ ranges over per-position Physical maps, including unchanged Rust
expressions under the totality premise; device execution additionally requires
BE-RustRepresentation. $b$ ranges over providers.
\begin{lstlisting}
t ::= rows r                     // the positions of a retained result or host
    | map f t                    // per-position total map
    | flatten t                  // join; offsets are the scan of lengths
    | compact p t                // total filter, order-preserving
    | tile n t                   // view: regroup into runs of n
    | partition_k[K](P) t        // key-disjoint redistribution into P parts
    | lookup b [K] t             // per-position bucket of provider b
    | fold (o,e) t               // monoid fold
    | canon t                    // support
    | store t                    // materialize
    | choose [ g => t ]*         // size-guarded equal alternatives
\end{lstlisting}
An optional trailing packet, after evidence, records column representations:
\begin{lstlisting}
representation { identity [x, ...]; encoded [y, ...]; }
\end{lstlisting}
\code{Program.representation} and \code{Analysis.representation} contain
\code{Representation \{ identity, encoded: BTreeSet<String> \}}. The sets
record facts supplied by binding/codecs, not facts inferred from host types.
Unlisted columns have unknown device representation and cannot justify
device Rust evaluation. Rewrites may monotonically refine this packet:
each source identity fact remains identity and each source encoded fact
remains encoded, while an unlisted column may acquire either fact.
The two sets remain disjoint and every listed column must exist.
\code{tile}, \code{flatten} over known offsets, \code{lookup} over a range
cursor and the gathers inside $f$ are \emph{views}: bijections on positions
that change addressing and materialize nothing (Lift's layout patterns,
Descend's views~\cite{paper-lift,paper-descend}). \code{store} materializes,
and \code{partition\_k} redistributes an ancestor store into owned parts;
a segmented stored \code{flatten} retains offsets (BE-Offsets).
Nested shape alone does not demand a Range provider: a sequential leaf
task can enumerate each exact bucket within its owned input tile.
Machine grading adds Range obligations when a non-leaf collective needs
indexed bucket offsets, or a distributing tile cuts the flattened bucket
stream across executors. This distinction preserves exact routed-provider
reads inside a whole task-local segment without weakening collective scans.
Under BE-Alpha, constructors are lifted through outer tile levels:
\code{map}, \code{compact}, \code{lookup}, \code{fold}, \code{canon} and
\code{store} operate on innermost rows and preserve those outer partitions;
\code{flatten} joins the two innermost levels. Thus a lookup followed by
flatten under a tile preserves that tile. Analysis records lengths at every
level (a tile has $\lceil L/n\rceil$ parts and at most $n$ rows per part),
while $\alpha$ forgets all partition levels. A collaborative store can hold
one part; a separated store publishes the concatenation of its outer parts.
\begin{mathpar}
\Rule{BE-Alpha}{}
 {\alpha(\mathsf{map}\,f\,t)=\mathrm{Bag}(f)(\alpha t)\quad
  \alpha(\mathsf{flatten}\,t)=\alpha t\quad\alpha(\mathsf{tile}_n t)=\alpha t\quad
  \alpha(\mathsf{compact}\,p\,t)=\alpha t|_p\quad\alpha(\mathsf{store}\,t)=\alpha t}

\Rule{BE-Bind}{}
 {\sem{\mathsf{probe}[K](l,b)}=\mathrm{supp}\,\alpha\big(\mathsf{flatten}(\mathsf{map}\,(x\mapsto x\bowtie\mathsf{lookup}_b[K]\,x)\,l)\big)}

\Rule{BE-Partition}{\{P_k\}\text{ disjoint}\quad\textstyle\bigcup_kP_k=[0,|t|)\quad
 (\oplus,e)\text{ commutative}}
 {\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t)=\textstyle\bigoplus_k\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t|_{P_k})}

\Rule{BE-Offsets}{o=\mathsf{scan}_{(+,0)}(|t_0|,\ldots,|t_{|t|-1}|)}
 {(\mathsf{flatten}\,t)_j=(t_i)_{j-o_i}\text{ for the unique }i\text{ with }o_i\le j<o_{i+1}}

\Rule{BE-Canon}{\alpha t=B}
 {\alpha(\mathsf{canon}\,t)=\iota(\mathrm{supp}\,B)\quad
  \mathsf{canon}(\textstyle\biguplus_kB_k)=\mathsf{canon}(\textstyle\biguplus_k\mathsf{canon}\,B_k)}

\Rule{BE-CanonSort}{\alpha t=B\quad
 \preceq\text{ is Rust Ord on the complete valuation, consistent with identity}}
 {\alpha(\mathsf{unique}_{=}
   (\mathsf{sortUnstable}_{\preceq}(\mathsf{collect}(t))))
   =\iota(\mathrm{supp}\,B)}

\Rule{BE-CanonOrdered}{t=\mathsf{directHostScan}(W)\quad
 W\text{ is immutable and load-verified nondecreasing under prefix }p\\
 x=y\Longrightarrow p(x)=p(y)\quad
 \preceq\text{ is a total complete-row order consistent with identity}\\
 [R_i]_i\text{ are the maximal equal-prefix runs of }W}
 {\alpha\big(\textstyle\mathsf{concat}_i
   \mathsf{unique}_{=}(\mathsf{sortUnstable}_{\preceq}(R_i))\big)
   =\iota(\mathrm{supp}\,\alpha t)}

\Rule{BE-Code}{\mathsf{dec}\text{ injective on }K\text{ (both sides)}\quad
 \mathsf{enc}\text{ monotone on }c}
 {\text{equality, hashing and canon on }K\text{, and order reads on }c\text{, act on codes}}

\Rule{BE-Choose}{t_1,\ldots,t_n\text{ have checked equal support}\quad
 \text{guards }g_i\text{ over lengths or target-wide workers, exhaustive}}
 {\mathsf{choose}\,[g_i\Rightarrow t_i]\text{ denotes any }t_i\text{; which runs is free}}
\end{mathpar}
BE-Bind is the Kleisli bind of Section~\ref{sec:denotation} restated: a
probe is a flatten of per-row lookups, so a join nest is a nested flatten
and flattening it (NESL~\cite{paper-nesl,paper-ndp-gpu}) is what removes
irregular nesting. A sequentially evaluated flatten of lookups needs only
exact buckets, including when its rows are stored. The contiguous-range
capability (rangeCursor) is required for a segmented flatten, a domain
consumed by a \code{Distribute} tile, or lengths folded collectively below
host. A \code{Strip} tile and an ordinary row store do not introduce this
requirement. Structural inference is shared by every machine; grading adds
only the range obligations of the actual distributed execution context,
not of unused child levels in the machine.
A \code{flatten} or \code{fold} graded at a
leaf level (one sequential executor) is a loop, not a collective; BE-Collective
constrains only terms graded at a level whose members jointly evaluate them.
BE-Partition is the law every schedule relies on; it licenses no arbitrary
early stop and is stated on bags: a lost or duplicated position changes
$\alpha$. BE-Canon makes per-part canon a sound prefilter that replaces
the global boundary only when equal rows meet in one part. BE-Choose is
incremental flattening~\cite{paper-futhark-flatten}: the right
decomposition depends on lengths and available workers known at run time,
so several equal decompositions may be recorded under thresholds that are
tuning parameters, not meaning. The guard \code{workers < N} has a positive
bound and reads one target-wide available-worker count. It is uniform for
collective participation, supplies no size evidence, and does not change
support; a final \code{else} covers the remaining worker counts. Pull supplies
one worker; target-hook translations receive an explicit worker expression,
with Tasks supplying \code{rayon::current\_num\_threads()}.

Canonicalization strategy belongs to Structures/Sequence, not to a provider
name or a per-element hash-insert law. Sort is the default, including
computed heads; it collects the whole stream at that boundary before
sorting and adjacent unique. Tasks realizes the sort with parallel comparison
sorting and then an in-place adjacent-unique pass. Comparisons use Rust
\code{Ord} on borrowed fields, including opaque user types and wide rows.
Ordered consumes only a direct proof-carrying host scan: the load check
retains the exact prefix comparison with immutable rows. No downstream
projection, predicate, join or computed head propagates that witness.
It proves order, never uniqueness; every equal-prefix run still requires
complete-row sort and unique. A borrowed realization may collect row
references without copying owned rows. Consumer membership indexes remain
separate, and CPU Datalog's \textsc{DL-InsertNew} hash-seen admission is
outside this cutover.
Push consumers obey the same recorded whole-stream Sort barrier: publication
callbacks begin only after its input is collected and canonicalized. A push
printer may not substitute per-element hash insertion to preserve earlier
callback timing; that would ignore the recorded execution strategy.

\paragraph{Key-disjoint partitions.}
Let $B=\alpha t$ be a bag of complete valuations $V$, $K$ a tuple of
available columns, and $r_P$ a fixed total routing function on key tuples
with range $[0,P)$. Write $B_p=B|_{r_P(K(x))=p}$, retaining every input
occurrence exactly once. Collisions between unequal keys are permitted;
equal keys must always route together. Empty parts are retained.
\begin{mathpar}
\Rule{BE-KeyPart}{P>0\quad K\subseteq V\quad
 t\text{ reads a store at a strict ancestor of the separated pool}\quad
 P\in\{1,\mathsf{width}(\mathsf{pool})\}}
 {\mathsf{partition}_{K,P}(t)=[B_0,\ldots,B_{P-1}]
 \quad\biguplus_{p<P}B_p=B
 \quad K(\mathrm{supp}\,B_p)\cap K(\mathrm{supp}\,B_q)=\varnothing\ (p\ne q)}

\Rule{BE-KeyPartCanon}{[B_p]_{p<P}=\mathsf{partition}_{K,P}(t)
 \quad V\to K}
 {\alpha(\mathsf{canon}\,t)
 =\textstyle\biguplus_{p<P}\alpha(\mathsf{canon}\,B_p)}

\Rule{BE-KeyPartGroup}{[B_p]_{p<P}=\mathsf{partition}_{K,P}(t)
 \quad G\ne\varnothing\quad G\to K}
 {\mathsf{group}_{G;(e_i,M_i)_i}(\mathsf{canon}\,B)
 =\textstyle\biguplus_{p<P}
 \mathsf{group}_{G;(e_i,M_i)_i}(\mathsf{canon}\,B_p)}

\Rule{BE-GroupPartial}{D=\iota(\mathrm{supp}\,\alpha t)
 \quad\biguplus_{p<P}D_p=D
 \quad(M_i,\oplus_i,e_i^0)_i\text{ commutative monoids}}
 {\mathsf{group}_{G;(e_i,M_i)_i}(D)
 =\mathsf{merge}_G\bigl([\mathsf{group}_{G;(e_i,M_i)_i}(D_p)]_{p<P}\bigr)}

\Rule{BE-KeyPartProvider}{[B_p]_{p<P}=\mathsf{partition}_{K,P}(t)
 \quad L\to K\quad K=h\circ L\quad I_p=\mathsf{build}_L(B_p)}
 {\mathsf{lookup}_{\mathsf{build}_L(B)}(l)
 =\mathsf{lookup}_{I_{r_P(h(l))}}(l)}
\end{mathpar}
The case $P=1$ is the identity cover $B_0=B$, with no hash routing.
Here equalities forget enumeration order but preserve bag multiplicities;
canon compares complete valuations, never just routing or aggregate columns.
Provider routing projects the physically stored lookup tuple: constant-bound
columns omitted by filtered layouts are not routing coordinates. Covering join
filters require exact distinct-key enumeration through \code{Keys}; rustc checks
this provider obligation, without a shared-compiler type-name whitelist.
A routed provider type is installed only when its actual constructor consumes
the recorded cover. Fused-arm providers are constructed inside each prefix-row
invocation; their flat Sequence stores are deferred, not independent builds.
The top-level provider rewrite therefore cannot retype these local providers:
rewriting a deferred store would leave the real constructor unrouted.
The group law uses the same complete-valuation canonicalization and declared
monoids as BE-Group. Since $G\to K$, no group crosses a part boundary.
An unkeyed aggregate uses BE-GroupPartial rather than BE-KeyPartGroup.
A keyed aggregate over globally unique contiguous parts also uses
BE-GroupPartial: the product aggregate monoid is lifted to finite maps from
group keys, with pointwise combination and the empty map as identity.
The host merges these maps and emits one flat row per present key. Absent
keys emit no rows, including on empty keyed input. The unkeyed case instead
combines scalar partial states and always emits its single identity row.
The checked premise is global uniqueness of complete valuations across
all parts, not merely uniqueness within each part. It is established either
by BE-KeyPartCanon (routing determined by the complete valuation followed
by per-part canon), or by BE-GroupKey's proof that the original valuations
are globally distinct. The latter permits ordinary contiguous tiles without
canon. Raw tiles without such a uniqueness proof are rejected: per-tile
canon alone cannot eliminate duplicates crossing tile boundaries.
Both \code{Tile} and \code{PartitionK} may feed an unkeyed partial fold.
A keyed \code{Tile} partial fold merges finite maps; a keyed
\code{PartitionK} retains BE-KeyPartGroup's independent-group cover.
The host merge combines aggregate states with the same monoid operations,
not by evaluating original row expressions again or counting partial rows.
The checker records each Group's proven partial mode in
\code{Analysis.partial\_groups}, by owning Sequence definition and constructor
preorder (reserving the slot before checking the Group input).
Grading and target interpretations consume these checked modes, rather than
rediscovering routing provenance through nested Lookup, Flatten or Choose terms.
For globally unique inputs with total pipelines, checked empty-key partition advice lifts
\code{Tile} through a single-use map/compact/lookup pipe spine to its raw
driver or existing named Store boundary. It introduces no new full-valuation
publication, changes no shared pipe, and retains the ordinary totality and
grade checks on every streamed operation.
Unauthored single-use views on that spine are graded at the pool's producer
along with the streamed work; moving only the Group would leave illegal
unstored host references. Authored grades and stored boundaries are preserved.
A pipeline lacking a descendant representation instead publishes
\code{parts = store tile N t} at host, then a pool-graded partial Group
consumes that ancestor-stored nested cover. Rust payloads remain unchanged;
host ownership follows representation facts, never a partiality distinction.
This is an explicit parts publication, not bounded-memory execution.
The provider law concerns exact point buckets (and hence membership), with
the same routing function and partition count at build and lookup. It does
not license a range lookup spanning several routing keys to read one part,
nor remove provider capability or codec obligations.
The routed provider retains the routing projection $h$ and applies it in
the written routing-column order to every lookup key. This includes
proper subsets and reordered routing tuples; the planner's default
candidate uses the whole canonical lookup key.
The surface constructor is \code{partition\_k[K](P) t}; it adds one nested
level of exactly $P$ parts graded at the pool. Canon and keyed group operate
inside each part, and an explicit flatten joins them. Redistribution obeys
BE-Separate through its ancestor store; it is not a pool collective.
The machine fixes $P$ at plan time. Runtime worker count only schedules
these parts and never changes routing or the equations above.

\paragraph{Providers and codecs are capabilities.} A provider is read
through \code{lookup} and the term records only what the read requires:
exact bucket, contiguous range (rangeCursor), membership, order. Its type
is an opaque token discharged by runtime traits, as Structures does today
(STR-Key, STR-SortedRun); the same holds for codecs (BE-Code's premises
are trait obligations, like Leibniz admissibility). Canonicalization instead
records the checked Sort or Ordered strategy; runtime order laws remain premises.

\subsection{Placement: a grading over a machine parameter}
\begin{definition}[Machine model]
A finite tree of \emph{levels} $\ell$, each labelled: \emph{collaborative}
(members share storage and may synchronize; collectives are available) or
\emph{separated} (members share nothing and exchange only through a store
at a common ancestor, at a boundary); scheduling static or dynamic; and a
failure channel to the root. The root is $\mathsf{host}$.
\end{definition}
Each \code{LevelNode} also records \code{host\_rust: bool}: true for host and
CPU task execution, false for GPU device/block/lane execution. At a level
without host Rust support, a Rust expression requires the recorded identity
representation of every read column; unknown or encoded reads stay at host.
This machine capability is separate from separation or collaboration.
\begin{center}
\begin{tabular}{@{}p{0.16\linewidth}p{0.4\linewidth}p{0.2\linewidth}p{0.16\linewidth}@{}}
\toprule
 & GPU (SIMT, cooperative groups) & tasks (Rayon) & sequential\\
\midrule
levels & host $>$ device $>$ block $>$ warp $>$ lane & host $>$ pool $>$ task & host\\
collaborative & block (shared memory, barrier), warp (lockstep) & none & —\\
separated & device/host; block/block (no forward progress) & task/task (join) & —\\
scheduling & blocks dynamic, order undefined & work stealing & fixed\\
failure & flag read by host & panic at join & unwind\\
\bottomrule
\end{tabular}
\end{center}
A Sequence term is \emph{graded}: each subterm carries the level that
evaluates it, each \code{store} the level that holds it, and \code{tile}
descends one level. The grading is a type-and-effect discipline, not a
language: it is checked against the machine parameter and changes no value.
Execution resources in the sense of Descend~\cite{paper-descend} are the
GPU instance of the grade.
\begin{mathpar}
\Rule{BE-Scope}{\mathsf{store}\,t\text{ at }\ell\quad\text{a read at }\ell'\le\ell\text{ lexically inside its extent}}
 {\text{the read is admissible}}

\Rule{BE-Collective}{\mathsf{fold}/\mathsf{scan}/\mathsf{flatten}\text{ at }\ell\quad\ell\text{ has members}\quad\ell\text{ collaborative}\quad
 \text{the whole of }\ell\text{ participates}\quad\oplus\text{ associative}}
 {\text{equals the sequential fold; commutative }\oplus\text{ makes it schedule-independent}}

\Rule{BE-Separate}{\ell_1,\ell_2\text{ separated siblings}}
 {\text{they exchange only through a store at a common ancestor; nothing else is observable across them}}

\Rule{BE-Length}{d=\mathsf{store}\,t\text{ at a separated level}\quad
 \mathsf{checkedLen}(d)\ne\mathsf{Unknown}(\varnothing)\ \lor\
 t\text{ names a completed host producer}}
 {|t|\text{ is available before the write, or bounded with an overflow flag}}

\Rule{BE-Publication}{d=\mathsf{store}\,t\quad t\text{ has checked provenance and consumers}}
 {\mathsf{publication}(d)\in\{\mathsf{BorrowHost},\mathsf{Alias},\mathsf{OwnRows},\mathsf{DeferredRows},\mathsf{Parts}\}}

\Rule{BE-TaskProducer}{t\text{ checked}\quad i=(\text{definition},\text{constructor preorder})}
 {\mathsf{producers}(t)=\text{distributing Tile identities reachable through row inputs and Ref}}

\Rule{BE-CarrierPublication}{t\text{ checked}\quad i=\mathsf{id}(t)}
 {\mathsf{carrier}(i)=\mathsf{TileInput}\text{ if no host borrow exists, or }\mathsf{Choice}\text{ for runtime choice}}

\Rule{BE-Boundary}{\text{a maximal segment of total terms between stores at a separated level}}
 {\text{is one unit of dispatch (a kernel, a task); its domain is the outer stored space; derived, not written}}

\Rule{BE-RustRepresentation}{\fv(e)\cap Q=C\quad
 \forall c\in C.\ \mathsf{deviceRepresentation}(c)=\mathsf{identity}\\
 \mathsf{otherInputs}(e)\text{ are closed captures}}
 {e\text{ may run on device, emitted verbatim and compiled by cuda-oxide}}
Representation facts enable placement; they do not themselves establish
codec correctness. Their correctness is the binder's GPU-Representation
obligation. BE-RustRepresentation admits monotone target refinements of
these facts, never removal or an identity/encoded flip.

\Rule{BE-Abort}{\bot\text{ raised below }\mathsf{host}}
 {\text{a once-set flag on the failure channel, mapped to }\bot\text{ at the next host boundary; no truncated success}}

\Rule{BE-Resource}{d\text{ a checked dispatch at }\ell\quad
 \mathsf{shape}(d)\text{ consumes recorded publication refinement}\quad
 \mathsf{layout}_M(\mathsf{shape}(d))\le\mathsf{capacity}_M(\ell)}
 {\text{the dispatch fits the bounded resource of its machine level}}
\end{mathpar}
The resource shape records every branch, payload lookup, live parent column
with its checked type and codec facts, fold, tile and item count. Byte layout
and alignment belong to the target-supplied machine, not to the language.
BE-Publication's ordinary owned-row publication stores expanded rows.
A terminal lookup does not by itself denote a deferred range: that
representation requires the explicit GPU-Launch refinement and a supported
contiguous-range provider. Without that record (including machines with no
GPU refinement), BE-Resource charges the lookup's live-parent payload scratch.
A later read of any completed publication does not charge its producer's
scratch again. This keeps the generic machine's expansion costs distinct
from the GPU's recorded deferred-range execution.
An unbounded level imposes no capacity premise. A bounded level without a
layout model, arithmetic overflow, or an oversized layout is rejected before
translation, including for explicitly advised programs. Resource recovery
enumerates checked alternatives in fixed order: nested inner-flatten
segmentation at preferred geometry, smaller item counts, then smaller strips
derived by halving the machine width. Only after these fail may it add
dispatch-splitting publications. Every candidate satisfies all grading and
catalog premises, including BE-Resource; PL-Cost compares the legal segmented
and plain schedules at the first feasible geometry. If none fits, rejection
retains all diagnostics from every attempted candidate.

The laws mention only labels of the machine parameter. A term that uses a
collective at a level the target marks separated is rejected for that
target, not reinterpreted. BE-Boundary derives kernels (GPU) and tasks
(Rayon) from the grading: the domain of a dispatch is the type of its outer
stored space, which replaces the current printer's
\code{driver.len.div\_ceil(1024)}; storing the H05 Customer level as
offsets makes the next dispatch span every customer. All admitted Rust is
total by premise. Row-dependent Rust lacking BE-RustRepresentation runs at
host; closed operands evaluate once at host (IF-Parameter). Codec-encoded
comparisons use explicit relational predicates and host-encoded operands,
not a rewritten Rust expression. No type-name whitelist establishes device
eligibility; sizes and encodings come from recorded provider/codec facts.
A store at a separated level is publication: a depth-zero producer is one
part at its unique child. Its outermost tile in dataflow order distributes parts over that
child; further tiles in the same definition strip-mine jointly at the
current effective level, and \code{items} assigns positions per member
without adding a level. A tile in a non-separated definition also
strip-mines; distribution to a deeper level requires a separately graded
definition. Analysis records each tile's interpretation and the dispatch's
producer level, outer tile width and concatenation protocol (count/scan,
reserve or bounded); publication concatenates the parts in part order.
The same publication rule applies to non-final stores. In
\code{p = t} graded at an explicit descendant execution extent and
\code{s = store p} graded at host, the producer executes at its recorded
grade and the completed store is published at host. Only the store encloses
that execution; a plain host reference to a descendant value is still
ill-scoped. Factoring a producer into a fresh name changes neither rows nor
support (EXT-SeqStore). Independent arm stores can therefore be published
by separate dispatches and concatenated by a host \code{union}, without a
dispatch spanning two outer stored spaces.
Conversely, a separated descendant store may name a host-graded producer.
The host producer is evaluated first, its completed length is known before
the write, and the projected rows are transferred into the descendant store.
This downward publication is an upload, not a GPU query dispatch; subsequent
lookup execution uses the stored layout without re-evaluating its predicate.

\paragraph{Composition of complete programs.}
A materialized result may bind a relation of a subsequent complete program.
This is ordinary substitution of the published store's $\alpha$ into that
relation, not inlining of either program or a new query rewrite. Each stage
is checked and graded independently. A resident binding retains its complete
row schema, key codec bounds, logical count, stream ordering, and ancestor failure channels;
changing a row-major publication to column views preserves every row and
does not download the relation. Nullable publications require a representation
that retains validity, or explicit host publication. Host-only stages use the
host interpretation and publish their completed rows. Independent terminal
branches retain the author's union/composition rather than selecting only the
last compiled rule. Conformance substitutes independently selected Sequential
interpretations of the same Physical stages through the identical graph.

\paragraph{Output.} The final \code{flatten} into one stored sequence of
unknown length is one term with several interpretations, equal under
$\alpha$: lengths computed first by a count pass (purity, premise~3,
licenses running the map twice), reservation by a commutative concatenation
(schedule-dependent positions, same bag), or a bounded buffer with retry.
Which is recorded, because it changes the program. Parts write only
positions they own by a view, or buffers they allocated; nothing reads
another part's fresh allocation before a boundary. That is
disentanglement~\cite{paper-disentangle}, the memory property that makes
these protocols lock-free.

\paragraph{Cost.} The set model has no cost; Sequence has work and
span~\cite{paper-nesl}: work the number of positions evaluated, span the
longest dependency chain. Plan R's two schedules have equal work; a
one-part schedule has span proportional to work, a grid-wide one span
logarithmic. Cost is not meaning; it is what a decomposition pass argues
with, and lengths in types are what make it computable.
BE-Publication derives ownership once, before support-equal result reheading.
A resident host Rows/Ref/Store chain can publish a borrow; a flat routing
input can alias an already published flat buffer and its length. Otherwise
retained rows are owned, either flat or as checked key-disjoint parts. Aliases
may rehead logical columns without claiming the source's raw carrier is
unchanged. Real row copies, including raw key-input staging, contribute
retained-row traffic $B$, not another row-expression evaluation or a unit of
compute span. Provider insertions continue to contribute work and span.
Borrow and alias publication add no traffic. Thus being consumed by a key
partition is not a free-store rule.
The native routed-provider representation records the inner provider of the
canonical \code{cq\_storage::sharded::Sharded} ABI. Before emission, checking
validates its type arguments and proves every routing column belongs to the
stored outer key, after constant elision. An unrelated type with the same
last identifier has no routed interpretation.

The \(\mathsf{DeferredRows}(c)\) refinement is checked Store-consumer fusion,
not a global lazy interpretation of \code{store}. It applies only to a staged
owned input \(d=\mathsf{store}\,t\) whose row and written-length consumers are
confined to one \(\mathsf{Parts}\) publication \(c\). That publication starts
with the recorded uniform guard \code{workers < 2}, whose arm contains a
singleton leaf \(\mathsf{partition}_K(1)\,d\), directly or beneath checked
nested length choices. Every leaf covers the same named \(d\) with the same keys.
Exactly one native routed provider is built, with no retained rows, direct
part replay, consumer alias, or final-output use. The pre-reheading input and
consumer result carriers agree. Checking follows pure named producer views
and previously published resident-host borrows, but not prior owned or nested
Stores. It uses Physical opacity analysis over every dependency, excludes
shadowable join-filter source bindings, and excludes
intervening publications of source dependencies.

Under these premises a worker-singleton leaf reached without counting \(d\)
may consume \(t\) directly. A proven nonexpanding host-length guard can select
this leaf before demanding a filtered staged input. Any count of \(d\) or routed
demand instead forces one owned row vector and retention token, reused by all
subsequent demands, including a later singleton leaf.
Thus \(t\) is evaluated at most once on each selected branch. A skipped vector
incurs no row-build or retention activity; actual routed copies remain owned.
PL-Cost nevertheless retains the worst-case owned-input traffic \(B\), with
unchanged work and span. Failure of any premise preserves the original
publication record, and the interpreter may not infer a new scheduling guard.

\subsection{Decomposition}
A planner is an advice generator, not another interpretation of Sequence.
Its inputs are a Sequence program $t$, a machine $M$, and an ordered catalog
$K$ of target-supplied providers, codecs and canon-strategy support with capabilities
and admissible levels. The catalog is data: shared planning and checking
do not depend on a target implementation. A successful result is a graded
program together with a replayable trace of the existing Sequence rewrites.
Let $t_0=t$, $t_i=r_i(t_{i-1})$, and let $A(t)$ record authored choices.
\begin{mathpar}
\Rule{PL-Closure}{\mathsf{plan}(t,M,K)=(t', [r_1,\ldots,r_n])}
 {t'=t_n\quad
  \forall i.\ \mathsf{check\_rewrite}(t_{i-1},t_i)\quad
  \mathsf{check\_grading}(t',M)}

\Rule{PL-Precedence}{\mathsf{plan}(t,M,K)=(t',\rho)}
 {A(t')|_{\mathrm{dom}(A(t))}=A(t)}

\Rule{PL-Det}{(t,M,K)\text{ fixed}\quad
  \text{candidate and catalog order fixed}}
 {\mathsf{plan}(t,M,K)\text{ has one result (or one rejection)}}

\Rule{PL-Select}{s'=\mathsf{retainUnsupportedHostReads}(s,K)\quad
 e\in\mathsf{Structures}(s')\quad K_e=\mathsf{stablePartition}(K,\mathsf{matchesRecordedType}(e))\quad
 k=\mathsf{first}\{k\in K_e\mid \mathsf{needs}(e)\subseteq\mathsf{caps}(k),
 \ \mathsf{levels}(k)\ne\varnothing,\
 \mathsf{elements}(e)\subseteq\mathsf{acceptedElements}(k)\}}
 {\mathsf{select}(s,K):\
 e.\mathsf{type}\gets k.\mathsf{type}\quad\text{by checked retention, index construction and retype}}

\Rule{PL-Resident}{\mathsf{hostRead}(p)\quad \exists\ell\in\mathsf{reads}(p).\ |\ell|>1}
 {\mathsf{admit}(p,k)\Longrightarrow
  \mathsf{Resident}\in\mathsf{caps}(k)\ \land\
  \mathsf{matches}(p,k)\ \land\
  \mathsf{needs}(p)\subseteq\mathsf{caps}(k)\ \land\
  \mathsf{reads}(p)\subseteq\mathsf{levels}(k)}

\Rule{PL-Cost}{C=(c_1,\ldots,c_k)\text{ admissible, preserving }A(t)\quad
 \mathsf{groupMode}(c)=\mathsf{Analysis}(c).\mathsf{partialGroups}\quad
 \kappa(c)=(W(c),I(c),S(c),B(c),\#\mathsf{stores}(c),\#\mathsf{dispatches}(c))}
 {c^*=\mathsf{foldl}\bigl(
   (a,b)\mapsto\text{if }\kappa(b)\prec\kappa(a)\text{ then }b\text{ else }a,
   c_1,(c_2,\ldots,c_k)\bigr)}
\end{mathpar}
BE-Length consumes the structural checker's recorded store length, never a
second syntactic size analysis. A reference to a completed store with an
unknown construction length has the runtime length of that publication.
Maps preserve their input length; choices join the checked lengths of their
arms. Host stores may grow, and a completed host producer supplies its length
before downward publication.
Group work and host merge costs consume the constructor-preorder mode in
\code{Analysis.partial\_groups}; layer geometry does not choose execution mode.
Catalog levels describe where a provider may be read, not where its owner is
constructed. Building an index from host rows does not certify a host read.
Placement must select a supported read level; authored unsupported grades are
rejected rather than silently reinterpreted.
The explicit \(\mathsf{Resident}\) catalog capability certifies that a native
input handle already denotes immutable target-resident storage. It permits
that handle's recorded descendant reads without constructing a host fallback
index. It is not inferred from a Rust type name, a range capability, or the
presence of device levels. Ordinary pipe-host adapters still require retention;
resident tokens must also satisfy every type, element, read and level obligation.

PL-Closure inherits its value laws from BE-* and the Sequence extension
rewrites; it adds no new equality of values. PL-Precedence preserves
authored grades, tiles, stores, choices, output protocols, codecs and canon
strategies: planning fills missing decisions rather than optimizing them away.
PL-Det includes rejection when no catalog token satisfies a recorded
obligation. PL-Cost uses the work and span of the preceding Cost paragraph,
not a semantic preference. Here $\prec$ is provable strict lexicographic
symbolic cost dominance: work first, then Lookup/Expand inversions $I$,
span, retained-row traffic $B$, stores and dispatches. $B$ sums the checked
owned publication lengths. It is a bandwidth tie-breaker, not an assumption
that copying one carrier costs as much as a hash/group row evaluation.
An inversion is a Lookup evaluated after an upstream Expand in the same
pipeline; retained references begin new pipelines.
Bounds and coefficient dominance establish comparisons; unresolved
comparisons, like equal costs, retain the earlier candidate.
For a BE-GroupKey-proven keyed group, both contiguous partial-map folding
and group-key routing remain candidates. The former is enumerated first,
then the native schedule and routed alternatives; cardinality uncertainty
uses the same stable incomparability rule, not a query-specific estimate.
Partial folding owns one accumulator map per machine scheduler partition,
not per logical tile. Its fold span uses that scheduler width. Host merge
adds serial dependency span for up to $P\,|G|$ partial aggregate states,
capped by the input count when both estimates are available for keyed groups.
Authored group/output count evidence supplies $|G|$ when present; otherwise
the charge remains the symbolic $P\,\mathsf{scan}(\mathsf{group})$, never zero.
For an unkeyed scalar partial fold with unknown input size, the fixed host-merge
setup instead follows the existing amortized-routing convention: halving
effective fold throughput charges its bandwidth without making a false
all-cardinalities dominance claim about a constant setup term. Known input
counts retain the explicit scalar merge charge. Keyed groups reserve their
variable-length output, avoiding a second count-pass evaluation of the fold.
Like routing, merging states is organizational span rather than repeated
evaluation of original row expressions. Many-group estimates can therefore
select key routing over partial-map merging without changing either meaning.
For an eligible native exact-key provider Store, the automatic schedule retains
an explicit runtime BE-Choose before this cost comparison. For published
input length \(n\), workers \(w\), and positive machine row cutoffs
\(\theta=\code{key\_partition\_threshold}\) and
\(\kappa=\code{key\_partition\_cache\_threshold}\), the policy is
\[
  \mathsf{route}(n,w)\iff n\geq\theta\ \land\ (w>1\ \lor\ n\geq\kappa).
\]
Let \(c=\max(\theta,\kappa)\). The first root arm \(w<2\) is itself a choice:
an optional proved \(\mathsf{len}(H)<c\) selects
\(\mathsf{partition}_{K,1}(t)\), then \(n<c\) selects that same singleton,
otherwise use \(\mathsf{partition}_{K,P}(t)\). The remaining root arms
select singleton for \(n<\theta\), and \(P\) parts otherwise.
Nested choices of fixed key covers retain the published-input allocation
witness of every leaf (BE-Length); varying the selected part count does not
introduce an unbounded separated store.
The host-layout name \(H\) is accepted by \texttt{Len::Input} and supplies an
upper bound only through nonexpanding Physical Rename, Select, Point, Range,
Guard, Bind, Project, and Semi/Anti driver chains. Probe, Merge, Union and Group
stop this derivation. The actual Sequence occurrence count must also be bounded:
host Rows and pure Ref chains, Store, Tile/Flatten and Canon preserve the bound;
Map/Compact additionally require the nonexpanding Physical path from their
child's provenance. Membership Compact may consume a Lookup's existence,
but expanding Lookup, Union, Fold and Group do not qualify. Choices require
compatible host and result provenance in every arm. A Rows read following a
non-BorrowHost publication of that result is excluded: support equality alone
does not prevent duplicate occurrences. A Sequence definition (including the
new publication) that shadows \(H\) also prevents the shortcut. Thus host length
can establish singleton selection without demanding filtered staging; the
exact-input fallback retains the equation when host length does not decide it.
Tasks defaults \(\theta=65{,}536\) and \(\kappa=6{,}291{,}456\) rows are
measured target parameters, not universal optima or cache-byte guarantees.
The cache cutoff exceeds H04 SF1's \(6{,}001{,}215\) host rows but is below the
measured H04/H21 SF10 provider inputs. A positive \(\kappa<\theta\) is valid.
Replay records both \code{threshold N} and \code{cache N}; explicit
threshold-only advice retains its legacy worker/count policy. This is a Machine
and Tasks Config parameter, not a new macro option or interpreter branch.
Written exact count guards use the Sequence \texttt{Len::Input} name of the
prior publication, not a cardinality estimate. All arms retain the same routing
keys and provider token; BE-Choose joins unequal outer lengths. The one-part
identity cover builds the native provider without hashing; routed leaves build
\(P\) providers. Fixed-cover allocations are available in each branch, so
differing part counts alone do not require Store capacity.
The rewrite redirects every ordinary row reference and written length guard
on the original provider definition to the new raw publication, preserving
its flat carrier and ancestor extent. Lookup provider identities retain the
retyped token. Consequently a derived provider sharing the original rows
does not inherit a spurious extra cover level from an earlier provider build.
When the original Store executes below host, checked publication advice names
its raw producer at the original execution grade and publishes
\code{store producer} at host before the runtime choice. This preserves task-owned
pipe references instead of moving their evaluation into the ancestor Store;
the ordinary publication and scope rules establish the transfer.
Force advice selects the fixed $P$-part schedule without a guard; forbid and
authored grades retain the native schedule. PL-Cost compares the remaining
collective and decomposition choices, never discards the automatic provider
choice for lack of a provable cardinality, and never overrides these policies.
Provider selection is unique per physical provider, not per Sequence alias:
an explicitly forced eligible publication wins, otherwise the last eligible
publication preceding every keyed reader is selected without reordering definitions.
This dominance premise is checked from recorded provider reads; forced or replayed
advice that moves the sole provider build after a reader is rejected. A forbid on
any alias retains the common native type; conflicting forced aliases are rejected.
Checked replay rejects retyping an already routed provider, rather than
constructing a nested routed family.
Provider eligibility is evaluated after decomposition against the scheduled
grading obligations. If segmentation or distributed lookup requires a range
cursor, the exact-only routed family is ineligible and the native provider is
retained; no runtime choice weakens a range or ordered-access requirement.
The publication must carry a flat valuation containing every routing key;
native layouts that reconstruct an omitted constant key do not satisfy this
premise. The routed token must cover every scheduled read level, capability,
and carried element type, not only match the provider family's type name.
Resource recovery first preserves the machine's preferred item count and
distributing width, trying nested segmentation before reducing either.
Local offsets segmentation is considered only at collaborative grades:
its inline Store cannot satisfy BE-Boundary at a separated task or pool.
At each geometry PL-Cost compares admissible segmented and plain candidates;
strict improvement replaces the earlier candidate, preserving stable ties.
Dispatch splitting is a last resort, never a substitute for an admissible
single-dispatch segmentation. All tiers retain authored tiles, grades and stores.

A planning invocation may reuse a structural proof only for an equal complete
Structures prefix and equal Sequence and evidence syntax. Machine grading is
checked separately for every requested grade. The join-support certificate
interns relation and column names into invocation-local integer identities;
its cache keys retain the complete ordered graph, headings and query atoms.
Neither a hash collision nor an estimate establishes an equality. Syntax trees
remain the source of spans and opaque Rust equality; proof comparison does
not require rendering those trees to token strings.

PL-Select is an explicit Structures selection operation before decomposition,
not an implicit override by PL-Precedence. It visits built indexes, sets
and row buffers in recorded entry order. Provider catalog order is explicitly
stable-partitioned per entry: tokens matching its recorded representation
precede all other tokens, retaining catalog order within both classes.
The first eligible token wins. This preserves admitted native keyed ABIs
instead of replacing them with generic row providers. Sort may record an
explicit \code{using Type} device sort/unique implementation selected by the
catalog; this refinement preserves Sort and never replaces Ordered with Sort.
The old dedup-provider retype selector is removed. Host scan adapters are unchanged.
Unsupported integral keyed host stream reads first use the checked Physical
\code{build\_host\_reads} retention rewrite, then receive a built index
checked by Structures. Obsolete keyed host fallback entries are removed;
the original host scan adapters remain unchanged. A built index supplies
the keyed obligation rather than claiming that column encoding supplies
an unavailable provider capability.
Structures has no machine grading, so selection requires host publication.
Later Sequence planning validates every actual execution level.
Provider tokens may restrict scalar row element types; an omitted restriction
accepts any type. Both built-index selection and host-fallback retention
check the recorded stored-row layout (including checked filtered projection),
and final catalog discharge checks it again at the actual execution grade.
A numeric-only device provider cannot be selected
for a row carrying a \code{String}; a compatible host token or a rejection
is required.
Each substitution uses the existing source/target Structures retype checks;
an absent token or inadmissible retention rejects with the obligation.
Sequence rewrite equality also accepts checked catalog retention:
host renames alone may change from \code{pipe} to \code{let}, with
their keyed fallbacks replaced by built indexes. The dedicated
\code{check\_retention\_rewrite} checks both endpoints and the Physical
rewrite contract, requiring identical non-mode Physical syntax and order,
original host scans, existing key layouts and canonical boundaries.
Provider, retained-row and membership-state types may change, as may Sort's
explicit \code{using} implementation. The canonicalization strategy itself
is preserved, particularly Ordered's verified-carrier requirement.
Ordinary Structures rewrites still require exact Physical syntax; neither
boundary permits replacing an opaque reader or predicate.
When catalog selection follows Sequence lowering, each newly retained
rename also receives an explicit Sequence store, so its provider is built
before lookup emission. Native provider preservation matches result and
key layout, not entry position: retention removes fallback entries and
appends indexes, changing their positions.
The native Tasks target preserves retained row-buffer types separately:
replayable rows use the row collection ABI, not a keyed range-provider family.
Catalog retyping also composes with a subsequent checked join reexpression.
The endpoint proof compares surviving storage layouts modulo implementation
types, while separately proving relational support, unchanged Rust payloads
and exact host-reader syntax. It does not require the composite Physical
change to fit the narrower mode-only retention certificate.
Placement propagates unavailable device representations and their unstored
feeds to host. A Rust expression may read only identity-represented device
columns, with other inputs supplied by closed captures; encoded columns use
relational predicates. Independent named union arms with distinct stored
domains are published separately, then concatenated at host; neither rule
weakens BE-RustRepresentation or BE-Boundary.
An already-checked Sequence store cuts producer provenance, including for
lookup providers: descendant reads consume materialized rows rather than
re-evaluating the host expression.
Guard-result carriers project away columns absent from the checked downstream
required-column set. The guard still receives its complete required input;
this representation projection happens after evaluation and does not change
its written domain or assert totality.
Unknown lengths remain type-length expressions rather than measured input
data or invented cardinalities. Work counts evaluated constructor positions;
aliases, tiles and stores add no evaluation work, with stores a separate
cost tier. Span follows dependencies, taking the maximum over branches.
An actual graded distribution introduces a symbolic maximum-part length
constrained by its driver, rows and machine width, not by multiplying tile
width by items.

The decision procedure is bounded enumeration. Host rows remain at host;
publication and stores consumed by lookup or canon use the deepest
admissible level, while intervening terms inherit producer placement.
Below host, the first fanout in a flatten chain uses the distributing
machine level's static width, if available. It first tries nested stores and
inner tiles with preferred items, then plain tiling at the same geometry.
Only if neither fits does it halve items to one, then halve the machine-derived
strip width to one. If every geometry fails, named publication boundaries
split dispatches, with choice/union publications as the last tier. Where separate
rewrites cannot express this decomposition, the checked \code{segment}
rewrite pairs an inner-flatten store with an outer tile, justified by
BE-Offsets and BE-Partition and exposed through both the library and macro.
Recorded output protocols, including count inserted by lowering, are preserved. Only absent
protocols are filled: count when the final length depends only on input
lengths, otherwise reserve; a bounded protocol requires an authored
capacity. Reported provider, canon and codec obligations are validated
against catalog capabilities at their levels. Structures already records
provider types and canon strategies, including any explicit Sort implementation.
Catalog support may refine that implementation without changing the strategy.
Codec laws remain abstract runtime premises; planning validates
catalog support, not those laws. Every proposed rewrite and the resulting
grade are checked; no emitter decision is introduced.


\subsection{Refinement and the emitter}
\begin{definition}[Sequence refinement]
A graded Sequence program $t$ over Structures $s$ refines $s$ for machine
$M$ when, for every input and every schedule $M$ admits under
BE-Partition, BE-Scope, BE-Collective, BE-Separate and BE-Abort,
$\mathrm{supp}\,\alpha(\mathsf{run}_M(t))=\sem s$ whenever $\sem s\ne\bot$,
and $\mathsf{run}_M(t)$ aborts only if some sequential schedule of $s$ panics.
\end{definition}
The obligation splits per construct: BE-Alpha for the shape terms, storage
laws for provider and codec interpretations, BE-Partition and
BE-Collective for the schedule. An emitter is a translation from graded
terms to the target (loops, assignments, barriers, launches), in the sense
of DPIA's strategy-preserving compilation~\cite{paper-dpia}: correct per
construct, race-free by construction from the views, deciding nothing. A
construct without a translation is rejected. Lift derives allocation and
barriers from its types~\cite{paper-lift}; here they are derived from the
grading, lengths and views.

\paragraph{Sequential translation.}
\begin{mathpar}
\Rule{T-Pull}{t\text{ checked}\quad\text{every grade is }\mathsf{host}}
 {\mathsf{run}_{\rm seq}(t)=\text{the fold: }\mathsf{rows}\mapsto\text{host rows},\
  \mathsf{map}/\mathsf{compact}\mapsto\text{the Physical row function},\
  \mathsf{lookup}\mapsto\text{the recorded capability},\
  \mathsf{flatten}\mapsto\text{iterator concatenation},\
  \mathsf{tile}\mapsto\text{contiguous groups},\
  \mathsf{choose}\mapsto\text{else arm unless a worker guard requires first-match evaluation},\
  \mathsf{fold}\mapsto\oplus,\ \mathsf{canon}\mapsto\text{the recorded Sort/Ordered strategy},\
  \mathsf{store}\mapsto\text{intermediate }\code{Vec}\text{ or final count iterator}}
\end{mathpar}
BE-TaskProducer records stable producer identities; an active producer is
consumed exactly once by its join. Ref and lifted adapters preserve those
identities irrespective of generated Rust names. BE-CarrierPublication extends
BE-Publication to translation carrier storage: a non-borrowable task driver
retains its input once, and a runtime choice retains only its selected arm,
recursively preserving dimensions. These records are printable analysis.
Their row volumes are independent symbolic retained-traffic terms in the cost;
summing conditional publications gives a conservative bound, not a claim that
unselected arms execute. Ordinary pull erases choices without worker guards
to Else, permitted by BE-Choose's equal-support premise; worker-guarded pull
and target hooks evaluate first-match guards (pull has one worker).
The host-only translation leaves the final store with \code{output count}
as a lazy pull iterator (BK-Dual); it does not collect the output into a
\code{Vec}. Intermediate stores materialize, and rows escaping block-local
storage may be collected to preserve their lifetime. The target-hook
\code{translate_with} path remains materializing for task and GPU targets.
The sequential interpretation preserves support under the provider laws and
propagates Rust failure by unwinding.

\subsection{Passes}
\begin{mathpar}
\Rule{L-Sequence}{s\text{ checked Structures}}
 {\mathsf{lower}(s):\ \text{host rename}\mapsto\mathsf{rows};\
  \text{unary step}\mapsto\mathsf{map}/\mathsf{compact};\
  \text{probe, merge}\mapsto\mathsf{flatten}(\mathsf{lookup});\
  \text{semi, anti}\mapsto\mathsf{compact}(\mathsf{lookup}_{\rm membership});\
  \text{union}\mapsto\mathsf{union};\
  \text{let}\mapsto\mathsf{store};\ \text{canon}\mapsto\mathsf{canon};\
  \text{return}\mapsto\mathsf{store}\text{ with }\mathsf{output}\ \mathsf{count};\ \text{no tile, no grade}}
\end{mathpar}
The checker re-derives this construction and compares it structurally.
\begin{itemize}
\item Structures $\to$ Sequence: the default lowering records ``one part,
nothing stored'': every result is a view or a device/host store as its
Physical mode says, no tiles. The shipped CPU target checks sequential grading
and translates this Sequence program to a pull iterator, with an optional
profile-counter variant.
\item Sequence $\to$ Sequence rewrites, advice-driven as the existing
rewrites are (Section~\ref{sec:structures}), each with a law: store a
flatten level (BE-Offsets), tile a space (BE-Partition), record a
size-guarded alternative (BE-Choose), choose the output interpretation,
record codecs and canon.
\item Grading: assign levels against a named machine model; checked by
BE-Scope through BE-Abort.
\item Translation per machine.
\end{itemize}
This mirrors the algorithm/schedule separation of Halide and
Exo~\cite{paper-exo}: the pipeline's advice is the schedule, each primitive
is an equivalence-preserving rewrite with a stated law.

The external \code{cq-sequence-rewrites} passes check both programs and
construction-based support equality:

\Rule{EXT-SeqTile}{n>0\quad d\text{ not an unbounded unknown-length store}}{d:=\mathsf{tile}_n\,d\quad\text{(BE-Partition)}}

\Rule{EXT-SeqChoose}{a,b\text{ have checked equal support}\quad\text{guards exhaustive}}{d:=\mathsf{choose}[g\Rightarrow a,\ \mathsf{else}\Rightarrow b]\quad\text{(BE-Choose)}}

\end{mathpar}
\code{grade} records advice only: the facade's grading phase checks the
machine and BE-Scope through BE-Abort.

\subsection{Lookup and Expand}
\label{sec:lookup-expand}
Lookup and Expand separate the shrinking and growing parts of a join
\cite[Sections~3.2--3.4 and~4]{paper-diamond}.
Sequence already supplies both: a \code{lookup} names matching positions,
\code{compact(lookup)} tests their existence, and \code{flatten} expands
them. A stored filtered relation with an indexed provider carries the
forward phase across a publication boundary. No additional Sequence
constructor is introduced.

Join order, Lookup/Expand order and relational filtering are recorded by
upstream planning, not rediscovered from Physical dependencies by Sequence.
Decomposition preserves that construction and chooses checked execution shape.
Author-supplied \code{choose} advice and key-partition alternatives remain
governed by \textsc{BE-Choose}; they do not authorize automatic relational
replanning or optional-filter discovery.

\begin{mathpar}
\Rule{PL-Evidence}{E\text{ is syntactically well-formed advice}\quad
 E_{\rm key}\text{ holds}\quad (t',\rho)=\mathsf{plan}(t,M,K,E)}
 {\mathrm{supp}(\alpha(t'))=\mathrm{supp}(\alpha(t))\quad
  \rho\text{ satisfies PL-Closure under }E_{\rm key}}
\end{mathpar}

Evidence records row counts, keys, foreign keys, selectivities, bounds and
sortedness beside analysis obligations. Keys are explicit author assertions
of physical uniqueness, not estimates; a false key can change grouped answers.
All other facts remain nonsemantic estimates used by checked execution-shape
selection. They do not authorize changing the recorded relational plan.

The \code{Planner} interface accepts $(t,M,K,E)$ and returns a program and
replayable advice trace. Serialized author advice and generated advice use
the same checked operations. The facade's Sequence-input \code{plan = path}
phase may select an ordinary custom pass; the default is order-preserving
decomposition. PL-Closure and the conformance harness remain unchanged.

\paragraph{Task translation.}
\begin{mathpar}
\Rule{T-Tasks}{t\text{ checked against }\mathsf{host}>\mathsf{pool}(\text{separated, dynamic})>\mathsf{task}}
 {\mathsf{run}_{\rm tasks}(t)=\text{T-Pull at }\mathsf{host};\

A collective graded at the separated pool is rejected by BE-Collective; a
reduction at the join does not make the pool collaborative. Panics
propagate through the join to the host, and no partially joined result is
published.
The shared dispatch erases the coarse index body before entering Rayon.
Publication groups contiguous tiles into a bounded multiple of the worker
count and joins per-group buffers in encounter order; per-index result slots
preserve order without specializing the scheduler for each pipeline.
The Tasks machine API \code{machine()} uses a fixed default of 64 logical
pool partitions; \code{machine\_with\_width(parts)} requires a positive count
and records it as the pool's distributing width. This logical width is not
the contiguous tile grain and is not the Rayon worker count. Changing the
runtime thread count changes scheduling and may select an equivalent recorded
worker-guarded cover, never results. Keyed group and routed point
providers realize BE-KeyPartGroup and BE-KeyPartProvider only where the
checked Sequence records them; the translator introduces no partition plan.
Joining task buffers preserves every surviving sequence dimension. Fold,
Canon, and Group remain lifted over those dimensions, rather than consuming
tile iterators as rows. Flattening a completed key cover restores ordinary
host reads; flattening a symbolic worker-local tile does not, until its join.
An early retained host publication uses an identity join predicate until its
covering provider is built (IF-JoinFilter). The build shadows that initial
binding, so subsequently evaluated lazy pipelines use the constructed filter.
The exact covering operator still rejects the same nonmatching rows.
Tasks consumes BE-Publication's ownership and representation records rather
than rediscovering base-row ancestry, partition consumers, or provider type
names. A BorrowHost routing input reads borrowed host tiles (or base-relative
positional ranges), without an intermediate whole-host vector. Host tiles
apply every recorded join-filter predicate inside each base-relative range,
not in a serial collection before dispatch. Routing groups consecutive chunks
into scheduler-fold-local buckets, reuses the first nonempty owner buffer,
and preserves occurrence order within each published part. These are
realizations of the existing checked covers, not additional IR choices.
For a recorded singleton provider cover over an immutable published source,
Tasks retains the source iterator rather than copying it into a row-part
vector. The native inner provider consumes that iterator directly. Routed
covers retain their owned part buffers and matching lookup-key router.
The singleton therefore records no partition-buffer insertions, while native
provider insertions are still counted. Any preceding owned input publication
remains an independently accounted Store.

The parallel Datalog extension (Section~\ref{sec:datalog-languages}) is the
task interpretation at the granularity of rule holes: its partitioned
leading scan is \code{tile} of \code{rows}, its grain the tile size, its
sharded admission BE-Canon, its publication barriers host-level
boundaries.

\paragraph{Checked GPU launch refinement.}
The GPU machine records its collective block width and the kernel-occupancy
policy. Grading records every dispatch's partition, publication, offset scan,
fold completion and required host synchronization points; these records are
part of printable analysis. One-part is explicit, not a fallback triggered by
a deferred range or a whole-input fold. The native contiguous-range predicate
is supplied by catalog identity, not by generated names or type suffixes.
GPU launch refinement precedes BE-Resource: shared-memory accounting and CUDA

of that store's deferred-range input.
\begin{mathpar}
\Rule{GPU-Launch}{d\text{ is a checked dispatch}\quad M.\mathsf{gpu}\text{ supplied}}
 {\mathsf{execution}(d)=
  (\mathsf{partition},\mathsf{kernelOccupancy},\mathsf{publication},
   \mathsf{offsetScan},\mathsf{foldCompletion},\mathsf{synchronizations})}
\Rule{GPU-LAUNCH-OCCUPANCY}{P=\text{domain tile count}\quad
 S=\text{device SM count}\quad R=\mathsf{residentBlocks}(K,\mathsf{threads},\mathsf{shared})>0}
 {\mathsf{grid}(K,P)=\min(\max(1,P),S R)}

 \ell_0,\ldots,\ell_{n-1}\text{ initialized}\quad \ell_n=0}

The deferred-range publication refinement applies only to a nonterminal,
noncanonical, non-provider-building publication with one chain whose last
contiguous lookup is followed only by stores and at least one flatten.
Host row consumers exclude this representation. The producer writes parent
rows, range beginnings and lengths on all scheduled blocks; a separate
device-wide scan completes offsets before consumers run. Wrapping offsets
are detected by adjacent-prefix decreases and abort publication.
Whole folds retain one scalar per block and combine on the producing stream;
the empty domain still produces the monoid identity. Checked arithmetic and
the existing monoid-law premises remain in force.
Count/failure readback for capacity replay is an explicit synchronization
record. Deferred offsets additionally record their total/failure readback.
There is no unrecorded per-dispatch fence.
Scan modules and workspaces may be retained per pool identity across invocations;
their context, stream and allocator owner outlive every borrowed resource.
Reuse changes neither the recorded scan step nor its failure/readback contract.

\paragraph{Arbitrary-width canonical provider.}
Let an injective recorded codec pack a row into $N=\max(1,\lceil b/64\rceil)$
little-endian lanes, where $b$ is computed from its checked setup bounds.
\begin{mathpar}
\Rule{GPU-WideCanon}{\mathsf{pack}\text{ injective}\quad
  P=\mathsf{stableRadix}_{N-1}\circ\cdots\circ\mathsf{stableRadix}_{0}}
 {\mathsf{decode}(\mathsf{unique}_{=\,\text{all lanes}}(P(\mathsf{pack}(B))))
   =\iota(\mathrm{supp}\,B)}
\end{mathpar}
This is an instance of BE-Canon: successive stable least-significant-lane
passes establish a total complete-key order, and adjacent equality compares
every lane. The target's \code{PackedCanon} (at most 128 bits) and
\code{WideCanon} (no fixed width limit) are device implementations of
sort/unique, recorded as \code{sort using Type}, not interchangeable hash-set
canonicalizers.
Complete declared domains, never statistical evidence, supply conservative
width obligations; actual lane counts use codec bounds at setup. Both
implementations publish the same device-resident count, failure ancestors,
and decoded column protocol.

The CUDA machine bounds block shared storage by 101,376 bytes. Its single
layout implementation starts with 48 bytes, records each materialized lookup's
256 begins and 257 offsets as four-byte entries, and stores each live parent
column for 256 members using its target carrier width (four-byte certified
narrow codes, otherwise eight bytes). A fold reserves 256 eight-byte values.
Every allocation retains its alignment and every choice arm is represented;
the final size is aligned to sixteen bytes. The same layout implementation
supplies BE-Resource and emitted offsets, so resource failure cannot select
an alternative algorithm inside the interpreter.

For the GPU instance of E-Neg (and RA-Anti), the checked Physical provenance
of \code{compact(lookup)} records the negative polarity. Let
$m(\rho)$ be the provider's membership result on the recorded key columns.
The lane keep bit is $\mathsf{live}(\rho)\land\neg m(\rho)$ for anti,
and $\mathsf{live}(\rho)\land m(\rho)$ for semi. Both polarities use the
same membership probe; neither expands witnesses. Empty provider ranges,
absent directory keys, and existential wildcard columns follow the same
equation. The translator reads this polarity, rather than choosing it.

\paragraph{Packed-run inputs and candidate arenas.}
A checked binding records that a host input is a collection of device runs
of packed words (\textsc{DL-DevicePacking}) in a stated column permutation;
it is never inferred from a built index. Scanning visits every run; a lookup
of a key prefix takes one contiguous word range per run, and expansion loops
over runs uniformly across the block, flattening each run's ranges as in the
segmented-flatten lemma. Membership is the disjunction over runs.
\begin{mathpar}
\Rule{GPU-Runs}{\text{input bound to runs }\rho_1\ldots\rho_m\text{ with packing }p\quad
 \textsc{STR-RunRead}}
 {\mathsf{lookup}(k)=\biguplus_j\mathrm{unpack}_p(\rho_j[\mathrm{range}_p(k)])\quad
  \mathsf{member}(k)=\bigvee_j\rho_j[\mathrm{range}_p(k)]\neq\emptyset}
\end{mathpar}
An arena terminal publishes the hole's head rows packed in the head's
canonical column order into a caller-owned device buffer and returns it with
its length. It is a candidate bag: canonicalization belongs to admission
(\textsc{DL-DeviceRuns}). Sizing follows the dispatch's recorded output
protocol, so a batch is never truncated.
\begin{mathpar}
\Rule{GPU-Arena}{\mathsf{run}_{\rm gpu}(t)\text{ as T-Gpu}\quad
 \text{output protocol discharges BE-Length}}
 {\mathrm{unpack}(\mathrm{arena})\equiv_{\mathrm{bag}}\sem{t}}
\end{mathpar}
Publishing an arena batch needs no terminal stream fence. Every recorded
dispatch metadata check and BE-Abort flag is still read before publication;
the batch retains its owners, and all later use, reuse and destruction are
ordered on the same pool stream, so a consumer can never observe an incomplete
batch. Timing events and the fence that reads them are opt-in and do not
change the result.
\begin{mathpar}
\Rule{GPU-Arena-Timing}{\text{metadata and BE-Abort checked before publication}\quad
 \text{all uses ordered on the producing stream}}
 {\text{omitting the terminal fence preserves }\textsc{GPU-Arena}}
\end{mathpar}
The recorded output protocol \code{reserve\_previous}, accepted only by the arena
terminal, starts each invocation of a hole with the last validated count of
that hole as its capacity (zero at first use). The remembered count is an
initial capacity, not a bound: the kernel counts every candidate and writes
only in bounds; an arithmetic failure aborts (BE-Abort); a capacity shortfall
discards the attempt and reruns it with the full required capacity against the
same immutable snapshot. Only a fully validated, initialized prefix is
published, so the batch equals the Count protocol's.
\begin{mathpar}
\Rule{GPU-ReservePrevious}{\text{inputs immutable during the invocation}\quad
 \text{count}\le\text{capacity checked before publication}}
 {\text{published batch}=\text{the }\mathsf{count}\text{ protocol's batch}}
\end{mathpar}

\paragraph{Closed host captures.}
A query-closed operand of an explicit relational \code{where} predicate is
evaluated once on the host per invocation and encoded through the column's
recorded provider/codec. Equality requires an equality-preserving encoding;
ordered predicates additionally require an order-preserving encoding.
No type spelling supplies either law. The capture is evaluated before its
first enabled, nonempty consuming dispatch and cached across capacity retries.
Rust guards, bindings and iterator expressions remain verbatim: they are not
split into recognized comparisons or rewritten to operate on dictionary IDs.
Their row reads must all have recorded identity device representation; their
other inputs are closed captures. Unknown or codec-encoded row reads require
host Rust execution, independently of the common pure-total premise.
\begin{mathpar}
\Rule{GPU-Capture}{e\text{ query-closed}\quad e\text{ deterministic and total}\quad
 \phi\text{ a relational predicate}\quad
 \mathrm{enc}\text{ preserves the predicate's equality/order}\quad
 C(e)=\text{recorded consuming definitions}\quad
 D(e)=\{(d,b)\mid C(e)\cap\mathrm{definitions}(d,b)\ne\varnothing\}}
 {\sem{\phi[\mathrm{enc}(e)/e]}_{\mathrm{device}}=\sem{\phi}_{\mathrm{host}}
 \quad\mathrm{evaluate}(e)\iff\bigvee_{(d,b)\in D(e)}(|d|>0\land b)}
\end{mathpar}
The capture record retains parameter indices and definition dependencies before
emission. Launch construction supplies the recorded domain length and branch
enable expression; generated names and kernel argument offsets carry no meaning.
The invocation-local cache is shared across capacity retries.

\subsection{Grouped folds}
\label{sec:grouped-fold}
A rule head may contain \code{count()}, \code{sum(e)}, \code{min(e)}, and
\code{max(e)}. Its remaining variables form the ordered key $K$. Let $V$
contain every named body variable, excluding anonymous wildcard witnesses,
and let $D=\delta(\pi_V\llbracket B\rrbracket)$ be the set of body valuations.
All aggregates consume this same domain. For $k\in\pi_K D$, write
$D_k=\{\rho\in D\mid\rho|_K=k\}$ and let
$[e(\rho)\mid\rho\in D_k]$ be a \emph{bag}: distinct valuations with equal
expression values contribute separately. This is SQL grouping over
\code{SELECT DISTINCT} of all named body columns, not an aggregate with
\code{DISTINCT} applied to its argument.
\begin{mathpar}
\Rule{RA-Group}{D=\delta(\pi_V\llbracket B\rrbracket)
 \qquad G=\pi_KD\text{ if }K\ne\varnothing,\quad G=\{()\}\text{ otherwise}}
 {\mathsf{group}_{K;(e_i,M_i)_i}(D)
  =\{(k,(\bigoplus_{M_i,\rho\in D_k}e_i(\rho))_i)\mid k\in G\}}
\end{mathpar}
Count uses $(\mathbb N,+,0)$ and $e(\rho)=1$; sum uses the declared additive
commutative monoid. Min and max use the option lifting of the declared
total order, with \code{None} as identity and \code{Some} as injection.
Thus empty keyed input has no answer, while empty global input has one
answer containing zero counts/sums and absent extrema. These laws assume
the declared operations satisfy their monoid premises; Rust expressions are
total by premise and runtime failures must never publish a partial answer.

Let $S$ be a store of distinct valuations, partitioned by key, and let
$o_k,o_{k+1}$ be the owner offsets of key $k$ in the grouped store.
\begin{mathpar}
\Rule{BE-Group}{\alpha(S)=D\qquad
 S[o_k:o_{k+1}]\text{ enumerates }D_k\text{ exactly once}}
 {\mathsf{segfold}_{K;(e_i,M_i)_i}(S)
  =[(k,(\mathsf{fold}_{M_i}(\mathsf{map}_{e_i}
       S[o_k:o_{k+1}]))_i)\mid k\in G]}
\end{mathpar}
Existing whole-sequence fold cannot introduce a data-dependent partition.
A segmented-fold term therefore records the keyed store and its per-owner
fold; its input canonicalization is over $V$, never over aggregate values.
The host hash-grouped implementation fuses store construction and segment
fold without changing this equation. The Tasks interpretation performs this
operation at the host join or independently inside key-disjoint parts under
BE-KeyPartGroup, never as a collective at the separated pool.

\paragraph{Key-aware grouped fold.}
\begin{mathpar}
\Rule{BE-GroupKey}{E_{\rm key}\models K_R\to R\ \text{with unique physical keys for every positive atom }R
 \quad V\text{ determines every }K_R}
 {\mathsf{canon}(\mathsf{valuations}_V)=\mathsf{valuations}_V}
\end{mathpar}
Under these asserted premises, each complete named valuation identifies at
most one physical witness combination. RA-Group therefore folds the same bag
without the canonical-valuation store. Renames translate keys, joins combine
them, scalar binds and filters preserve them, and projection must retain a key.
Expanding Rust binds and unions supply no such certificate. The checked
\code{group\_without\_canon} rewrite removes canonicalizers only if the resulting
group input still has proven positional uniqueness. Proof caches include
evidence, so removing an assertion cannot reuse its proof. GPU interpretation
may read resident columns directly and evaluate only the group arguments;
it does not decide whether a key premise holds.

\paragraph{GPU machine instance of BE-Group.}
The target canonicalization implementation publishes the distinct complete valuations
before the grouped boundary. Stable radix ordering of their key codes gives
a permutation $\pi$; adjacent unequal keys mark owner offsets. Thus each
half-open segment of $\pi$ enumerates exactly $D_k$, and the same BE-Group
equation applies, without a new rewrite or a translator-selected plan.
Each owner is reduced collaboratively using the declared integer monoid:
count and sum have zero identity; extrema carry a separate validity bit
and retain the full-width value, including both signed endpoints.
Codec widths constrain the result (in particular unsigned 32-bit sums
cannot silently become signed 64-bit sums). Runtime capacity or offset failure
is reported through output status, together with ancestor failures.
Empty keyed input publishes zero owners; an empty global key publishes one
owner with count/sum zero and invalid extrema. Values, validity, and logical
output count remain resident until the explicit typed host decode.

\subsection{Related work}
NESL and flattening~\cite{paper-nesl,paper-ndp-gpu} give the objects and
BE-Offsets. Lift/RISE~\cite{paper-lift} give views, lengths in types and

execution resources as terms and collectives only on whole resources; here
that is the GPU instance of the grading. Futhark~\cite{paper-futhark,paper-futhark-flatten}

schedule-as-rewrites discipline the pipeline already follows.

the output protocols. What none of them covers: relations under a set
denotation with a canonical boundary (BE-Alpha, BE-Canon), joins as
flattens of lookups into indexes built in a prior phase (BE-Bind), and a
partial host fragment with written-order meaning above a total device

\paragraph{Invocation-local proof reuse.}
Planner enumeration may share a checked Structures prefix, its support graph,
and immutable structural analysis between candidates. Cache hits require
complete syntax equality; interned proof identities are introduced only after
that comparison. Evidence changes revalidate evidence obligations, and grading
is always checked against the requested machine. Preparing common placement
once and batching nonsemantic grades therefore preserves PL-Closure and PL-Det;
the replay trace still contains the individual checked decisions.

Catalog read-level premises apply to the consuming row layout as well as the
indexed payload. A host-only row cannot acquire a descendant-only read token
merely because its lookup key is numeric. A checked publication of numeric
rows before a host consumer is an alternative under BE-Scope and PL-Precedence,
not an exception to the catalog premise. Resource-rejected dispatches may
instead publish named inner flatten levels using EXT-SeqStore; every resulting
tile/item candidate still satisfies BE-Resource before PL-Cost selection.

\subsection{Nonsemantic expansion observations}
\Rule{SQ-ExpansionCounters}
 {s\text{ is a checked Sequence expansion site}\quad
  C_s=\sum_{p\in\mathsf{parents}(s)}|\mathsf{children}_s(p)|}
 {\mathsf{observe}(s)=C_s\quad
