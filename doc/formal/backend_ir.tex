\section{Sequence: the back-end level (design)}
\label{sec:backend-ir}\label{sec:sequence}
This section is a design, not a verified implementation; its rules are
\emph{abstract} in the inventory until a pass and a check implement them. It
adds one level below Structures, \emph{Sequence}, shared by every back end,
and states what below it is not a level: placement is a grading on Sequence
terms, the machine is a parameter of that grading, and each emitter is a
translation. The level names no data structure, no algorithm and no machine.

\subsection{Why one level, and why this one}
A level is justified when its denotation changes: it adds or forgets an
observable, so that a different class of programs becomes equal. Below
Structures exactly one such change happens. Every level through Structures
denotes a function into $T X=\bot+\mathrm{Set}_{\rm fin}(X)$ composed in
written order (Section~\ref{sec:denotation}); the sequential pull runtime
makes nothing else observable, so order, multiplicity before \code{canon},
evaluation counts, sizes and placement are all the emitter's to choose. A
parallel runtime makes positions and sizes decisions that change the
program (which positions form the parallel domain; what must be allocated
before it runs), and makes placement and partiality constraints on whether
a term can run at all (where a value is visible; that device code cannot
unwind). Positions and sizes change the objects: that is the Sequence
level. Placement and partiality constrain terms without changing their
values: that is a type-and-effect grading, not a level. Kernels, barriers
and launch shapes are derived from the grading: not a level, not syntax.

This is deliberately not progressive lowering in the MLIR sense. A pass
takes a whole program at one level to a whole program at the next; no
program mixes levels; the composition theorem of
Section~\ref{sec:composition} depends on that. A back end that needs a
construct the shared level lacks defines a complete diverged variant with
its own check, as \code{diverged-ra} does; nothing is mixed into the shared
level.

\subsection{Objects: the sequence monad and its morphisms}
Let $\mathrm{Seq}$ be the finite-sequence monad: $\eta(x)=\langle x\rangle$,
$\mathsf{map}$ its functor action, $\mathsf{flatten}:\mathrm{Seq}(\mathrm{Seq}\,X)\to\mathrm{Seq}\,X$
its join. $\mathrm{Bag}$ and $\mathrm{Set}$ are monads likewise, and the
forgetful maps are monad morphisms:
\[
 \mathrm{Seq}\xrightarrow{\ \alpha\ }\mathrm{Bag}\xrightarrow{\ \mathrm{supp}\ }\mathrm{Set},
 \qquad \alpha\circ\mathsf{flatten}=\mathsf{join}_{\rm Bag}\circ\alpha\circ\mathrm{Seq}(\alpha),
 \quad \alpha\circ\mathsf{map}\,f=\mathrm{Bag}(f)\circ\alpha .
\]
The front end computes in $\bot+\mathrm{Set}$; Sequence computes in
$\bot+\mathrm{Seq}$; the refinement obligation is that the morphism of the
result equals the front-end value. Parallel admissibility is exactly the
structure $\mathrm{Bag}$ has and $\mathrm{Seq}$ lacks: its monoid is
commutative, so a fold over it is schedule-independent, and $\alpha$
forgets the order a schedule imposes.

A Sequence object is a nested sequence of \emph{coded} rows together with
its shape. Its type carries its lengths as symbolic expressions over input
lengths and earlier scans (size-dependent types in the sense of
Lift and Futhark~\cite{paper-lift,paper-futhark}); a term whose length is
not expressible is given a declared capacity. A codec
$\kappa=(\mathsf{enc},\mathsf{dec})$ with $\mathsf{dec}\circ\mathsf{enc}=\mathrm{id}$
on its domain refines row values; $\alpha$ applies $\mathsf{dec}$ per
column. A \emph{space} is a shape considered on its own: a finite index set
with lexicographic order and nesting.

\subsection{Terms}
$f$ ranges over per-position maps built from the total Physical kernels
(rename, project, relational select, point and range reads, semi and anti
tests over admissible keys; ST-Total). $b$ ranges over providers.
\begin{lstlisting}
t ::= rows r                     // the positions of a retained result or host
    | map f t                    // per-position total map
    | flatten t                  // join; offsets are the scan of lengths
    | compact p t                // total filter, order-preserving
    | tile n t                   // view: regroup into runs of n
    | lookup b [K] t             // per-position bucket of provider b
    | fold (o,e) t               // monoid fold
    | canon t                    // support
    | store t                    // materialize (the only non-view)
    | choose [ g => t ]*         // size-guarded equal alternatives
\end{lstlisting}
\code{tile}, \code{flatten} over known offsets, \code{lookup} over a range
cursor and the gathers inside $f$ are \emph{views}: bijections on positions
that change addressing and materialize nothing (Lift's layout patterns,
Descend's views~\cite{paper-lift,paper-descend}). Only \code{store}
materializes; a stored \code{flatten} is kept as its offsets (BE-Offsets).
\begin{mathpar}
\Rule{BE-Alpha}{}
 {\alpha(\mathsf{map}\,f\,t)=\mathrm{Bag}(f)(\alpha t)\quad
  \alpha(\mathsf{flatten}\,t)=\alpha t\quad\alpha(\mathsf{tile}_n t)=\alpha t\quad
  \alpha(\mathsf{compact}\,p\,t)=\alpha t|_p\quad\alpha(\mathsf{store}\,t)=\alpha t}

\Rule{BE-Bind}{\mathsf{rangeCursor}(b,K)}
 {\sem{\mathsf{probe}[K](l,b)}=\mathrm{supp}\,\alpha\big(\mathsf{flatten}(\mathsf{map}\,(x\mapsto x\bowtie\mathsf{lookup}_b[K]\,x)\,l)\big)}

\Rule{BE-Partition}{\{P_k\}\text{ disjoint}\quad\textstyle\bigcup_kP_k=[0,|t|)\quad
 (\oplus,e)\text{ commutative}}
 {\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t)=\textstyle\bigoplus_k\mathsf{fold}_{(\oplus,e)}(\mathsf{map}\,f\,t|_{P_k})}

\Rule{BE-Offsets}{o=\mathsf{scan}_{(+,0)}(|t_0|,\ldots,|t_{|t|-1}|)}
 {(\mathsf{flatten}\,t)_j=(t_i)_{j-o_i}\text{ for the unique }i\text{ with }o_i\le j<o_{i+1}}

\Rule{BE-Canon}{\alpha t=B}
 {\alpha(\mathsf{canon}\,t)=\iota(\mathrm{supp}\,B)\quad
  \mathsf{canon}(\textstyle\biguplus_kB_k)=\mathsf{canon}(\textstyle\biguplus_k\mathsf{canon}\,B_k)}

\Rule{BE-Code}{\mathsf{dec}\text{ injective on }K\text{ (both sides)}\quad
 \mathsf{enc}\text{ monotone on }c}
 {\text{equality, hashing and canon on }K\text{, and order reads on }c\text{, act on codes}}

\Rule{BE-Choose}{t_1,\ldots,t_n\text{ equal under BE-Partition}\quad
 \text{guards }g_i\text{ over lengths, exhaustive}}
 {\mathsf{choose}\,[g_i\Rightarrow t_i]\text{ denotes any }t_i\text{; which runs is free}}
\end{mathpar}
BE-Bind is the Kleisli bind of Section~\ref{sec:denotation} restated: a
probe is a flatten of per-row lookups, so a join nest is a nested flatten
and flattening it (NESL~\cite{paper-nesl,paper-ndp-gpu}) is what removes
irregular nesting. BE-Partition is the law every schedule relies on; it
holds for partial $f$ (one undistinguished $\bot$) but licenses no early
stop and is stated on bags: a lost or duplicated position changes
$\alpha$. BE-Canon makes per-part canon a sound prefilter that replaces
the global boundary only when equal rows meet in one part. BE-Choose is
incremental flattening~\cite{paper-futhark-flatten}: the right
decomposition depends on lengths known at run time, so several equal
decompositions may be recorded under thresholds that are tuning
parameters, not meaning.

\paragraph{Providers and codecs are capabilities.} A provider is read
through \code{lookup} and the term records only what the read requires:
exact bucket, contiguous range (rangeCursor), membership, order. Its type
is an opaque token discharged by runtime traits, as Structures does today
(STR-Key, STR-SortedRun); the same holds for codecs (BE-Code's premises
are trait obligations, like Leibniz admissibility) and for \code{canon}.

\subsection{Placement: a grading over a machine parameter}
\begin{definition}[Machine model]
A finite tree of \emph{levels} $\ell$, each labelled: \emph{collaborative}
(members share storage and may synchronize; collectives are available) or
\emph{separated} (members share nothing and exchange only through a store
at a common ancestor, at a boundary); scheduling static or dynamic; and a
failure channel to the root. The root is $\mathsf{host}$.
\end{definition}
\begin{center}
\begin{tabular}{@{}p{0.16\linewidth}p{0.4\linewidth}p{0.2\linewidth}p{0.16\linewidth}@{}}
\toprule
 & GPU (SIMT, cooperative groups) & tasks (Rayon) & sequential\\
\midrule
levels & host $>$ device $>$ block $>$ warp $>$ lane & host $>$ pool $>$ task & host\\
collaborative & block (shared memory, barrier), warp (lockstep) & none & —\\
separated & device/host; block/block (no forward progress) & task/task (join) & —\\
scheduling & blocks dynamic, order undefined & work stealing & fixed\\
failure & flag read by host & panic at join & unwind\\
\bottomrule
\end{tabular}
\end{center}
A Sequence term is \emph{graded}: each subterm carries the level that
evaluates it, each \code{store} the level that holds it, and \code{tile}
descends one level. The grading is a type-and-effect discipline, not a
language: it is checked against the machine parameter and changes no value.
Execution resources in the sense of Descend~\cite{paper-descend} are the
GPU instance of the grade.
\begin{mathpar}
\Rule{BE-Scope}{\mathsf{store}\,t\text{ at }\ell\quad\text{a read at }\ell'\le\ell\text{ lexically inside its extent}}
 {\text{the read is admissible}}

\Rule{BE-Collective}{\mathsf{fold}/\mathsf{scan}\text{ at }\ell\quad\ell\text{ collaborative}\quad
 \text{the whole of }\ell\text{ participates}\quad\oplus\text{ associative}}
 {\text{equals the sequential fold; commutative }\oplus\text{ makes it schedule-independent}}

\Rule{BE-Separate}{\ell_1,\ell_2\text{ separated siblings}}
 {\text{they exchange only through a store at a common ancestor; nothing else is observable across them}}

\Rule{BE-Length}{\mathsf{store}\,t\text{ at a separated level}}
 {|t|\text{ is in its type before the write (a scan), or a capacity with an overflow flag}}

\Rule{BE-Boundary}{\text{a maximal segment of total terms between stores at a separated level}}
 {\text{is one unit of dispatch (a kernel, a task); its domain is the outer stored space; derived, not written}}

\Rule{BE-Partial}{\text{opaque Rust }e}
 {e\text{ runs at }\mathsf{host}\text{ only: closed }e\text{ once before dispatch (IF-Parameter); row-dependent }e\text{ never below host}}

\Rule{BE-Abort}{\bot\text{ raised below }\mathsf{host}}
 {\text{a once-set flag on the failure channel, mapped to }\bot\text{ at the next host boundary; no truncated success}}
\end{mathpar}
The laws mention only labels of the machine parameter. A term that uses a
collective at a level the target marks separated is rejected for that
target, not reinterpreted. BE-Boundary derives kernels (GPU) and tasks
(Rayon) from the grading: the domain of a dispatch is the type of its outer
stored space, which replaces the current printer's
\code{driver.len.div\_ceil(1024)}; storing the H05 Customer level as
offsets makes the next dispatch span every customer. Written order has no
force below host: nothing partial is there (BE-Partial), so inside a
dispatch the full set algebra applies.

\paragraph{Output.} The final \code{flatten} into one stored sequence of
unknown length is one term with several interpretations, equal under
$\alpha$: lengths computed first by a count pass (purity, premise~3,
licenses running the map twice), reservation by a commutative concatenation
(schedule-dependent positions, same bag), or a bounded buffer with retry.
Which is recorded, because it changes the program. Parts write only
positions they own by a view, or buffers they allocated; nothing reads
another part's fresh allocation before a boundary. That is
disentanglement~\cite{paper-disentangle}, the memory property that makes
these protocols lock-free.

\paragraph{Cost.} The set model has no cost; Sequence has work and
span~\cite{paper-nesl}: work the number of positions evaluated, span the
longest dependency chain. Plan R's two schedules have equal work; a
one-part schedule has span proportional to work, a grid-wide one span
logarithmic. Cost is not meaning; it is what a decomposition pass argues
with, and lengths in types are what make it computable.

\subsection{Refinement and the emitter}
\begin{definition}[Sequence refinement]
A graded Sequence program $t$ over Structures $s$ refines $s$ for machine
$M$ when, for every input and every schedule $M$ admits under
BE-Partition, BE-Scope, BE-Collective, BE-Separate and BE-Abort,
$\mathrm{supp}\,\alpha(\mathsf{run}_M(t))=\sem s$ whenever $\sem s\ne\bot$,
and $\mathsf{run}_M(t)$ aborts only if some sequential schedule of $s$ panics.
\end{definition}
The obligation splits per construct: BE-Alpha for the shape terms, storage
laws for provider and codec interpretations, BE-Partition and
BE-Collective for the schedule. An emitter is a translation from graded
terms to the target (loops, assignments, barriers, launches), in the sense
of DPIA's strategy-preserving compilation~\cite{paper-dpia}: correct per
construct, race-free by construction from the views, deciding nothing. A
construct without a translation is rejected. Lift derives allocation and
barriers from its types~\cite{paper-lift}; here they are derived from the
grading, lengths and views.

\subsection{Passes}
\begin{itemize}
\item Structures $\to$ Sequence: the default lowering records ``one part,
nothing stored'': every result is a view or a device/host store as its
Physical mode says, no tiles. Its sequential interpretation is today's pull
printer, which is therefore already correct for it.
\item Sequence $\to$ Sequence rewrites, advice-driven as the existing
rewrites are (Section~\ref{sec:structures}), each with a law: store a
flatten level (BE-Offsets), tile a space (BE-Partition), record a
size-guarded alternative (BE-Choose), choose the output interpretation,
record codecs and canon.
\item Grading: assign levels against a named machine model; checked by
BE-Scope through BE-Abort.
\item Translation per machine.
\end{itemize}
This mirrors the algorithm/schedule separation of Halide and
Exo~\cite{paper-exo}: the pipeline's advice is the schedule, each primitive
is an equivalence-preserving rewrite with a stated law.

\subsection{The H05 reference as a term}
The hand-written kernels (\code{experiments/gpu/h05-reference}) are
\[
 \mathsf{canon}\big(\mathsf{flatten}(\mathsf{map}\,g\,(\mathsf{tile}_{256}\,C))\big),\quad
 C=\mathsf{store}\big(\mathsf{flatten}(\mathsf{map}\,(\mathsf{lookup}_{\rm Nation})\,(\mathsf{rows}\ \mathrm{Region}_{\rm ASIA}))\big)\text{ at the separated level}
\]
with $g$, per customer position, two further flattens (Orders by customer,
Lineitem by order) tiled at 1024 at the collaborative level with 4 items
per lane, a membership test (Supplier), and the output flatten interpreted
by a collaborative scan plus one reservation per tile. $C$ is stored as
offsets, not rows (BE-Offsets). Every provider is read as a range cursor;
every column is a dense code of one join domain; \code{canon} is a fold on
a packed code. Compiled plan R records the same Physical program; what it
lacks is \code{store} of $C$ and the tiles, which the current printer
decides for itself. Those are the terms a rewrite must record.

\subsection{Related work}
NESL and flattening~\cite{paper-nesl,paper-ndp-gpu} give the objects and
BE-Offsets. Lift/RISE~\cite{paper-lift} give views, lengths in types and
derived barriers, but encode the OpenCL hierarchy in the terms; here the
hierarchy is the machine parameter. DPIA~\cite{paper-dpia} gives the
emitter as a proved translation. Descend~\cite{paper-descend} gives
execution resources as terms and collectives only on whole resources; here
that is the GPU instance of the grading. Futhark~\cite{paper-futhark,paper-futhark-flatten}
gives size types and BE-Choose. Halide and Exo~\cite{paper-exo} give the
schedule-as-rewrites discipline the pipeline already follows.
Disentanglement~\cite{paper-disentangle} names the memory property behind
the output protocols. What none of them covers: relations under a set
denotation with a canonical boundary (BE-Alpha, BE-Canon), joins as
flattens of lookups into indexes built in a prior phase (BE-Bind), and a
partial host fragment with written-order meaning above a total device
fragment.
