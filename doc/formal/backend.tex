\section{Back end: representation, evaluation unit, control}
\label{sec:backend}

The back end separates three decisions over the same Physical program:
representation $R$, evaluation unit $E$, and control $C$. Structures records
$R$ and $E$; an emitter chooses $C$. None changes the written-order denotation
or discharges the host premises of Section~\ref{sec:premises}.

\subsection{R: representation as data refinement}
For each result $r:U_r$, choose a representation $\rho_r$ and an abstraction
$\alpha_r:\rho_r\to\operatorname{Bag}_{\rm fin}(\data^{U_r})$.
Tuples use the identity abstraction. Positions carry one \code{RowId} for each
lineage-connected base occurrence, together with owned computed columns.
For a carried occurrence $H$ and logical-to-host map $\lambda_H$, abstraction
fetches column $\lambda_H(c)$ at that occurrence's ID; owned columns are read
by value. IDs are physical witnesses, not logical attributes. Distinct
occurrences of the same host remain distinct, as in join indices~\cite{paper-join-indices}.
The Structures grammar adds:
\begin{lstlisting}
Entry ::= r repr = tuples;
        | r repr = positions { H1 lineage { a -> c, ... },
                               H2 lineage { ... } } owned [x, y];
\end{lstlisting}
The occurrence list is finite; \code{owned []} is permitted. An absent entry
means \code{tuples}. Each lineage map is rederived from Physical, not trusted
because it was written. Let $L_r=\bigcup_H\dom\lambda_H$ and let $O_r$ be the
owned computed columns. The structural check requires coverage of the whole
heading (hence of every downstream key, predicate, Rust free variable and
returned column) and valid, unambiguous origins:
\begin{mathpar}
\Rule{STR-Repr}{
 \forall H,\ \mathsf{lineageConnected}(r,H,\lambda_H)\quad
 \mathsf{validOwned}(r,O_r)\\
 \mathsf{unambiguous}(L_r,O_r)\quad \mathsf{heading}(r)\subseteq L_r\cup O_r
}{\mathsf{covered}(r,\rho_r)}
\end{mathpar}
This is the checkable part of data refinement~\cite{paper-data-refinement}.
The semantic forward-simulation obligation, for every operator with inputs
$r_1,\ldots,r_k$ and output $r$, is
\[
 \alpha_r(\mathsf{op}_{\rho}(x_1,\ldots,x_k))
 =\mathsf{op}(\alpha_{r_1}(x_1),\ldots,\alpha_{r_k}(x_k)).
\]
Here $\mathsf{op}$ is the bag realization of the Physical step.
Initialization and reads obey the same commuting law.
Structural coverage does not prove the storage laws: fetch
must equal the indicated column of \code{row_at}, and builds and reads must
preserve multiplicity. The target of $\alpha$ is a bag, not a set;
\code{canon} takes support and re-establishes the set boundary. Positional
representation alone proves neither uniqueness nor ordered enumeration.

\paragraph{Build statistics.}
The provider declaration owns each statistic's field, unit, precision,
producer, accessor ABI, placement, availability, computation and aggregation
law. A \code{publications} record binds that declaration to one immutable
Physical build, provider token, complete ordered layout and code-domain epochs.
\begin{mathpar}
\Rule{STR-BuildStats}{
 s\in\mathsf{declaredStats}(p)\quad
 (b,p,L)\in\mathsf{selectedBuilds}\quad
 \mathsf{domainsMatch}(b,L,s)\quad\mathsf{aggregationLegal}(s)
}{\mathsf{publication}(b,p,L,s)\text{ is well formed}}
\end{mathpar}
Exact distinct keys and maximum buckets are not sums over overlapping
segments; full-key counts never describe a scalar projection. Numeric accessor
ABI is a read-only, constant-time \code{Option<u64>}: absence is not zero
and neither availability nor a read may force lazy work. Code bounds are not
numeric count operands. No statistic is selected automatically by this contract.

\paragraph{CPU runtime publication laws.}
\textsc{RT-BuildStats} requires every present scalar to equal its stored
occurrence oracle: rows count occurrences, keys count complete grouping keys,
and maximum group counts the largest bucket (zero for completed empty data).
The \code{stat\_rows}, \code{stat\_keys}, \code{stat\_max\_group} accessors,
and run providers' \code{stat\_runs}, read metadata in constant time.
An unfinalized lazy hash returns absence, not zero. Multi-run global keys and
maxima remain absent unless already established by an existing materialization;
neither access nor availability may trigger that work.
Structures records ordinary versus statistics construction and a demand mask.
Provider \code{statistics\_build} declares the accumulation fields; selected
publications supply each demanded bit's immutable build/layout witness.
The checker validates these witnesses without rerunning selection.
The printer emits ordinary \code{Build::build}, or the recorded
\code{BuildWithStatistics} call, never deriving protocol support from accessors.
\code{BuildWithStatistics} and \code{BuildWithSidecar} take independent
\code{ROWS,MAX\_GROUP} const-generic method parameters while preserving the
normal lazy boundary. Demanded initializer dispatch occurs outside the
ordinary \code{OnceCell} closure, preserving its hot-loop register allocation.
Ordinary \code{Build} requests no accumulation; cheap lengths remain available.
Explicit direct \code{from\_pairs} constructors retain their documented defaults.
\begin{mathpar}
\Rule{STR-Construction}{
 d=\mathsf{recordedDemand}(b,p,L)\quad
 \forall f\in d:\ \mathsf{supportsAccumulation}(p,f)\land
 \mathsf{selectedPublication}(b,p,L,f)\quad
 \forall f:\ \mathsf{supportsAccumulation}(p,f)\land
 \mathsf{selectedPublication}(b,p,L,f)\implies f\in d
}{\mathsf{construction}(b,p,L)=
 \begin{cases}\mathsf{Ordinary}&d=\varnothing\\
 \mathsf{Statistics}(d)&d\ne\varnothing\end{cases}}
\end{mathpar}
\begin{mathpar}
\Rule{RT-BuildStats}{
 \mathsf{stat}(x,f)=\mathsf{Some}(n)
}{n=\mathsf{oracle}_{f}(\alpha(x))}
\end{mathpar}
\textsc{RT-RunFilter} governs borrowed ordered scalar run views. Point tests
are exact; an interval test uses lower-bound search and OR across all runs.
The selected scalar must be the complete stored layout; arbitrary composite
projections are not licensed by lexicographic order.
\begin{mathpar}
\Rule{RT-RunFilter}{
 F=\mathsf{borrowedRunView}(x)\quad K=\mathsf{scalarKeys}(x)
}{
 F.\mathsf{test}(k)\iff k\in K\quad
 F.\mathsf{anyIn}(l,h)\iff \exists k\in K.\ l\le k\le h
}
\end{mathpar}
The provider token fact \code{run\_filter} declares the source capability;
\code{borrowed\_filter} and \code{attached\_filter} declare mutually exclusive,
explicitly advised realizations. With neither fact, the default conditionally
builds projected \code{Keys::distinct\_keys} through \code{Build} after activation.
Default activation retains ordinary construction and exact
\code{Keys::key\_count}. Only authored optional-statistic policies finalize the
source with a unit sidecar before reading metadata; scalar accessors never force work.
For explicit attachment, \code{BuildSidecar} supplies an incremental builder
and \code{BuildWithSidecar} returns the completed index and filter together.
Tuple builders observe the same construction without projected-key staging.
Conservative filters may admit false positives but never false negatives;
every exact covering operator remains.

\paragraph{Lookup witnesses.}
Either representation may append \code{witness \{ b [K] at s as Type \}}.
This cursor is not a column and does not contribute to coverage.
\begin{mathpar}
\Rule{STR-Witness}{
 \mathsf{share}(r)=(b,K,s,p)\quad
 \alpha_{\rm witness}(w)=\mathsf{lookup}_b(k)\\
 \mathsf{allPathsConsumeBeforeEscape}(r,p)
}{\mathsf{witness}(r,b,K,s,w)\text{ is admissible}}
\end{mathpar}
The escape obligation is checked explicitly, not implemented by pruning:
only project, select, point, range, left semi/anti, and nonintroducing probes
may forward the witness, and each must retain every lookup key column.
A rename starts a distinct occurrence; it is not forwarding evidence.
Every path must reach the force probe before canon, return, retained let/rows,
exists, union/fallback operands, fused prefixes, or opaque bind/guard.
Rust checks the cursor's type and Copy capability.
For a maintained leveled host the cursor is the bounded sequence of
$(\mathit{run},\mathit{begin},\mathit{end})$ ranges obtained from its snapshot,
not a single contiguous range. Its abstraction is their bag concatenation
(\textsc{STR-RunRead}). The force reuses every range without searching again;
the snapshot is immutable throughout the hole and cannot be inserted into or
compacted until all readers have been enqueued (\textsc{STR-RunSnapshot}).

\begin{lemma}[Witness abstraction]
Under STR-Witness, replacing the forcing probe's lookup by its carried
cursor preserves the row bag and bucket order.
\end{lemma}
\begin{proof}
The cursor abstracts to the same lookup; forwarding preserves the key,
and the force consumes it before any boundary can expose the carrier.
\end{proof}

\subsection{E: evaluation unit as strictness}
A \emph{stage} is a representable segment of a pipe's definition chain,
within its producer and consumption boundaries. All admitted Rust expressions
and relational kernels are total under the premises. Only explicit
\code{where} predicates become relational \code{select}; a Physical
\code{guard} remains the original Rust expression.
The checked batch vocabulary below is a representation capability, not a
totality classification. A Rust operation outside that vocabulary may end a
stage without acquiring a different meaning or a fixed written position.
For the checked stage rule, let
$\mathcal T_{\rm stage}=\{\mathsf{unit},\mathsf{rename},\mathsf{project},
\mathsf{select},\mathsf{point},\mathsf{range},\mathsf{semi},\mathsf{anti}\}$:
\begin{mathpar}
\Rule{ST-Total}{
 S=(o_1,\ldots,o_m)\quad \forall i,\ o_i\in\mathcal T_{\rm stage}\\
 \mathsf{admissibleKeys}(S)\quad \mathsf{totalInputs}(S)
}{\mathsf{total}(S)}
\end{mathpar}
Materialized inputs are values; new producers obey the same totality premises.
The stage checker records supported producer and consumption representations.

Structures records its evaluation unit by \code{r stage = batch N;} with
$N>0$: the chain from the preceding boundary (or producer) through $r$ runs
at most $N$ rows ahead. Absence means scalar demand, $N=1$. A \emph{for}
producer has a known finite length and indexable positions: a host scan,
retained \code{rows}, or a positional read. An \emph{unfold} producer advances
a state-dependent cursor. Probe and merge produce such cursors, so a checked
segment cannot contain them or end after them. Retaining their output as
\code{rows} supplies a new \emph{for} producer for a subsequent segment.
Semi and anti are total filtering steps and may lie inside a segment.
An explicit \code{expand} flag admits a probe whose selected provider declares
exact finite cursor expansion; unannotated probes still end the segment.
This distinction follows the producer representation of
Kiselyov et al.~\cite{paper-stream-fusion}; staging here specifies evaluation
strictness, not an additional relational rewrite.
\begin{mathpar}
\Rule{ST-Stage}{
 \mathsf{total}(S)\quad \mathsf{producer}(S):\mathsf{for}\quad N>0\\
 \mathsf{representedSegment}(S)\quad \mathsf{preserveDemand}(S)
}{r\;\mathsf{stage}=\mathsf{batch}\ N\text{ is admissible}}
\end{mathpar}
The staging pass records the previous fixed probe optimization as
\code{stage = batch 128}: a total rename/select/point/range/project host-scan
spine feeding a built probe. Unannotated authored Structures remain scalar;
the default pipeline preserves its earlier decisions by recording them.

\paragraph{By-need lookup sharing.}
\code{r share = lookup b [K] first s force p;} names an earlier retained
payload build or a recorded immutable host snapshot, an eager semi
with result $r=s$, and a later probe.
\begin{mathpar}
\Rule{ST-Share}{
 b<s<p\quad
 (\mathsf{letPayload}(b,K)\lor\mathsf{sameSnapshotLayout}(b,K,s,p))\quad
 s=\mathsf{semi}_{eager}[K](l,b)\\
 p=\mathsf{probe}[K](l',b)\quad\mathsf{preservedKeys}(s,l',K)
}{\mathsf{share}(s)=(b,K,s,p)}
\end{mathpar}
Each $(b,K,s)$ has one sharing decision. Without a witness it retains
ordinary re-evaluation. A retained witness additionally requires declared
\code{retain} support (or \code{expand}, which implies it) on the selected
payload or candidate layout; membership-only builds do not qualify.
Host reads must declare support at both demands and record the same provider,
layout and key on the same immutable occurrence. Snapshot publication belongs
to the runtime owner, not this pass. A different layout or key cannot establish
the premise. Generated witness types may be inferred; native emission checks
Copy without choosing a concrete cursor representation.

\paragraph{GR-Retain: nonintroducing bridges.}
The \code{retain\_lookups} producer follows the actual input chain from the
later force back to the eager lookup, not adjacency in the definition list.
The independently checked $\mathsf{preservedKeys}$ premise permits
project/select/point/range/semi/anti and a probe whose checked output heading
is contained in its left input heading. Every bridge keeps all retained key
columns (including candidate-directory prefixes) unchanged. A full-key
membership probe on another provider is therefore a bridge; it remains in
place and still filters the stream. It neither replaces the retained provider
nor becomes the force for that provider.
An introducing probe is not a bridge, even if a later projection drops its
new columns. Opaque binds/guards, lost keys and unsupported operators are not
forwarding evidence. STR-Witness additionally checks every consumer path:
no branch may publish, canonicalize, escape a scope or lose the key before
the recorded force. The same $(b,K,s)$ cursor is carried as a non-column Copy
field through admitted bridges and consumed at that force, without repeating
the lookup. Provider identity, ownership and immutable snapshot lifetime
requirements above are unchanged; the realization only transports the checked
witness and does not select bridges or inspect Rust types or expressions.
\begin{lemma}[Lookup coupling]
The retained memo satisfies $\mathsf{memo}=\mathsf{lookup}_b(k)$ at both demands.
\end{lemma}
\begin{proof}
Host immutability and the earlier let, or the shared snapshot lifetime,
keep the provider unchanged. The checked chain preserves key terms.
IndexRead's occurrence-preserving lookup law (STR-SortedRun and STR-RunRead
for runs) therefore identifies both total reads without changing the recorded
expression placement.
\end{proof}

\begin{mathpar}
\Rule{ST-Expand}{
 r=\mathsf{probe}[K](l,b)\quad \mathsf{declaresExpand}(b,K)\\
 \mathsf{totalSegment}(l,r)\quad \mathsf{producer}(l):\mathsf{for}
 \quad N>0\quad\mathsf{representedSegment}(l,r)
}{r\;\mathsf{stage}=\mathsf{batch}\ N\ \mathsf{expand}\text{ is admissible}}
\end{mathpar}
The declared expansion contract supplies a Copy exact-size cursor, checked by
the realizing backend. It does not require a sorted implementation or establish
the single contiguous item-array contract of Sequence's Range capability.
Smallest uses its selected two-level candidate directory, not an ordinary
complete-key payload index on the same prefix. A target must realize the
recorded decision and its cursor obligations or reject the unsupported access
shape; it may not silently erase the decision when switching terminals.
The native terminal currently rejects retained/expanded Smallest and retained
prefix shapes it cannot realize. The CUDA Sequence terminal rejects native
Structures witnesses, staging and join filters rather than treating them as
ordinary device lookups. Legacy provider names grant no exception.
A Smallest intersection records expansion only at its introducing probe.
Its membership checks are part of that same total intersection, not independent
cursors; subsequent staged probes may cross them without adding a force-stage.
\begin{lemma}[Segmented flatten]
Flattening $N$ finite ranges is total and length-known: with exclusive
offsets $o_i=\sum_{j<i}|R_j|$, its length is $M=\sum_i|R_i|$.
Each output position identifies exactly one nonempty owner range and offset.
\end{lemma}
\begin{proof}
Exclusive scan (Blelloch's prefix-sum construction) preserves range order;
concatenation preserves every occurrence. Chunks of the virtual array
therefore preserve the scalar bag and the recorded operator sequence.
\end{proof}

For total predicates $p_1,\ldots,p_k$ and a chunk $(x_j)_{j<n}$, initialize
$m_j=\mathsf{true}$ and update $m_j\gets m_j\land p_i(x_j)$ for each $i$.
The surviving positions are precisely
$\{j<n\mid\bigwedge_i p_i(x_j)\}$. Evaluating later predicates on rows rejected
by earlier ones is safe because no evaluation is $\bot$. Finite Set with
union and $\emptyset$ is a commutative idempotent monoid, so regrouping these
total contributions does not change the answer. At the bag level masks keep
each surviving occurrence once. A selection vector materializes surviving
positions at a representation boundary; it need not be materialized between
supported predicates. Early-stop consumers can change evaluation counts,
not the answer or the recorded plan.

\begin{lemma}[Forcing a lazy build]
Suppose a keyed read consumes its immutable build source once and subsequent
reads reuse the resulting index. Scalar and chunked realization of the same
recorded operations return the same bag.
\end{lemma}
\begin{proof}
Every build expression is pure and total and retains its free-variable
bindings. Repeated reads therefore observe one unchanged relation. Chunk
lookahead changes evaluation counts but neither index contents nor lookup
answers. Build timing remains a recorded representation decision.
\end{proof}

\subsection{C: control as fold/unfold duality}
Fix one stream algebra: empty stream, yield, map, filter and concatenation,
with the recorded Physical operators and $R/E$ decisions. Pull realizes it
by an unfold of a coalgebra $S\to 1+A\times S$; push realizes it by a fold
into a consumer algebra~\cite{paper-pushpull}. Exhaustive successful
realizations enumerate the same bag, including repeated witnesses; \code{canon}
then yields the same set. This is a control choice, not a new IR entry.

An early-stop consumer must already determine its answer from the consumed
prefix (for example a positive existential witness); arbitrary truncation of
returned answers is not allowed. Pull may omit later work once the answer is
determined, while preserving the supplied operator plan and free-variable
bindings. Writing $P$ for push execution and $L$ for pull:
\begin{mathpar}
\Rule{BK-Dual}{
 \mathsf{sameStreamAlgebra}(P,L)\quad \mathsf{sameRE}(P,L)\\
 \mathsf{sameRecordedPlan}(P,L)\quad \mathsf{answerDeterminedStop}(L)
}{\sem P\sqsubseteq\sem L}
\end{mathpar}
Fold/unfold fusion gives bag equality on exhaustion and answer equality at
an admissible stop. Rust totality is a premise, not a distinction between
pull and push; a panic violates the contract. This is an abstract emitter
obligation, not a claim that a source marker proves emitted Rust.
