\section{Local contracts and pass correspondence}
\label{sec:pass-contracts}
Write $\mathsf{WF}_L(s)\Downarrow A$ for successful local checking with analysis
$A$ (unit for checks returning no analysis). Write
$\mathsf{check}_f(s,t,\chi)\Downarrow\ok$ for the separately callable pass
correspondence check. These are executable structural checks. They do not
establish Rust expression semantics, representation laws, or equality of
arbitrary program meanings. Rules below summarize the predicates defined here;
each implementation rule is registered at the function that checks them.

\subsection{Language-local contracts}
\paragraph{CQ and CQ-NF.}
$\mathsf{CQScope}(s)$ consists of the CQ clause rules in
Section~\ref{sec:languages}, plus declaration and result checks: relation and
column names are unique and declared relations have positive arity;
declaration attributes are limited to at most one \code{index(...)} list; body atoms name declared inputs at the declared arity;
lets cannot shadow bound logical names; the body contains an atom; the head has
positive arity. A declaration named by the head is treated as the result and
must have its arity. Without that declaration, every head argument must be a
bound bare variable with a known, non-inference symbolic type. With a declared
result, these bare-head binding/type-inference requirements are not imposed.
Negation and aggregation parse but are rejected by CQ checking. Visible logical
uses are checked in written scope; opaque syntax remains Rust's responsibility.
\begin{mathpar}

\Rule{WF-CQ}{\mathsf{CQScope}(s)}{\mathsf{WF}_{CQ}(s)\Downarrow\ok}

\Rule{WF-NF}{\mathsf{WF}_{CQ}(s)\quad\text{each atom has distinct bare arguments}\\
 \text{an all-bare head has distinct arguments}}
 {\mathsf{WF}_{NF}(s)\Downarrow\ok}
\end{mathpar}
NF is a restriction of the same \code{cq::Program}, checked by
\code{normal::check}, not another Rust AST type. It does not restrict a computed
head to bare variables.

\paragraph{VO.}
$\mathsf{Schedule}(t,A)$ checks subatom relation, clause index, arity and original
column names. A dropped column must be unbound. It accumulates bound names,
newly introduced names per step, and per-clause variable coverage. Every atom
variable must eventually be covered. Ordinary guards occur in source guard order
excluding those
consumed once by reductions; lets occur in source let order and match their
source binding exactly. Guards reject visible free names that are unbound query
variables (atom or let names). Lets inspect the first lexically free name outside
the bound set and reject it when it is an atom variable. Neither check resolves
Rust names; these are the actual lexical tests, not a complete dependency proof. Every guard and let must be placed. A reduction precedes
its target's first subatom. A semijoin reduction names a different atom and
lists exactly its shared variables with the target; a guard reduction consumes
one matching source guard and may use no visible query variable outside the
target atom. This local guard check does not reject opacity; the reduction
\emph{pass} check does. VO does not require an acyclic reduction graph.
\[
\Rule{WF-VO}{\mathsf{WF}_{NF}(t.cq)\quad\mathsf{Schedule}(t,A)}
 {\mathsf{WF}_{VO}(t)\Downarrow A}.
\]

\paragraph{RA and IX.}
$\mathsf{RAHeading}(a,A)$ means the local operator rules in
Section~\ref{sec:languages}, valid declarations, fresh result names, earlier
operands, reachable definitions, visible expression-use checks, and a defined
output. An all-bare output has exactly its input heading; a computed output may
use a subset. Analysis carries bindings, symbolic types and computed-column
provenance, without Rust type unification. For IX let $D(a)$ be the set of exact
right-result/shared-heading descriptors demanded by its joins and semijoins.
\begin{mathpar}

\Rule{WF-RA}{\mathsf{RAHeading}(a,A)}{\mathsf{WF}_{RA}(a)\Downarrow A}

\Rule{WF-IX}{\mathsf{WF}_{RA}(t.ra)\quad\text{each index ends in a semicolon}\\
 \text{unique index names and descriptors}\quad\operatorname{descs}(t)\subseteq D(t.ra)\\
 \text{each descriptor names a result with strictly increasing in-range ordinals}}
 {\mathsf{WF}_{IX}(t)\Downarrow\ok}
\end{mathpar}
IX local validity permits partial demand coverage and arbitrary index names.
First-use ordering, complete coverage and \code{iN} names belong to the pass
correspondence rule below.

\paragraph{Physical.}
The program is standalone. $\mathsf{PHeading}(t,A)$ checks declarations and
unique results, earlier operands, total one-to-one renames, fresh extension
columns, subset projections, visible expression uses, defined output and
reachability. Probe/merge/semi keys are duplicate-free lists whose set is exactly
the operands' heading intersection; semi keeps the left heading, probe/merge
take the union. Range checks its column and condition scope but does not itself
prove an integer bound or ordered representation. Shared algebra operators
have their local heading effects. Analysis derives rows, source identifiers,
symbolic types, computed columns, hosts/renames, keyed/merge/range reads, scans,
recognized comparison conditions, modes and canon flags. Output expressions
reject visible unavailable attributes; an all-bare head's dependency set must
exactly equal the returned heading, while a computed head may use a subset.
Let $\mathsf{reads}(r)$ count operand occurrences and the return use.
\begin{mathpar}

\Rule{WF-Physical}{\mathsf{PHeading}(t,A)\quad\mathsf{PMode}(t,A)}
 {\mathsf{WF}_{Physical}(t)\Downarrow A}

\Rule{PH-Pipe}{\mathsf{mode}(r)=pipe\quad\mathsf{reads}(r)=1\\
 r\notin\dom A.key\_reads\quad r\notin\dom A.range\_reads}
 {\mathsf{PModeOK}(r)}

\Rule{PH-Let}{\mathsf{mode}(r)=let\quad\mathsf{reads}(r)>0}
 {\mathsf{PModeOK}(r)}

\Rule{PH-Alias}{\mathsf{mode}(r)=alias\quad\mathsf{operator}(r)=rename(R,m)}
 {\mathsf{PModeOK}(r)}
\end{mathpar}
$\mathsf{PMode}$ requires the applicable rule for every result. A merge-side
read can satisfy a pipe's single-use rule; its ordering premise is discharged
by Structures. Physical checks neither IX demand membership nor canonical
return evidence.

\paragraph{Structures.}
$\mathsf{Entries}(t,A)$ validates its embedded Physical and records exactly one
host entry per input, host key names from declared columns, canon facts, and
built entries over existing \code{let} results. Built columns are in the
heading and do not repeat across levels. Duplicate host entries and duplicate
built entries with the same concatenated level sequence are rejected. Host
key duplicates are not separately rejected by this local analysis; pass policy
validation is stricter. A built key answers the union of a prefix of its levels.
Define $\mathsf{host}(r,C)$ by translating $C$ through a rename and comparing
its sorted list with the host's sorted key list (without removing duplicates); $\mathsf{built}(r,C)$ by a matching
level prefix. Write $\mathsf{orderedHost}$ when the host also says ordered.
\begin{mathpar}

\Rule{STR-Key}{\mathsf{host}(r,C)\lor\mathsf{built}(r,C)}
 {\mathsf{answers}(r,C,probe/semi)}

\Rule{STR-Range}{\mathsf{orderedHost}(r,\{c\})\lor\mathsf{built}(r,\{c\})}
 {\mathsf{answers}(r,\{c\},range)}

\Rule{STR-Merge}{\mathsf{orderedHost}(r,C)\lor\mathsf{built}(r,C)\\
 \text{or }(\mathsf{mode}(r)=pipe\land\mathsf{operator}(r)=merge[C](l,s))}
 {\mathsf{answers}(r,C,merge)}

\Rule{WF-Structures}{\mathsf{Entries}(t,A)\quad\text{all Physical reads answered}\\
 \mathsf{unique}(t.returned)\text{ inferred}}
 {\mathsf{WF}_{Structures}(t)\Downarrow A}
\end{mathpar}
The uniqueness inference starts Unit at the empty key, and a Rename at its full
heading when its host is canon or it has a full-key build. Join requires both
input keys and unions them; semi keeps the left key; select/range/extend keep
the input key; project keeps it only when no key column is dropped. If no key
is inherited, a canon flag or full-key build supplies the full heading as key.
The return must have a key. These are symbolic premises: a built type accepted
here must still implement the appropriate ordered, membership, construction or
canonical trait in generated Rust. Trait laws and host canon/order claims are
representation assumptions, not established by syntactic analysis.

\subsection{Pass correspondence checks}
Each complete pass check requires successful local checks of its source
and target; equalities are the AST equalities used by the code, unless a rule
explicitly compares normalized names or descriptors. These checks do not call
\code{compile} to compare its output.

\paragraph{Ordering.}
Define $\mathsf{OrderObligations}(s,t,\chi)$ as: unchanged CQ; no reductions;
at least one subatom per atom clause; Coarse has
exactly one full subatom per atom; Fine introduces at most one new variable per
subatom. Under Written, introducing subatom indices are nondecreasing (all
Coarse subatoms count; in Fine only those introducing a name count).
Ordinary guard/let placement is constrained by VO, not exact Written expansion.
Prefix and Elimination rankings are construction choices checked by fixtures,
not correspondence obligations.
\[
\Rule{CK-Order}{\mathsf{WF}_{NF}(s)\quad\mathsf{WF}_{VO}(t)\\
 \mathsf{OrderObligations}(s,t,\chi)}
 {\mathsf{check}_{order}(s,t,\chi)\Downarrow\ok}.
\]

\paragraph{Reduction.}
$\mathsf{ReduceObligations}$ requires a reduction-free source, unchanged CQ,
and equality of surviving target steps with source steps after removing one
matching ordinary guard per pushed guard. Under guards=None, no guard reduction
is allowed. Under Atoms, each pushed guard is nonopaque and all its free names
belong to its chosen atom; the checker does not require pushing every eligible
guard or choosing the earliest host. Under semijoins=None, no semijoin reduction
is allowed. Under Tree, the source must be acyclic, each directed GYO tree edge
occurs exactly once, all upward edges precede all downward edges, children
precede their parent's upward edge and parents precede their children's downward
edges. Sibling orders need not be BFS. The local VO check supplies shared-key
and before-first-subatom constraints; the checker adds no requirement that
pushed guards precede every tree reduction.
\[
\Rule{CK-Reduce}{\mathsf{WF}_{VO}(s)\quad\mathsf{WF}_{VO}(t)\\
 \mathsf{ReduceObligations}(s,t,\chi)}
 {\mathsf{check}_{reduce}(s,t,\chi)\Downarrow\ok}.
\]

\paragraph{Elaboration.}
Erasure reconstructs atoms from RA renames, guards from selects and bindings
from extends; structural join, semijoin, project and Unit definitions contribute
no items. Duplicate identical atom reconstructions are suppressed. Matching
items are ordered by the separately supplied CQ source body; remaining items
follow definition order. It clones that source program with reconstructed body
and RA head, then compares \code{normal::Kernel} values (atom/guard/let vectors
and head tokens with variable renaming).
\[
\Rule{CK-Elaborate}{\mathsf{WF}_{VO}(s)\quad\mathsf{WF}_{RA}(t)\\
 t.declarations=s.cq.declarations\quad t.head=s.cq.head\\
 \mathsf{kernel}(t,s.cq)=\mathsf{Kernel}(s.cq)}
 {\mathsf{check}_{elaborate}(s,t,())\Downarrow\ok}.
\]
This is the implemented structural criterion, not a complete semantic-equivalence
procedure or an exact RA-shape comparison.

\paragraph{Index demands.}
The independent checker traverses RA definitions using IX-Join, IX-Other,
IX-New and IX-Reuse. It requires the next first-use descriptor at the next target position and its
normalized name \code{iN}; extra entries are rejected.
\[
\Rule{CK-Index}{\mathsf{WF}_{RA}(s)\quad\mathsf{WF}_{IX}(t)\quad t.ra=s\\
 t.indexes=[i_n=d_n]_{n=0}^{k-1}\text{ from first-use derivation}}
 {\mathsf{check}_{index}(s,t,())\Downarrow\ok}.
\]

\paragraph{Physical lowering.}
Erase probe/merge to natural join, semi to semijoin, range to select, and remove
modes/canon flags, preserving definitions, names, declarations and output.
$\mathsf{PolicyPhysical}(t,\chi)$ requires exactly the declared input host names
in the policy, with unique valid key columns. A join is merge iff merge policy
is set and its shared heading is nonempty; otherwise it is probe. A range must
rename a host with a single ordered key matching its range column and have a
recognized usable integer bound among conjunction leaves. Bounds are recognized
by the comparison parser, excluding inequality and strict bounds that overflow
\code{i32}; an eligible select is not required to become a range.
Aliases must answer every keyed/range/merge read from policy host facts, ordered
where required. Let/pipe choices may differ from construction when locally valid.
Canon may appear only at return or a project=canon projection; that policy
requires canon on key-dropping projections. The return must be unique by the
policy key inference or a canon flag. This inference uses Unit, canon hosts,
join key unions, left keys for semi, preservation through select/range/extend,
and key-preserving project. It does not consult built structures.
\begin{mathpar}

\Rule{CK-Demands}{\mathsf{WF}_{Physical}(t)\quad\forall\,probe[C](l,r),semi[C](l,r)\text{ in }t.\\
 (r,\operatorname{ordinals}_{H(r)}(C))\in\operatorname{descs}(s)}
 {\mathsf{demands}(s,t)\Downarrow\ok}

\Rule{CK-Physical}{\mathsf{WF}_{IX}(s)\quad\mathsf{WF}_{Physical}(t)\\
 \mathsf{erase}(t)=s.ra\quad\mathsf{demands}(s,t)\quad\mathsf{PolicyPhysical}(t,\chi)}
 {\mathsf{check}_{physical}(s,t,\chi)\Downarrow\ok}
\end{mathpar}
Demand membership concerns probe/semi right operands only; merge/range have
separate policy/representation premises. No missing IX demand is synthesized.
The checker does not require the constructor's particular materialization
choices and does not use \code{semijoin = prefer_lazy}.

\paragraph{Structure selection.}
$\mathsf{StorageRules}(s,t,\chi)$ first requires exactly the policy host facts,
including written host-key tuple order and canon/order flags, and unchanged
Physical. Independently collect unanswered reads per exact result and key,
with strength membership $<$ payload $<$ ordered. Host keys discharge exact
reads; merge-sorted pipes discharge their matching merge reads. Advice
\code{#[index(T)]} on a renamed input fixes each built type to $T$ and requires
one level per entry. Without advice, defaults are \code{HashSet<_>},
\code{cq_storage::HashIndex<_, _>}, and \code{BTreeMap<_, Vec<_>>} by strength.

Without advice, strict inclusion chains with membership at each nonmaximal
key and no ordered maximal read require one curried Trie, its levels the
successive key differences. The independent check allows an empty first key;
the constructor's chain builder additionally requires that first key to be
nonempty. Correspondence checking remains separate from construction. Under intersect=smallest the checker independently
recognizes adjacent pipe probe/check pairs whose intermediate result is not
flagged canon and whose second left operand is that intermediate result.
One new variable completes both candidate headings; both prefixes are nonempty,
the sides are materialized, and there is no advice
or host-answered key reads, and only compatible prefix/full unordered demands.
It adds prefix/full membership demands and requires two levels. Conflicting
prefix choices are excluded. Each extra level wraps the leaf default in
\code{cq_storage::Trie<'_, _, T>}.
Every built prefix must discharge an unanswered demand exactly once; missing,
extra, duplicate, wrong-level and wrong-type builds fail. Entry order is free;
comparison is against these obligations, not the selector's token stream.
\[
\Rule{CK-Structures}{\mathsf{WF}_{Physical}(s)\quad\mathsf{WF}_{Structures}(t)\\
 t.physical=s\quad\mathsf{StorageRules}(s,t,\chi)}
 {\mathsf{check}_{structures}(s,t,\chi)\Downarrow\ok}.
\]

\subsection{Realization evidence}
\code{cq-physical-realization} checks its Structures input and prints a
\code{syn::Expr}; it has no source/target \code{check} and no independent Rust
semantic checker. Its evidence consists of independent answer oracles, rustc
trait guards at generated uses, and authored expansion fixtures
(Section~\ref{sec:evaluation}). The optional binary intersection path chooses
between candidate sets using runtime counts without reordering the RA/VO plan.
Rows borrow host/built fields, computed columns remain owned, and host lookups
clone owned key values; distinct providers may clone retained rows. A block
with bound storage collects answers before returning \code{Vec::into_iter};
a block without bound statements may return the lazy iterator. This evidence
supports the exercised cases, not an arbitrary Rust equivalence theorem.
