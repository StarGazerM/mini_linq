\section{Replacing compiler components}
\label{sec:extensibility}
Replacements satisfy the source judgment, domain, target and preservation
contracts of Theorem~\ref{thm:composition}. A replaceable implementation owns its
admitted domain, lowering, configuration and independent source-to-target checks.
A resource implementation owns construction and all operations interpreting that
representation. Multiple macro aliases can select the same implementation with
different continuations; they need not introduce separate packages.
A checker never calls its emitter. \code{cq-compose} owns default selection;
explicit implementations do not import that selector.

Compiler families are isolated by semantic boundary: planning, equality demands,
whole-query realization, native operation expansion, Access execution and Pipeline
endpoints. Implementations depend on shared syntax without calling a universal
strategy dispatcher. Storage contains data structures and minimal operation traits;
composition and the procedural-macro frontend wire implementations together.
Route-specific analysis stays with its consumer. Feature-closure and source-removal
probes test actual build dependencies, while external macro consumers test lexical
replacement. Ordinary package tests cover supported feature selections and target
prerequisites. Neither package isolation nor successful feature resolution proves
semantic substitution; the source snapshot records which gates completed.

\paragraph{Representations and algorithms.}
Ascent BYODS formalizes custom representations through DLDS and
concretization into facts~\cite{paper-byods}. Here a represented relation
$\gamma(s)$ must also satisfy the operations required by its chosen pass.
For key sort $K\subseteq U$ and key tuple $u$, exact lookup requires
\[
 \set(\operatorname{lookup}_K(s,u))
 =\{t\restrict(U\setminus K):t\in\gamma(s),\ t\restrict K=u\}.
\]
Membership agrees with nonemptiness; scans enumerate $\gamma(s)$.
Induction over the finite plan then preserves its completed pure answer
when providers satisfy these laws and the host assumptions. Sorted access
additionally needs order and seek laws. Rust trait signatures alone do not
establish these premises, and changing input meaning, such as adding an
equivalence closure, changes the source contract.

\paragraph{Push and multiway execution.}
The implemented \code{push_set!} lowers Access directly to nested loops and one
result set (PS-*), without a Pipeline intermediate. It can replace a set-valued
Access continuation when completed-set observations agree. A public lazy Iterator
requires an implementation preserving its demand and stopping contract
(Section~\ref{sec:scope})~\cite{paper-pushpull}.
A WCOJ pass must retain a complete positive join region before committing
to binary intermediates, then supply variable-prefix restriction and
intersection operations. Current index requirements describe equality keys,
not trie order or seek; using Leapfrog Triejoin would require those
additional laws and its own complexity argument~\cite{paper-lftj}.
Neither replacing a hash table alone nor treating a host function as an
enumerable relation establishes that algorithm.

\paragraph{Staging and quotation.}
Compilation specializes query structure; rows and host values remain residual.
Direct RA/Index/Access/Pipeline entries and local quotations retain binding,
typing and context contracts without reconstructing CQ
(Section~\ref{sec:constraint-planning}). The physical supplement gives rules and
algorithms for direct RA-to-Access lowering, with independent key, candidate-scan
and complete pair-production operations. Row providers own construction and access;
lexical macros select
local refinements. Generated operations use ordinary Rust data types and traits.

\paragraph{Extractable teaching implementations.}
The YA release profile selects graph planning, named-result indexes, exact
materialized access, pull and collection. Its generated inventory separates the
two-sweep scheduler from semijoin-to-Access lowering; independent administrative
and target checks remain supplied. Verification checks the foundation with both
exercise algorithms absent and each expected failure separately, then compiles
and executes the temporary reference implementations. The delivered files have
the student stubs restored and their inventory hashes checked. Unselected native,
block, prefix and configured-relation implementations are physically absent.
This exercises an actual source boundary without establishing arbitrary provider
laws. Triejoin and recursive program semantics remain separate design obligations.
