\section{Pass contracts and acceptance}
\label{sec:research-contract}
Each language has syntax, a well-formedness judgment and a meaning independent
of the pass producing it. For a selected implementation $f$, require
\[
 \mathsf{WF}_L(s)\land\mathsf{Domain}_f(s,\chi)
 \quad\Longrightarrow\quad
 f(s,\chi)=t\ \land\ \mathsf{WF}_M(t)
 \ \land\ \alpha(\sem t_M)=\sem s_L.
\]
$\chi$ is explicit configuration and $\alpha$ relates the target observation
to the source meaning. An unmet domain premise must be diagnosed. A pass must
follow the stated boundary: physical lowering derives operands from RA and
checks their demands in IX; it cannot invent a missing demand or substitute
a different RA version.

\paragraph{Open physical configuration.}
The post-IX passes take explicit configuration $\chi$ from the caller: a
query-independent policy stating host facts (the key a host value is stored
under, whether that key is ordered, whether the value is canonical) and
strategy (merge or probe joins, semijoin preference), plus \texttt{\#[index(Type)]}
advice naming the Rust type built over a relation when the plan indexes it.
Neither pass reselects a choice recorded by the previous one. Whether a value
implements the operation trait each read needs is Rust's check at a guard the
printer emits beside the value; those trait laws are stated in
\path{runtime/cq-storage/src/lib.rs} and checked by its representation tests.

\paragraph{Residual syntax and ownership.}
An expansion can return $C[h_1,\ldots,h_n]$, an ordinary Rust context containing
lower-language quotations. Each hole records a remaining compilation task.
The printed program borrows from hosts and built structures and copies no
binding; an owned computed value crossing a join is a Rust move error. Rust
type checking alone does not establish the representation laws.

\paragraph{Three independent checks.}
Acceptance requires
\[
 \mathsf{RuleDerivation}(s,t)\ \land\
 \mathsf{ExpectedExpansion}(s,t)\ \land\
 \mathsf{SemanticAgreement}(s,t).
\]
The first checks compilation premises and conclusions. The second compares
each actual macro output with its authored boundary fixture, ignoring only
whitespace and source spans. The third checks representation laws and answers
with independent oracles. Equal answers cannot compensate for hardcoded dispatch,
reselection in a later pass or an omitted boundary. Fixtures are revised
through design review, never regenerated merely to bless changed output.

\paragraph{Observation and status.}
RA denotes sets. Physical enumeration may contain multiple witnesses; its
consumer must implement the requested observation. Pure completed answers do
not establish equal partial-consumption, callback or destructor traces. Host
quotation requires binding, typing and lifetime preservation and the assumptions
of Section~\ref{sec:scope}. Push/pull placement remains unspecified.
Section~\ref{sec:evaluation} lists the evidence for the implemented chain.
Documentation checks alone do not establish the runtime trait laws.
