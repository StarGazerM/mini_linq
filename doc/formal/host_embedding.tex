\subsection{Native Rust and logical dependencies}
\label{sec:host-embedding}
\label{sec:hostobjects}
CQ clauses use derived parsing; expressions, patterns and types delegate to
\code{syn::Expr}, \code{syn::Pat}, and \code{syn::Type}. Blocks, closures,
qualified paths and macros retain native Rust syntax. Macro bodies remain
opaque token trees~\cite{host-synmacro}; parsing does not establish resolution,
typing or purity.

Let $\Gamma_Q$ describe logical types and representation modes,
$\Gamma_H$ the host bindings, and $\rho\approx_{\Gamma_Q}\nu$ mean that
Rust bindings represent valuation $\nu$. The host boundary is
\[
\Rule{H-Eval}
 {\Gamma_H;\Gamma_Q\vdash_H e:\tau\quad \rho\approx_{\Gamma_Q}\nu\quad
  \langle e,\rho,\sigma\rangle\Downarrow_H(v,\sigma',\alpha)}
 {\langle\mathsf{host}[e],\nu,\rho,\sigma\rangle
  \Downarrow(v,\sigma',\alpha)}.
\]
Rustc checks the elaborated host context. Under $\mathcal H_{\rm rel}$,
this boundary induces the function used by Select and Extend.

The lexical helper in \path{languages/cq-syntax/src/rust.rs} returns free simple value names
$F$ and opacity bit $o$, before Rust name resolution. It threads binding
scopes: in \code{|x| x + y}, only $y$ is free. Given available logical names
$B$, dependencies are $F\cap B$, or all of $B$ when opaque. Diagnostic
\code{known_uses} returns $F\cap Q$ for all logical names $Q$, or the empty
set when opaque. Thus \code{accept(x)} normally requires logical $x$;
\code{accept!(x)} conservatively retains every available logical binding.
Opacity supplies no missing future binding. The precise FV rules follow in
Section~\ref{sec:languages}.

\label{sec:hostmovement}
Matching separates symmetric equalities from directional computation.
In $R(x,y),S(y,z)$ either atom can supply $y$. A preceding
$\mathsf{let}\ y=e$ must instead compute $y$ before $S(y,z)$ matches it.
A new bare argument binds, a repeated name constrains equality, and
\code{_} retains an unnamed witness. Computed arguments require their free
logical inputs: \code{S(f(k),z)} needs an available $k$, while
\code{S(k,f(k))} can obtain $k$ from a candidate row and test the second
position afterward. A-Prefix/A-Local normalize these dependencies into CQ
bindings and guards; C-Ready schedules their inputs separately.

Free variables alone do not justify changing callback counts. For
$R=\{(1,10),(1,20)\}$, set-projecting \code{R(x,witness)} to $x$ before
\code{let y = tick(x)} changes two calls to one. Coarse elaboration retains
witness columns until its final projection; Fine can project partial subatoms.
Neither establishes arbitrary effect-trace equivalence. Argument scope also
differs from execution order: in \code{R(x,f(x),g())}, A-Prefix places a
$g()$ binding before the atom and A-Local places the $f(x)$ guard after it. The \code{argument_placement}
example checks VO equality and RA operator positions: the $g$ binding precedes
matching and the $f$ guard follows binding $x$. It executes no generated Rust. An atom is a matching
construct; its runtime schedule is determined by the generated operators.
