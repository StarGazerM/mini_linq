\section{Index selection and physical realization}
\label{sec:physical}
\subsection{Exact index-selection judgments}
For sorts $V=\Delta(l).V$ and $W=\Delta(r).V$, define
\[
\begin{aligned}
\operatorname{reskey}(l,r)&=\langle j\mid\ord(W)_j\in V\rangle,\\
\operatorname{basekey}(l,R,m)&=\langle j\mid m(\Sigma(R)_j.a)\in V\rangle.
\end{aligned}
\]
Keys follow increasing ordinals. $K\oplus\kappa$ appends a nonempty unseen
signature, preserving first-use order. Fold definitions using:
\begin{mathpar}

\Rule{IX-Result}{o=l\bowtie r\ \lor\ o=l\ltimes r\quad
 \kappa=(\mathsf{result},r,\operatorname{reskey}(l,r))}
 {(r_0=o,K)\Rightarrow_{\rm ix}K\oplus\kappa}

\Rule{IX-Other}{o\notin\{\text{Join},\text{Semijoin}\}}
 {(r_0=o,K)\Rightarrow_{\rm ix}K}

\Rule{IX-Base}{o=l\bowtie r\quad D(r)=\delta_m(R)\quad
 \kappa=(\mathsf{base},R,\operatorname{basekey}(l,R,m))}
 {(r_0=o,K)\Rightarrow_{\rm base}K\oplus\kappa}

\Rule{IX-Module}{\Sigma;\Delta\vdash(D,\emptyseq)\Rightarrow_{\rm ix}K}
 {\Sigma\vdash D\Downarrow_{\rm result}(D,K)}
\end{mathpar}
IX-Base folds actual join order on a root Rename, left-deep joins with direct
right Renames, and final Project. Both algorithms preserve every definition.
The default entry selects result indexes for extended linear RA; the planned
entry supports general DAGs. Selection returns exactly the stable required
list; physical backends also accept valid extras. Coverage requires the exact
right result version, including reduced/projected versions.
\begin{theorem}[Index selection]
Both selection algorithms preserve the entire RA and hence its denotation.
Their output satisfies IX-WF and contains exactly one signature for each
nonempty key required in their respective domains, ordered by first use.
\end{theorem}
\begin{proof}
Induct on definitions. Checked layouts give increasing in-range ordinals;
each binary step appends its nonempty unseen signature, preserving uniqueness
and first use. Every consumer is visited and $D$ is copied unchanged.
\end{proof}

\subsection{Storage representation relation}
Let $\operatorname{row}_V(t)=\langle t(x)\mid x\in\ord(V)\rangle$.
For base rows use schema order instead. A Rust row set $S\simeq_V L$ means
its abstract rows are exactly $\{\operatorname{row}_V(t)\mid t\in L\}$.
For key positions $k$ and complementary positions $p$, an index is either
\[
 \operatorname{KeySet}_k(L)=\{\operatorname{row}(t)|_k\mid t\in L\},
 \quad
 \operatorname{Buckets}_k(L)[u]
 =\langle\operatorname{row}(t)|_p\mid t\in L,\operatorname{row}(t)|_k=u\rangle.
\]
Each represented row contributes its complementary payload once, in fixed
construction order; missing keys give empty buckets. KeySet is a HashSet;
Buckets a HashMap to payload vectors. Complements retain layout order;
singleton Rust tuples retain commas and the empty tuple is $()$.
\begin{mathpar}

\Rule{ST-Key}{S\simeq_V L}
 {\mathsf{collectSet}(\mathsf{map}(\operatorname{cloneKey}_k,S))
 \simeq\operatorname{KeySet}_k(L)}

\Rule{ST-Bucket}{S\simeq_V L}
 {\mathsf{foldPush}(S,k,p)\simeq\operatorname{Buckets}_k(L)}
\end{mathpar}
foldPush visits stored rows once, appending each complement at its key.
Induction on those visits proves ST-* under lawful cloning/equality.
Materialized indexes need payload iff a natural-join consumer adds a fresh
right attribute; other consumers use membership, sharing Buckets if necessary.
Lazy proper keys always use Buckets; full keys use KeySet.
\subsection{Access constructors, defined independently of the emitters}
Abbreviate Access fragments by $\mathsf{for}_N(e)$ and $\mathsf{if}(e)$,
retaining their positive/binding and guard labels. For represented $S:V$,
$\operatorname{scan}(S,V)$ is $\mathsf{for}_{\ord V}(S.\mathsf{iter}())$
when $V\ne\emptyset$, otherwise $\mathsf{if}(\neg S.\mathsf{isEmpty}())$.
Lookup uses $S.\mathsf{iter}()$ for empty keys, otherwise
$\mathsf{Buckets}_k(S).\mathsf{get}(u).\mathsf{intoIter}().\mathsf{flatten}()$.
Existence is nonemptiness for empty keys, KeySet contains for key sets, and
Buckets contains-key otherwise. Lookup binds complement columns; left bindings
form keys in right-key order. Output uses result-sort order.
\begin{lemma}[Lookup and membership adequacy]
For $t:V$, $L:W$, and $K=V\cap W$, exists returns true iff $t$ has a compatible
witness in $L$. If $W\setminus V\ne\emptyset$, lookup enumerates exactly the
complementary tuples of those witnesses, each once.
\end{lemma}
\begin{proof}
Empty keys admit all rows. Otherwise key equality is agreement on $V\cap W$.
ST-Key decides existence; ST-Bucket enumerates exactly its witnesses' payloads.
Key and complement reconstruct each row uniquely, including the fully-bound
case with at most one compatible tuple.
\end{proof}

\subsection{Materialized IndexedRA to staged Rust}
Write $s_r=\operatorname{scan}(\mathcal S(r),\Delta(r).V)$,
$h_V=\mathsf{out}_V$, and $e_V=\operatorname{host}_V(e)$
(Section~\ref{sec:host-elab}); these abbreviate existing Access syntax.
Outputs clone/bind values in $\ord(V)$. With implicit checked environments
$\Sigma;\Delta;\mathcal S$, the operator rules are:
\begin{mathpar}
\Rule{M-Unit}{}{\mathbf1\Downarrow_M[\mathsf{unit}()\Rightarrow\mathsf{if}\ \mathsf{true};h_\emptyset]}

\Rule{M-Rename}{\Sigma(R)=\bar a:\bar\tau\quad m(\bar a)=\bar x}
 {\delta_m(R)\Downarrow_M[\operatorname{scan}(\mathcal S(R),\bar x);h_{\set(\bar x)}]}

\Rule{M-Project}{V=\Delta(r).V\quad U\subseteq V}
 {\pi_Ur\Downarrow_M[s_r;h_U]}

\Rule{M-Select}{V=\Delta(r).V}
 {\sigma_er\Downarrow_M[s_r;\mathsf{if}(e_V);h_V]}

\Rule{M-Extend}{V=\Delta(r).V\quad N\cap V=\emptyset}
 {\operatorname{ext}_{N,e}r\Downarrow_M[s_r;\mathsf{for}_N(\mathsf{once}(e_V));h_{V\cup N}]}
\end{mathpar}
Rename scans schema order and outputs result order. Extend owns new fields,
cloning old ones as needed; its Let label uses AC-Bind even for empty $N$,
evaluating $e$ once per input tuple. For binary operators let
$V=\Delta(l).V$, $W=\Delta(r).V$, $K=V\cap W$, $N=W\setminus V$,
$u=\operatorname{row}_K(t)$, $J=\operatorname{lookup}(\mathcal S(r),K,u)$,
and $E=\operatorname{exists}(\mathcal S(r),K,u)$:
\begin{mathpar}
\Rule{M-JoinFor}{N\ne\emptyset}
 {l\bowtie r\Downarrow_M[s_l;\mathsf{for}_N(J);h_{V\cup W}]}

\Rule{M-JoinIf}{N=\emptyset}
 {l\bowtie r\Downarrow_M[s_l;\mathsf{if}(E);h_V]}

\Rule{M-Semi}{}{l\ltimes r\Downarrow_M[s_l;\mathsf{if}(E);h_V]}
\end{mathpar}
Pull adds Project/Distinct to each region; its sources, patterns, and clones
are already Rust. Join-output/semijoin-probe statistics are excluded from set
observations. File state $(S,\mathcal S)$ contains statements and store names.
Normalize inputs and build extra base indexes first. Let $t_r(A)$ be
$\mathsf{let}\ S_r:\mathsf{HashSet}(\operatorname{Row}_{\Delta(r).V})
=\mathsf{collect}(\mathsf{pull}\{A\})$, followed by buildIndexes($r$).
\[
\Rule{M-Def}{\Sigma;\Delta;\mathcal S\vdash o\Downarrow_M A\quad r\text{ fresh in }\mathcal S}
 {(S,\mathcal S,r=o)\Rightarrow_M(S\concat t_r(A),\mathcal S[r\mapsto S_r])}.
\]
buildIndexes applies ST-* to requirements targeting $r$ after $S_r$ exists.
Shared results are defined once. Build finally maps the head into an answer
HashSet; query clones its rows, materialize collects/sorts, and run composes
build/materialize. None re-plans CQ.
The domain requires IX-WF, required-key coverage, at most twelve attributes
per result, and nameable outputs; successful Rust elaboration is additional.
\begin{theorem}[Materialized representation preservation]
Under $\mathcal H_{\rm rel}$ and adequate host expression elaboration, the
abstract M-rules produce a store representing every named RA result and an
answer representing the RA output.
\end{theorem}
\begin{proof}
Induct on definitions. Normalized inputs represent $I$. Unit yields the empty
tuple singleton; Rename relabels; Project/Distinct implements restriction; Select/Extend applies the
specified host function. Lookup adequacy proves both join cases and Semi.
Cursor preservation (Section~\ref{sec:cursor}) and collection establish each
result set; ST-* establishes its indexes. Earlier operands, including shared
versions, remain available without recomputation. Final head mapping and set
collection give the RA output.
\end{proof}

\paragraph{A further physical realization.}
The design supplement, \href{physical_design.pdf}{\emph{YA-Aware
Physical Administration}}, specifies one backend family with versioned resources
and immutable row-ID selections. Each YA edge becomes Build, Attach,
Reduce: construct source-key providers, bind conservative filters to this
consumer's scan, then probe exact membership before keeping left IDs.
Bloom filters reject rows; dynamic key bounds and block zone maps can reject
whole blocks. Projection still deduplicates into a new arena.
A separate Transfer mode omits sweep probes and preserves
$\pi_{X_i}(\bowtie_j L_j)\subseteq C_i\subseteq L_i$, requiring exact final
assembly. It cannot claim Y-Freeze's full reduction. The supplement gives
named rules, matching algorithms, provider/evidence contracts and Rust
compilation records; production implementation remains future work.

\subsection{Lazy linear lowering and the basic storage algorithm}
The lazy domain follows RA dataflow: Unit/Rename starts current $p$; other
Renames become pending. Join consumes $p$ and a pending direct Rename;
Select/Extend consumes $p$; final Project consumes $p$ after all pending
Renames. Semijoin, bushy operands, internal Project, and later operations are
excluded. Requirements target direct Renames; empty Extend uses AC-Bind.
Build stores renamed rows in lexical attribute order and builds indexes,
without evaluating Select/Extend/head leaves. Query folds:
\begin{mathpar}

\Rule{L-Root}{p=\bot\quad o=\delta_m(R)}{(p,A,o)\Rightarrow_L(r,[\operatorname{scan}(S_r,V_r)])}

\Rule{L-Unit}{p=\bot\quad o=\mathbf1}{(p,A,o)\Rightarrow_L(r,[\mathsf{unit}()\Rightarrow\mathsf{if}\ \mathsf{true}])}

\Rule{L-Join}{o=p\bowtie r\quad r\text{ pending direct Rename}}
 {(p,A,o)\Rightarrow_L(r_0,A\concat\operatorname{joinAccess}(p,r))}

\Rule{L-Select}{o=\sigma_ep}{(p,A,o)\Rightarrow_L(r_0,A\concat[\mathsf{if}(\operatorname{host}(e))])}

\Rule{L-Extend}{o=\operatorname{ext}_{N,e}p}
 {(p,A,o)\Rightarrow_L(r_0,A\concat[\mathsf{for}_N(\mathsf{once}(\operatorname{host}(e)))])}

\Rule{L-Output}{o=\pi_Up\text{ is final}\quad\text{all pending Renames consumed}}
 {(p,A,o)\Rightarrow_L[\mathsf{head}_U\Rightarrow\operatorname{host}(\bar e);A]}
\end{mathpar}
$r_0$ names the current definition. Nonroot Renames only update pending.
joinAccess uses M-JoinFor/If against stored inputs without materialization;
Output adds one head map and Distinct.
\begin{lemma}[Pure fusion]
On this linear domain under $\mathcal H_{\rm rel}$, the lazy rule result set
equals the materialized RA result set.
\end{lemma}
\begin{proof}
Scans and Unit have unique tuples. Equal Join unions have equal left/right
restrictions, hence arise from the same pair. Select cannot duplicate; Extend
retains the input, so cannot identify distinct bindings. Induction gives the
same complete relation before final Project. Since pure heads depend only on
kept attributes, deduplication before or after head mapping yields the same
set. Stateful interleavings need not agree (Counterexample~\ref{cx:effects}).
\end{proof}

R1 uses the same access cases over schema-ordered base rows and base indexes.
Inputs are normalized to HashSets. Empty-key scans reuse a full-key set or a
first-use-numbered row vector; proper indexes store complementary vectors.
One final consumer owns each normalized input: a full index, else a needed
row vector, else the last proper index. Other builders borrow/clone first.
ST-* proves the representations; Rust must validate this ownership schedule.
\subsection{Host expression elaboration}
\label{sec:host-elab}
$\operatorname{host}_V(e)$ makes primitive comparisons explicit (reference
comparisons for lazy execution). General expressions alias scanned values to
borrowed fields and computed values to owned clones. Simple paths retain their
identifiers/contexts; opaque macros get aliases for retained names at their
path span. Other Rust expression and macro subtrees are preserved.
\begin{obligation}[Host adequacy, not proved by FV]
For every claimed admissible expression and related stored binding, the
elaborated expression resolves to the intended logical environment, has the
promised Rust type, and yields a representation of $\bar e$.
The comparison-recognition case and the alias-introduction case both require
this obligation. Lexical liveness and successful AST parsing alone do not
establish it; macro hygiene and ownership are not erased from the obligation.
\end{obligation}
