Compiler audit snapshot — 17 September 2026

Scope
The borrowed execution experiment now composes the existing stage APIs:
CQ -> RA -> IndexRequirements -> Rust[Access, Native] -> Rust[Pipeline, Native] -> Rust.
Rust[...] denotes ordinary Rust containing macro invocations, not a new IR.
The old direct relational-to-iterator/loop implementations and their test/document
entry points were deleted without compatibility aliases. Existing hash and
configured-relation implementations retain their declared domains and APIs.

The no-index policy preserves checked RA and writes an empty overlay. Borrowed
scan lowering consumes IX and rejects nonempty demands, Select, Extend and
computed outputs. Each admitted RA definition becomes a checked Access region.
Access now admits an empty body for Unit and a simple identifier for exactly
one fresh variable. Intermediate support, existential consumption and final
answers use the same Access-to-Pipeline compiler with separate endpoint choices.

Shared/restarted definitions use Native Build/Scan. Replay privately owns one
source, a demanded prefix and independent cursor positions. Generated code uses
BuildReplay and ReplayRead; storage contains no relational operator or compiler
dispatch. Field payloads remain borrowed. Construction performs no input scan
or field read; existence stops at its first witness. Prefix retention can grow
to full inputs, comparisons remain nested, and replay uses non-Send Rc state.
These are finite stable pure-value guarantees, not effect or performance claims.

Actual expansion evidence
The current capture is target/staged-execution-review. It records 58 actual
procedural-macro input/output pairs for one Star query, with 699 copied source
fingerprints unchanged during capture. The recorder returns original token
streams without reparsing. The unchanged example compiles and runs against an
independent oracle. Full inputs and immediate outputs are in steps.md; raw
files, invocation index, command, instrumentation patch and verification are
retained beside it. review.md annotates all 58 calls, with every non-root call
matched to a direct invocation in its captured parent output. Declarative macros
are traced in a separate compilation.

The first three actual calls are graph_query, no_indexes and borrowed_scans.
Later calls include ten pull_stream/stream_pipeline pairs, four
pull_exists/exists_pipeline pairs, one pull/iterator_pipeline pair, fourteen
replay operations and eleven input-provider operations. Only the physical pass
resolves RA definitions; Access and Pipeline lowering remain real selected
macro invocations. Invocation order is not runtime evaluation order.
Older expansion directories are historical and do not describe this revision.

Naming audit
The post-implementation audit in doc/NAME-AUDIT.md covers crate responsibilities,
implementation modules, all 44 exported procedural macros and caller-bound
paths. It proposes names without renaming APIs. CQ planning is part of CQ-to-RA
lowering; index demand selection is a policy; Access/Pipeline/Native libraries
are compiler transformations; storage is runtime data. Existing RA/IX input
asymmetry, push/pull targets, partial Native domains and absent planning feedback
are recorded separately because naming changes cannot repair those contracts.
