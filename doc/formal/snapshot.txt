Revision: Macro-family ownership and Cargo feature testing, 15 September 2026.

Architecture: CQ -> RA -> IndexRequirements -> Rust[Access] -> Rust[Pipeline] -> Rust, with a separate configured direct RA -> Rust[Access] edge. Eleven compiler/storage packages comprise seven implementation families, IR and storage foundations, composition, and the procedural-macro frontend. An implementation module owns its algorithm, domain, configuration, checks and tests. No context IR, route tag, capability registry or runtime relational interpreter was introduced.

Ownership: cq-plan contains canonical/prefix/graph; cq-index contains input/result; cq-physical contains input/lazy/materialized/direct. cq-access owns candidate, key-resource and witness-resource alternatives; cq-providers owns hash/sorted/block representation protocols. cq-pull owns Access lowering; cq-pipeline owns iterator/collect/stream endpoints. Each family depends only on cq-ir among local packages. Physical access/domain/check helpers are private to their consuming family. Only neutral heading and namespace-preserving index-signature facts moved into the existing IR. The former individual algorithm and helper crates are removed, without compatibility re-exports.

Composition: cq-compose::with_default_indexes makes one RA-dependent choice of index policy and physical continuation. Macro and typed complete-program composition share that decision. Emitted IX carries the caller-selected continuation through a native macro invocation, not a serialized choice. Explicit index entries retain caller aliases; independently authored IX selects an explicit physical entry. The old automatic index_requirements macro is removed. The replacement Access test executes five explicit routes plus the default on 256 finite databases and duplicate-input variants, checking exact answers and 1536 uses of the replacement Access continuation.

Native bindings: scan requires no unrelated configuration; exact membership does not require a construction iterator; native hash/sorted materialization does not require a storage path. Block materialization uses the existing operation form materialize owner value (rows), with packing configured by its provider. Rows and packing evaluate in order once per construction. Key and witness implementations own their complete resource protocols. Resource reuse requires the current right-hand result, ordered coordinates and configured macro binding. The direct lowerer forwards configured paths; it does not inject storage, collection or iterator choices into leaves.

Hosts: direct plain/observed item and callable forms share the checked lowering. Callables borrow inputs in declaration order, capture ordinary caller configuration and return owned answers. Observed hosts own counters, initialization and checkpoints, forwarding the actual optional work expression. Source borrows and witness resources are hoisted to preserve deferred-stream lifetimes. Regression tests cover direct and opaque caller helper-name collisions in block packing, metadata predicates and observed statistics. Independent physical checks reject fabricated initialization, incorrect statistics definitions, duplicate/destructured observer bindings and extra host statements. Arbitrary selected macro bodies remain outside this scaffold correspondence check.

Enforcement: tools/check_dependencies.py checks all Cargo dependency kinds, renamed dependencies and exact frontend feature forwarding. Its final --isolate run passes 24 copied source-removal build/test jobs, 22 runnable frontend probes with a renamed dependency and substituted continuations, six family all-feature checks, an import/feature audit of 62 implementation files, six forbidden-dependency mutations and two sibling import/feature mutations. Built-in next stages are disabled in each frontend probe. Cargo isolates families; sibling independence is separately checked by source removal and reviewed imports. Log: target/family-isolation-final.log. The latest direct checker also passes its source-removal, combined-feature and frontend gates in target/observed-final-isolation.log. All 22 external macro probes pass again after the frontend feature changes in target/feature-frontends.log.

Package feature testing: tools/check_features.py derives 34 distinct configurations from Cargo metadata: no defaults, each completed feature, default/completed bundles and test/example prerequisites. Every configuration passes ordinary cargo test, including all 20 completed integration/example targets across the matrix. Cargo required-features gates multi-stage targets; individual native cases execute with their own features. No-default is warning-free; scan-only runs both parser validation and the actual discarded-predicate/observer regression. Splitting combined native tests preserves all assertions and increases their count from six to eight. CI runs this matrix separately from external dependency/continuation isolation; no exhaustive subset claim is made. Logs: target/feature-matrix.log and target/feature-logs/.

Workspace validation: 466 tests passed across 80 reported test targets with cq-workloads/compiled-queries and mini-linq/compiled-workloads explicitly enabled. All three harness-free examples executed: blocked-ya, rust-expressions and rust-expressions-planned. The final source also passes workspace/all-target Clippy with -D warnings, formatting and whitespace checks. Log: target/feature-workspace.log and target/feature-clippy.log. The unfinished hw4 optional track is not part of this completed-feature gate.

The current eight separately gated native cases also pass in release, as do both scan-only tests with defaults disabled (target/feature-native-release.log and target/feature-scan-release.log). Formal evidence: check.py validates 154 named rule links and 320 reviewed source fingerprints; 14 Access refinement rules retain source/algorithm/model associations. The finite model passes 98,415 current-view candidate cases and 1,280 witness cases, plus correlated-key, i64-boundary, empty-key, stream-support and stale-version witnesses. All five executable paper drivers pass. Logs: target/family-formal-drivers.log and target/feature-formal-pdf.log. Both manuscripts build without unresolved references/citations or layout warnings: 34 pages for the main paper and 11 for the physical supplement. All 337 checked local Markdown link paths resolve. The separate doc/notes repository is untouched.

Limits: package isolation, source extraction, scaffold correspondence and semantic correctness are distinct claims. The direct backend retains its documented i64 array/RA domain. Bounded tests do not establish arbitrary provider laws, complete Rust elaboration/effect adequacy, arbitrary composition or physical optimality. Cost search, recursive-program semantics and Triejoin remain future work. Reviewed source identity is recorded in sources.sha256; the inventory itself does not check mathematical proofs.
