Revision: Extractable compiler implementations and reusable materialized queries, 15 September 2026.
Architecture: CQ -> RA -> IndexRequirements -> Rust[Access] -> Rust[Pipeline] -> Rust; configured direct RA -> Rust[Access] remains a separate edge. No language or serialized IR was added.
Ownership: existing IR modules own syntax and local judgments; explicit compiler implementations own admitted domains and independent source-target checks; composition.rs owns defaults and complete program composition. Shared analysis contains linear/key facts without route selection or generated storage. Graph certificate checking is independent of scheduling. The central pass_contracts module is removed; correspondence checks live with their semantic edges.
Composition: canonical, prefix and graph CQ entries, input/result index entries, and input-indexed/lazy/materialized physical entries are explicitly selectable. Relative macro continuations use ordinary Rust aliases. Five explicit routes agree on all 256 databases of the small two-relation fixture and duplicate-input variants. Graph and prefix proofs for the same CQ both check and replay; incompatible explicit routes return diagnostics. Malformed expression proofs are rejected before graph state construction.
Reusable host: compile_materialized_query returns a checked native expression with declaration-order, once-only input evaluation. compile_materialized_callable adds an independently checked anonymous closure. It introduces no generated function item, supports native Rust captures, and has ordinary per-value inferred closure input types. Plain execution has no counters or output-ordering requirement; the existing standalone host retains observations and sorted materialization. Both use the same set computation. Input normalization now spells the same conversion/collection operations with qualified calls for closure inference. Repeated calls rebuild local sets/indexes; persistent indexes and recursive semantics are not implemented by this adapter.
Teaching extraction: tools/export_ya.py selects a source/dependency allowlist into three independent crates. The final export contains 57 inventoried files, excludes unrelated physical implementations, and replaces exactly two algorithm files with YA-scheduling and semijoin-lowering exercises. The stubbed foundation builds and passes 30 IR tests; each exercise suite detects its own missing implementation; a temporary two-file reference overlay passes 49 tests and both examples. Final inventory hashes, internal manifest paths, restored stubs and absence of reference/build artifacts were checked. This is the YA part of Project 2; triejoin and the Project 3 recursive-program release remain future semantics work.
Validation: 407 workspace tests passed across 55 targets with cq-workloads/compiled-queries, including execution of the blocked-ya and Rust-expression example drivers. Focused release validation passed 83 compiler tests across six targets and four macro composition/host tests across two targets. The library's 57 tests passed again after lint-only helper relocation. Workspace/all-target Clippy with compiled queries and -D warnings, formatting and whitespace checks passed. Logs are target/decomposition-{workspace-tests,release-tests,macro-release-tests,final-unit-tests,clippy}.log.
Formal inventory: 140 main-manuscript rules plus 14 implementation-linked Access-refinement rules, two physical algorithms, and 150 reviewed source fingerprints. The finite model passed 98,415 current-view candidate cases and 1,280 witness cases, plus targeted correlated-key, i64-boundary, empty-key, stream-support and stale-version witnesses. Inventory/source identity and bounded denotational checks do not constitute full Rust or provider-law verification.
Documentation: stage ownership, macro continuations, host observation contracts, rule-to-source mappings and complete staged example artifacts are current. Local documentation paths resolve. Both manuscripts build without LaTeX warnings or overfull/underfull boxes: main manuscript 33 pages, physical supplement nine pages. Source identity is recorded in sources.sha256; current boundaries are in ../IR-STAGE-REVIEW.md and ownership in ../COMPILER-STRUCTURE.md.
Remaining limits: the configured direct array backend retains its declared i64/RA domain; provider laws, arbitrary Rust effects/hygiene, conditional context adequacy and automatic physical cost search are not mechanically established. Host-independent query compilation is demonstrated for materialized hash access, not every backend. Storage contains data structures and traits, not runtime relational execution.
