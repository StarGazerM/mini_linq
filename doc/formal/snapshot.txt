Revision: Native algorithm and representation boundaries, 15 September 2026.

Architecture: CQ -> RA -> IndexRequirements -> Rust[Access] -> Rust[Pipeline] -> Rust remains the indexed route. Configured relation realization separately lowers RA to Rust containing Access and native fragments. Push-to-set lowers Access directly to Rust. No contextual whole-query IR, route tag, capability registry or runtime relational interpreter is introduced.

Ownership: cq-plan owns canonical/prefix/graph planning; cq-index owns base-input and named-result equality demands. cq-realize owns hash_inputs, hash_prefix, hash_materialized and relations realizations. cq-native groups rows, candidates, keys, witnesses and complete pair algorithms at the native-fragment boundary. cq-execution owns pull and push Access execution, cq-pipeline the iterator/collect/stream endpoints. cq-ir owns their grammars and local judgments; cq-storage contains runtime data structures and minimal operation traits. cq-compose supplies typed recipes and mini-linq exposes the procedural macros.

Composition: each macro chooser invokes its selected caller-relative continuation. mini_linq chooses canonical/prefix; optimized_query chooses graph/prefix; both emit choose_indexes through the selected planner. Index policies emit choose_realization. The default realization chooser examines actual IX and selects an admitted hash implementation. An eager recipe is a facade binding result_indexes as choose_indexes and hash_materialized as choose_realization. Compiled workloads enter the ordinary macro route. Typed recipes are a separate API with explicit iterator-valued and set-valued continuations.

Native semantics: Type receives logical Rust column types; each row provider owns Field and Record. Tuple sets can coexist with i64 arrays and block storage in configured RA. Key construction remains representation-owned. Produce binds a local emission sink; Pairs owns complete traversal and auxiliary storage for equal-key pair production. Hash, repeated nested traversal and sort/merge preserve occurrence multiplicity under finite stable traversal and pure-key premises. Sort/merge explicitly sorts both inputs. The selected result provider deduplicates emitted rows. The surrounding realization still owns named-result materialization and resource lifetimes; these local seams do not establish arbitrary region fusion.

Configuration: optional defaults and per-result overrides supply only the roles used by actual RA operators. Rename needs only input providers; Unit only an output provider; Project/Extend need Access and an output provider; Select needs Access; Semijoin needs Access, candidate scan and key resource; NaturalJoin needs an output provider and pair algorithm. Missing used choices are source errors rather than implicit fallbacks.

Pruning: candidates enumerate only current handles and cover every exact match. Zone metadata rejects a block before opening its selected payload; exact membership completes the semijoin. Resource sharing requires the same current RHS version, separator and configured key binding. BuildBlocks::pack_unique accepts any unique-row iterable; uniqueness is a caller precondition and HashSet is not imposed as the trait's carrier.

Execution observations: pull lowers checked Access to Pipeline; push_set emits nested Rust loops and one set sink directly, cloning only incoming bindings conservatively live after each dependent source. Pipeline permits arbitrary fresh stream names, tuple alpha-renaming, selected/reordered bindings and early or repeated projections. It remains a linear single-consumer chain with final Distinct. Eager-set, distinct-iterator and pre-Distinct-stream observations are different contracts. Arbitrary host effects, panic/drop behavior and demand timing are not equated by completed-set preservation.

The finite model passes 98,415 current-view candidate cases and 1,280 witness cases, plus correlated-key, i64-boundary, empty-key, stream-support and stale-version checks. Execution-boundary design, 16 September 2026: doc/IR-STAGE-REVIEW.md now distinguishes the implemented architecture from a pending redesign.
