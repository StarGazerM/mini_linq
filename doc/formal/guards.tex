\section{Guards: earned position independence}
\label{sec:guards-design}

Position independence is a property of the relational language, not an
assertion attached to arbitrary Rust. The implemented guard contract follows
a single principle.

\paragraph{Principle.} A guard is position-independent exactly when the
language itself can see that it is defined on every value of its declared
types. By the Motion lemma (Section~\ref{sec:premises}) this is the condition
under which a plan may evaluate it on rows the written order would not reach.
Nothing the author asserts and nothing matched by name can supply it. Every
other guard is opaque and pinned: it keeps its written position in the Rust
chain, and relational steps may only move earlier across it, which can only
shrink its evaluation domain.

\paragraph{The relational vocabulary.} Position independence is earned only by
constructs whose meaning the CQ language defines:
\begin{enumerate}
\item \emph{Comparisons} \code{== != < <= > >=} and the Boolean connectives
\code{\&\& || !} over query names, parameters and literals (CQ-GuardRecognize).
Totality follows from the Leibniz and Order premises; the printer's
\code{relational\_eq}/\code{relational\_cmp} obligations make rustc check the
\code{Eq}/\code{Ord} bounds. This is the language's grammar, not an allowlist
of arbitrary Rust functions or author-supplied type-name promises.
\item \emph{Relational operators}: atoms, semijoins and anti-joins. Membership
of a value in a relation is relational, not a Rust call.
\item \emph{Typed arithmetic} (CQ-Arith): \code{+ - *}, and integer
\code{/} with a nonzero literal divisor, over declared integer names,
integer literals and decimal coefficients. Its meaning is wrapping arithmetic,
not Rust's debug-panicking arithmetic. Date coefficients use their declared
integer width. A decimal's \code{scaled()} projection denotes its signed
64-bit coefficient; elaboration uses the canonical \code{cq\_load::Decimal}
projection, not a promise about an arbitrary Rust method.
\end{enumerate}

\begin{mathpar}
\Rule{CQ-Arith}{\Gamma\vdash a,b:\mathbb Z/2^w\mathbb Z\quad
 op\in\{+,-,*\}\ \lor\ (op=/\land b\text{ a nonzero integer literal})}
 {\Gamma\vdash a\ op\ b:\mathbb Z/2^w\mathbb Z\quad
  \mathsf{total}(a\ op\ b)}
\end{mathpar}
Addition, subtraction and multiplication reduce the result modulo $2^w$.
Signed division truncates toward zero; the exceptional minimum-value divided
by $-1$ returns the minimum value. Literal coefficients use the declared
integer representation. Host elaboration uses \code{wrapping\_add},
\code{wrapping\_sub}, \code{wrapping\_mul}, and \code{wrapping\_div};
device compilation implements the same fixed-width operations natively.
Operands must agree in declared integer type; no implicit widening, runtime
divisor proof, captured Rust function, cast or arbitrary method earns totality.
The grammar is closed under \code{if c \{a\} else \{b\}} when $c$ is a
recognized total predicate and both branches are total expressions of the
same declared type. It also admits primitive \code{T::from(a)} exactly when
the source integer range is contained in the target range; canonical primitive
UFCS calls enforce that representation. A lossy \code{as} cast remains opaque.
These expressions may occur in scalar bindings, aggregate arguments and
recognized comparisons. Their typed grammar is rechecked from row types in
later IRs, where they retain Bind/Guard syntax rather than an asserted flag.

\paragraph{No asserted totality.}
The guard grammar has no \code{\#[total]} annotation, \code{Filter} has no
totality flag, and relational constraints contain no arbitrary Rust predicate
variant. Method names and type names do not certify guards.
The guard-motion obligations in C-Ready, E-Constraint, ST-Total, the mask
lemma, BK-Dual's total case, BE-Boundary and DL-Delta use recognized
relational predicates under premises 1--2 and the purity premises; they
require no asserted-totality premise. Producer and input obligations remain
separate.

\paragraph{Consequences.}
\begin{enumerate}
\item \emph{Arbitrary Rust guards} (\code{name.contains("green")}, a TPC-H
\code{LIKE}): ordinary Rust, type-checked by rustc and evaluated at their
written position. Nothing special is recognized; pinning is the normal
treatment of Rust, not a loss of meaning.
\item \emph{Datalog negation} is a CQ negated atom \code{!R(..)}, elaborated
to the existing RA \code{anti}. It is not encoded as a Rust membership
guard and requires no assertion.
\item \emph{GPU translation} re-translates relational predicates and CQ-Arith
expressions only. Motion admits typed arithmetic bindings and guards as soon as
their query inputs are bound; BE-Partial no longer pins the whole relation to
host for a price-times-discount aggregate argument. The \code{h05} range guard
still becomes a recognized \code{Between}, retaining range reads. A nonliteral
divisor or an unrecognized call remains opaque and must run at host.
\end{enumerate}

\subsection{Negation in CQ}
\paragraph{Grammar.} \code{BodyItem ::= ... | "!" Atom}.
Arguments are logical variables, constants (literals, parameters) or
\code{\_}.
\paragraph{Contract.}
\begin{mathpar}
\Rule{CQ-Neg}{R\text{ a declared input relation}\quad |args|=|\Sigma(R)|\\
 \mathrm{vars}(args)\subseteq\mathsf{bound\_before}(i)\\
 \text{binds nothing}\quad \text{columns at constants and variables Leibniz}}
 {\mathrm{WF}(\code{!R(args)}\text{ at clause }i)}
\end{mathpar}
Safety: every named variable is bound by earlier clauses; wildcards are
existential and bind nothing. A negated relation is an input of the query (CQ
has no recursion; stratification is the enclosing compiler's obligation).
\paragraph{Meaning.}
\[
\llbracket\code{!R(args)}\rrbracket(\rho)=
\begin{cases}\{\rho\}&\neg\exists t\in R.\ \mathsf{match}(args,\rho,t)\\
\emptyset&\text{otherwise}\end{cases}
\]
where \code{match} compares named variables and constants by Leibniz equality
and ignores wildcards. It never yields $\bot$: negation is total and
relational, so the Motion lemma lets it move like a selection once its
variables are bound.
\paragraph{Elaboration.}
\begin{mathpar}
\Rule{E-Neg}{p\text{ the prefix binding }F=\mathrm{vars}(args)\quad
 s=\pi_{F}(\sigma_{consts,repeats}(\mathsf{rename}(R)))}
 {\code{!R(args)}\ \leadsto\ \mathsf{anti}_F(p,s)}
\end{mathpar}
Constants and repeated-variable equalities become selections on $R$,
wildcards are projected away, and the
result is the existing RA anti-join ($\sem{\mathsf{anti}_F(r,s)}=\sem
r\triangleright_F\sem s$); Physical chooses \code{anti eager|lazy} and the read
of $s$ (a host membership read when the host supports exact membership) as
for block fallback anti steps. An all-wildcard atom is an emptiness test of
$R$ ($F=\emptyset$). VO records \code{Step::Negation(cq::Negation, Token![;])}
as a relational step; it requires its named variables, provides none,
and is neither a Rust-chain step nor a reduction target or support.
The implementation elides an existential projection when the anti key itself
discards the unused columns, preserving a direct host read. Borrowed key sets
are queried with the borrowed tuple before considering an owned-key read or
a built fallback. An empty host key uses a first-row witness test rather than
allocating a membership index.
Computed prefix values use borrowed native probes too; only an unsupported
host's retained fallback requires owned keys.

\paragraph{Datalog.} The fork emits \code{!K(args)} against the borrowed,
completed key-set host of the lower stratum (or \code{!R(args)} against the
relation), declared like any hole input; the Round checker's negation rule
compares that atom instead of a Rust guard. Key holes apply constant filters
and repeated-variable equalities before projecting the distinct variables,
so the emitted atom has distinct arguments (or a unit-column wildcard).
Key sets stay built once per stratum; the anti read uses the host's membership,
never a per-call build. The Round checker independently derives these keys.
