\section{Rust expressions and relational predicates}
\label{sec:guards-design}

\paragraph{Two syntactic categories, one Rust semantics.}
\code{if e}, \code{let p [: T] = e} and \code{for p in e} embed the same
opaque Rust expression category. Each expression is pure and total by
premise, including generator construction, conversion and finite iteration.
A panic violates the premise: it is a wrong plan, not an outcome whose
removal or preservation licenses optimization. Rust evaluates the original
expression; the compiler does not recognize arithmetic, calls, comparisons,
casts, methods, types or boolean subexpressions.

\paragraph{Free-variable placement.}
An expression may execute wherever its query free variables are bound.
Lexically opaque syntax conservatively reads the complete lexical environment.
An expression's bound-variable identities and syntax are preserved, but no
written-order Rust chain or relational predecessor set constrains motion.
The CQ-to-VO planner records the placement; later passes consume that decision.
Closure is the fact $\fv(e)\cap Q=\emptyset$, not a weaker kind of opacity.

\paragraph{Relational vocabulary.}
\code{where P} alone introduces the explicit comparison, membership, range
and boolean grammar of Section~\ref{sec:cq}. Its equality and order are those
of the column representation, under the Leibniz and Order laws. Operands
are query variables, literals or closed Rust expressions evaluated once on
the host. Fields, function calls and other closed host expressions are not
special cases; free-variable analysis supplies the same closure criterion.
Only this syntax supplies point/range/membership reads, filter priorities,
Masks supports, derived domains and user-authored join equalities. Atoms,
occurrence literals, normalization identities, semijoins and antijoins retain
their independently defined relational meaning.

Relational conjunctions become independent clauses before planning, retaining
every conjunct and its scope. After scope resolution, variable and literal
equalities use the canonical equality clause, keeping literal point reads
ahead of general predicate filters; captured Rust operands remain constraints.
VO parsing uses the same canonical equality form. Programmatic equivalent
constraint nodes follow the same equality pushdown and structural branch
accounting, so they neither lose an equality nor repeat a branch-local test
after its columns have been projected away.
Adjacent inclusive bounds on one term use the
compact range form; a disjunction of literal equalities on one term uses the
same membership form as an explicit literal list. These normalizations also
apply inside relational disjunctions, so derived domains retain their literal
membership restrictions. Half-open ranges retain both their inclusive lower
and exclusive upper bounds. None of these rules inspect \code{if}: a Rust
array \code{contains} call and its surrounding Rust conjunction remain one
unchanged opaque predicate.

\paragraph{Types and representations.}
Types are host syntax passed to rustc, not a compiler classification.
No integer, decimal, string, optional or floating-point type spelling proves
totality or admissibility. There is no wrapping-arithmetic translation or
syntactic Eq/Ord rejection. Codecs and providers record representation facts,
including sizes and encodings; traits enforce the required operations and
their semantic laws remain premises.

\paragraph{Device placement.}
A row-dependent Rust expression is emitted verbatim and compiled by
cuda-oxide. It may execute on device only when every column it reads has an
identity device representation (no codec), and its other inputs are closed
captures (BE-RustRepresentation). Otherwise it executes at host.
Codec-encoded columns are compared through \code{where}; a closed operand
is encoded on the host using the compared column's recorded codec.
Device eligibility is a representation fact, not a Rust type-name or
arithmetic whitelist.

\subsection{Negation in CQ}
\paragraph{Grammar.} \code{BodyItem ::= ... | "!" Atom}.
Arguments are logical variables, constants (literals, parameters) or
\code{\_}.
\paragraph{Contract.}
\begin{mathpar}
\Rule{CQ-Neg}{R\text{ a declared input relation}\quad |args|=|\Sigma(R)|\\
 \mathrm{vars}(args)\subseteq\mathsf{bound\_before}(i)\\
 \text{binds nothing}\quad \text{columns at constants and variables Leibniz}}
 {\mathrm{WF}(\code{!R(args)}\text{ at clause }i)}
\end{mathpar}
Safety: every named variable is bound by earlier clauses; wildcards are
existential and bind nothing. A negated relation is an input of the query (CQ
has no recursion; stratification is the enclosing compiler's obligation).
\paragraph{Meaning.}
\[
\llbracket\code{!R(args)}\rrbracket(\rho)=
\begin{cases}\{\rho\}&\neg\exists t\in R.\ \mathsf{match}(args,\rho,t)\\
\emptyset&\text{otherwise}\end{cases}
\]
where \code{match} compares named variables and constants by Leibniz equality
and ignores wildcards. It never yields $\bot$: negation is total and
relational, so the Motion lemma lets it move like a selection once its
variables are bound.
\paragraph{Elaboration.}
\begin{mathpar}
\Rule{E-Neg}{p\text{ the prefix binding }F=\mathrm{vars}(args)\quad
 s=\pi_{F}(\sigma_{consts,repeats}(\mathsf{rename}(R)))}
 {\code{!R(args)}\ \leadsto\ \mathsf{anti}_F(p,s)}
\end{mathpar}
Constants and repeated-variable equalities become selections on $R$,
wildcards are projected away, and the
result is the existing RA anti-join ($\sem{\mathsf{anti}_F(r,s)}=\sem
r\triangleright_F\sem s$); Physical chooses \code{anti eager|lazy} and the read
of $s$ (a host membership read when the host supports exact membership) as
for block fallback anti steps. An all-wildcard atom is an emptiness test of
$R$ ($F=\emptyset$). VO records \code{Step::Negation(cq::Negation, Token![;])}
as a relational step; it requires its named variables, provides none,
and is neither a Rust expression nor a reduction target or support.
The implementation elides an existential projection when the anti key itself
discards the unused columns, preserving a direct host read. Borrowed key sets
are queried with the borrowed tuple before considering an owned-key read or
a built fallback. An empty host key uses a first-row witness test rather than
allocating a membership index.
Computed prefix values use borrowed native probes too; only an unsupported
host's retained fallback requires owned keys.

\paragraph{Datalog.} The fork emits \code{!K(args)} against the borrowed,
completed key-set host of the lower stratum (or \code{!R(args)} against the
relation), declared like any hole input; the Round checker's negation rule
compares that atom instead of a Rust guard. Key holes apply constant filters
and repeated-variable equalities before projecting the distinct variables,
so the emitted atom has distinct arguments (or a unit-column wildcard).
Key sets stay built once per stratum; the anti read uses the host's membership,
never a per-call build. The Round checker independently derives these keys.
