\section{Structures: concrete representations}
\label{sec:structures}

\paragraph{Grammar.} Structures annotates a separately supplied complete Physical
program $p$, referring to its definitions by name. Parsing and checking receive
$p$ explicitly; the Structures program neither embeds nor prints it.
\begin{lstlisting}
Structures ::= structures { providers { Decl* } Entry* }
Decl ::= x = Type { Fact, ... };
Fact ::= reads [Cap,...] | supports [Support,...] | build (inferred | typed)
       | accounting (rows | keys) | (nested | routed) N | join_filter
       | shared | packed_bits N | abi (range | runs | columns)
       | contiguous_range | bounds resident_columns
       | items N [rows Type, columns Type]
       | choice N [eager Arg, lazy Arg]
Cap ::= exact | range | membership | ordered | distinct | resident
Provider ::= @x [(Provider)] [InputSchema] as Type
InputSchema ::= input { keys N; columns [InputColumn,...] }
InputColumn ::= Type => Type [codec ["[" N "]"] Type]
Entry ::= r = Provider [K]... [supports [Support,...]] [items (rows | columns)]
              [membership] [payload[P] constants{c = term, ...}];
        | r host ReaderRef = Provider [K]... [supports [Support,...]];
        | r native ReaderRef = HostRead [K] [supports [Support,...]];
        | r rows = Provider; | r canon = Canon; | r head = Provider;
        | r group = Provider;
        | r selection = Provider base H lineage{a -> c, ...}
              summary (none | per_block);
        | r keyset = Provider [K] (owned | borrowed)
              base H lineage{a -> c, ...};
        | r read = positional base H lineage{a -> c, ...}
              column c marker Type predicate Predicate;
        | r join_filter = Provider build s [k]
              covering j marker Type policy (always | abandon N of H keys (key_count | Accessor));
        | r share = lookup b [K] first s force p;
        | r repr = (tuples | positions {H lineage {a -> c, ...}, ...}
                         owned [O]) [witness {b [K] at s as Type}];
        | r stage = batch N [expand];
Predicate ::= physical | membership s [K] summary (exact | row)
ReaderRef ::= scan | candidates | membership | result(Ident)
HostRead ::= exact | membership | candidates | range | ordered
Support ::= retain | expand | keys
Canon ::= rows | [K] | host
\end{lstlisting}

\paragraph{Provider tokens.} A provider is a declared token, never a Rust type.
The pass that selects a provider, or authored \code{retype} advice, records
its token id $x$, the inner instance of a nested or routed token, and the Rust
spelling printers emit verbatim. The \code{providers} table declares each
referenced token once: its read capabilities, the strongest support an
instance may declare, its construction (\code{inferred}: a bare path built by
\code{Build::build}; \code{typed}: \code{<T as cq\_storage::Build<\_>>::build}), allocation
accounting, composition with the inner's generic argument index, supplementary
join-filter eligibility, sharing with pool and task readers, a packed-key
width limit, native ABI, contiguous-range eligibility and bounds source.
Native Host input instances additionally record ordered logical/storage columns
and optional codecs. Each \code{InputColumn} stores
\code{codec\_id: Option<CodecId>} beside \code{codec: Option<syn::Type>}, with
\code{cq\_lang\_structures::provider::CodecId(pub u32)}.
Source \code{codec Type} may omit the id; the Structures declaration boundary
interns missing ids once by opaque token spelling, locally to that declaration
context. Repeated automatically interned spellings share an id.
Explicit \code{codec [0] Type} and \code{codec [1] Type} remain distinct even
with the same spelling; explicit ids are preserved. \code{None} is identity.
Later passes compare recorded ids, never codec types; the type is only a
printing payload after interning. Codec-id presence records encoding.
Logical declaration identity is separately recorded as
\code{logical\_type\_id: Option<cq\_syntax::LogicalTypeId>}, whose id wraps
\code{u32}. Relation syntax is \code{column: Type [id] in [domain] (expr)};
provider columns use \code{[id] Logical => Storage codec [id] Codec}.
Ids may be omitted at declaration boundaries: interning preserves explicit
ids and shares automatically interned equal spellings once, without merging
explicitly different ids. Source/provider logical-id mismatches are rejected.
Parsing Structures with its supplied Physical program seeds the input declaration
table with that program's relation identities, so input encounter order cannot renumber
logical types. Standalone Structures declarations intern in their own table;
programmatic producers copy the source declaration identities.
RA and Physical rows carry a sparse \code{logical\_type\_ids} map.
Physical computed output columns receive their result declaration's id;
computed opaque types without such a declaration remain unknown. Later codec lookup is keyed by
logical id, not by the printing-only logical type. Neither logical identity
nor codec identity proves the runtime codec laws.
Comparing token ids is identity, not recognition.

enumerates a supplementary join filter iff its inner does.

\paragraph{Contract.}
Write $h_r=A.physical.headings[r]$, $B_r=A.built[r]$, $F=A.fallbacks$,
$N=A.natives$, $S=\mathrm{dom}(A.selections)$, $R=\mathrm{dom}(A.retained)$,
$D=\mathrm{dom}(A.reads)$ and $Q=\mathrm{dom}(A.filtered)$.
$k_r$ is the list of Physical keyed reads $(u,K,supply)$ of $r$.
The function $\mathsf{prefixes}(L)$ returns the unions of the nonempty
prefixes of the sequence of levels $L$.
$\mathsf{candidates}(t)$ returns the Physical candidate sides $(r,K)$.
$\mathsf{required}(t,A,r)$ is the downstream column demand computed by
\code{filtered::required\_columns}, including keys, predicates, Rust free
variables and the answer. $\mathsf{constants}(r)$ is the map of reconstructible
literal equalities proved by a declarative selection, and the empty map for
a rename or union. $\mathsf{multi}(r)$ is true exactly for a union with no
correlated \code{over} origin. These functions do not inspect type spellings.
$\mathsf{physicalReads}$ enumerates the checked Physical keyed and merge
demands as $(provider,key,mode)$ triples, using range mode for non-stream
point/range supplies and the reader's probe, semi, anti or merge mode otherwise.

$\mathsf{op}(Result(u))$ is the operator of $u$, and other reader tags
have their own distinct operator tags.
The function $\ell_t(r)$ rederives lineage in definition order: a
literal-free rename starts its declared host occurrence; Select, Point and
Range inherit their input; Project restricts its input map to $h_r$;
non-lazy Semi inherits its left input. All other operators, canon boundaries,
computed columns and fused members return $\bot$. A result is retained only
when its map is total on $h_r$ and injective.
$\mathsf{spine}(r)$ follows Project inputs, Point/Range inputs and Semi
left inputs to the first prior selection or rename; it includes $r$ but
excludes a prior selection endpoint.

In STR-E-Read, $c_r$ is the logical column mapped to the recorded host
column. $\mathsf{conditionColumn}$ returns the first point key or range
column, and $\mathsf{selectionConstants}$ includes the proved singleton
terms (not only reconstructible literals).
$\mathsf{readSpine}(r)$ starts at the predicate input (the left input for
Semi), stops before a prior selection, and otherwise follows Project until
a rename or recorded read. Other operators are included and rejected by
STR-E-Read. The order $<$ is Physical definition order, so summary edges
cannot form cycles. Both row and exact summaries require an owned scalar
keyset; exact summaries additionally incur Rust's
\code{ExactIntervalMembership} obligation.

The remaining representation and realization laws are not additional
Structures-checker predicates. Constant columns are reconstructed rather
than stored; projection follows predicate evaluation and precedes publication
or upload. Literal-bearing renames use ordinary storage without filtered
annotations; eligible leading literal keys can use native point access,
otherwise the source scans and filters. GPU retained occurrence tables are
built before the query stream kernel.
Keysets record their provider and ownership without excluding payload indexes.
Default policy records codec and bitmap budget in the provider type.
Rust checks codec, key-layout, interval, positional host, marker, key,
lifetime and provider obligations uniformly through aliases. Every positional
or join-filter marker must implement \code{ColumnSlot<H,N>} for the
declaration-order slot derived from lineage; type compatibility or spelling
does not establish that binding. These trait and storage abstraction laws
remain semantic premises, not checks performed by the Structures validator.
A keyed Group's recorded provider is a finite map from keys to declared
accumulator tuples: \code{Default} creates the empty map,
\code{entry(k).or\_insert\_with(f)} returns the unique state and invokes $f$
only on insertion, and owned \code{IntoIterator} enumerates each pair once.
Rust checks operations and bounds, not these finite-map laws. Realization
preserves the recorded provider type; \code{group} retyping selects it.

\paragraph{Provider-authored support.}
Support is recorded with the selected provider layout, bounded by its token's
declared support, and never inferred from a Rust type spelling. \code{retain}
requires an immutable exact lookup with a Copy
cursor; \code{expand} additionally requires an exact finite cursor length and
implies retain. \code{keys} requires exact distinct-key enumeration through
\code{Keys}. Duplicate declarations, support on scan adapters, support not
declared by the token, and payload-cursor
support on membership-only builds are rejected. A one-level unit key remains a
lawful keyed read; empty levels in a multi-level layout do not confer support.
Default selection records \code{keys} on a one-level, non-membership payload
build exactly when its chosen token declares it.
Ordinary complete-key reads and Smallest candidate directories select different
layouts: a capability on a payload index cannot certify a separate candidate
directory, or conversely.

These declarations do not discharge Rust trait obligations or the semantic
provider laws. Native emission checks \code{IndexRead}, Copy,
\code{ExactSizeIterator}, and \code{Keys} as required; ordinary payload,
membership, interval and ordered accesses retain their own trait obligations.
Aliases and unrelated provider names receive identical checks. Default selection
declares support only for implementations and access paths it chooses, without
imposing unused fallback bounds on a native host read.
Retyping replaces token, spelling and support packet together; bare retyping clears the packet. Existing witnesses,
expansion and filters must remain justified. Target catalogs declare the same
tokens and selection preserves live obligations, while replay freezes
both provider records and support. Neither support nor sorted storage grants
Ordered, contiguous Sequence Range, or device placement.

Uniqueness: Unit has the empty key; a rename of a certified or discharged
\code{host_set} has its full heading as key, and other host renames have none; join needs both
keys and unions them; semi/anti keep the left key; union infers none;
selections, guards and binds preserve it; projection preserves it only if no key
column is dropped; a canon flag gives the full heading through its checked canonical reference.
A built structure alone proves no uniqueness.
An explicit \code{membership} modifier on a single-level filtered build proves
that every downstream observation is a supplied key or reconstructed constant.
The checker rederives projection coverage and rejects partial-key or ordered
reads. The printer emits one unit witness on successful membership, without an
occurrence-preserving payload index. Default selection records
token \code{dense\_membership} for one stored key column, whose declaration spells
\code{DenseMembership<K,16777216>} once and requires \code{K: OrderKey}.
Wider stored keys record \code{adaptive\_membership}, whose declaration spells
\code{AdaptiveMembership<K,16777216>} once. Rust key syntax is never inspected.
The membership contract itself remains valid for explicitly recorded composite keys.
No base-table key or foreign-key assumption is used.

\paragraph{One ordered key law.}
\code{OrderKey} supplies one total order embedding for stored and absent
query keys. Dense, rank and radix representations all use this encoding;
\code{KeyCodec} is only a sealed directory policy delegating to it, or
\code{NoDense}, which disables numeric directories. Width requirements
are provider capabilities, never truncation.

\paragraph{Runtime scan blocks.}
The authored family $F$ is Plain or Bytes. Plain stores native-width ordinals;
Bytes stores constant, byte or two-byte residuals when strictly narrower,
otherwise native-width ordinals. Block size is a positive multiple of 1024.
The inverse ordinal law is a premise on the host type, not compiler inspection.
Ordinals and extrema are collected in one input traversal; reusable block
scratch supplies the final payload after its base and width are known.
\begin{mathpar}
\Rule{RT-ScanCodec}{b=\mathsf{encode}_F(v)\quad
 \forall x\in v.\ \mathsf{fromOrdinal}(\mathsf{ord}(x))=x}
 {\mathsf{concat}(\mathsf{decodeVectors}(b))=v}
\Rule{RT-ScanSummary}{b=\mathsf{encode}_F(v)\quad
 s=\mathsf{summary}(b)\quad v\ne []}
 {s.lo=\min_{x\in v}\mathsf{ord}(x)\quad s.hi=\max_{x\in v}\mathsf{ord}(x)}
\Rule{RT-Translate}{b=\mathsf{encode}_F(v)\quad
 p\in\{\mathsf{point},\mathsf{window},\mathsf{membership}\}\quad
 c_i=\mathsf{ord}(v_i)-b.base}
 {\mathsf{translate}(p,b)(c_i)\iff p(\mathsf{ord}(v_i))}
\end{mathpar}
Window translation handles open endpoints with checked successor/predecessor;
absent constants and empty intersections do not introduce matches. Filtering
returns ascending occurrence positions, including duplicate occurrences.

\paragraph{Opt-in shared scan descriptors (P6 A).}

domain identity/version and carrier. A fresh immutable snapshot identifies
the encoded source; layout and domain are not inferred from Rust names.

Metadata validation is independent of encoding: it checks family membership,
byte extents/alignment, block/vector counts, live prefix and summary provenance,
not equality with the encoder's preferred compression choice. Safe imports
add payload overflow/carrier and summary-enclosure checks.

Optional vector extrema originate in the encoding traversal, or are validated
against imported payload. Conservative enclosing extrema are lawful.
The positional read law preserves duplicates and requested order and returns
ordinal carriers, not reconstructed authored Rust values. It does not supply
compiler read authorization. Predicate-mask agreement uses RT-Translate;
these laws do not assert cooperative tile scheduling, payload-read pruning,
default codec selection or retirement of existing logical inverse sites.
Legacy FastLanes is not a selectable S1 family.

\paragraph{Membership representation law.}
Selection records the \code{dense\_membership} token
\code{DenseMembership<K,B>} for a membership store with one stored key column
(counted after filtering) and \code{adaptive\_membership}
(\code{AdaptiveMembership<K,B>}, exact hash membership for every
\code{Eq + Hash} key) for wider keys; neither selection nor printing inspects
Rust types. Both denote exactly the supplied set of keys. The dense provider
requires \code{K: OrderKey}, a total order-preserving ordinal:
$\mathsf{ord}(x)=\mathsf{ord}(y)\iff x=y$. A recorded dense key lacking the
capability is a rustc error at its one typed build, never a hash fallback;
integer aliases and user implementations obey the same capability law. The
provider's Rust type carries the ordinal capability, so each membership probe
has no indirect codec call.

\paragraph{Columnar loading.}
Source batches feed one bounded block tail per ordinary column. Interned
columns finalize the dictionary first; their temporary-code remap feeds that
same block encoder. Neither route constructs an intermediate vector of rows.
\[
\Rule{LD-ScanBlocks}{R=\mathsf{concat}(batches)\quad
 C=\mathsf{loadColumns}_{F,B}(batches)}
 {\alpha(C)=R\quad
  \mathsf{summary}(C_j)=\mathsf{extrema}(\mathsf{ord}(R_j))}
\]
The summary equation applies only when requested. Payload and extrema consume
the same input occurrences, independent of source batch boundaries; source
errors do not publish partial dictionaries.
The capability also records an associated unsigned word type: ordinary
integer and string-code ordinals use \code{u64}; wide custom ordinals may use
\code{u128}. Bounds and offsets use that word without a universal widening.
A checked conversion of the complete span to \code{usize}, followed by the
budget check, precedes bitmap allocation and every bounded offset conversion.
The dense provider uses a bitmap only when its observed ordinal span fits the
recorded bound $B$; otherwise it keeps exact hash membership. Contains-only
membership does not construct a sorted interval index.
The compiler records the provider and budget; key sets and sorted runs record
their codec in the provider spelling (for example \code{I64Codec}), never a
guessed or trait-selected codec.
\[
\Rule{STR-AdaptiveMembership}{

\paragraph{Native host reads.}
An entry \code{r native }$c$\code{ = }$\rho$\code{ [}$\vec K$\code{] [supports [}$S$\code{]]}

\paragraph{Sorted runs.}
\code{SortedRun} stably clusters payload occurrences by key. Its directory
and adjacent offsets partition a contiguous payload array; lookup returns a
Copy range cursor. Equal-key input order and multiplicity are preserved.
Presence/rank and binary-search directory access identify the same exact
range. This is a payload representation, not a uniqueness assertion.
\code{RadixRun} uses the same stable clustered payload representation, but its
directory is radix routing over a bounded-error rank spline. A total injective
order-preserving \code{OrderKey<Ordinal = u64>} encoding covers owned, borrowed, and singleton
tuple i32/i64/u32/u64 keys. Integer differences precede floating conversion;
the final window includes a conservative rounding allowance. Exact equality
inside that window determines the payload range, not the prediction itself.
For membership alone, a bounded lazy presence projection may instead record
the encoded keys in a bitmap: a bit is set iff that key occurs in $D$.
Its word-rounded storage is at most one byte per distinct key and 128 KiB;
sparse domains keep exact spline search. Initialization neither changes
$(D,O,V)$ nor invalidates existing payload cursors.
Payload layout is explicit: \code{RadixRun<K,V,C>} requires
\code{ItemColumns<Row=V>}. The default vector stores opaque items;
tuple-of-vector layouts store independent columns. All columns have the same
length; append and range-copy preserve the same occurrence positions.
Key-only operations do not call row reconstruction. Column-group reads
borrow the selected arrays and position ranges; lookup reconstructs only
demanded rows, while contiguous legacy item reads may materialize a row view.
The compiler records C rather than inspecting V: a one-level payload build
carries the Structures fact \code{items rows} or \code{items columns}. The
provider token declares the layout argument and both spellings
(\code{items 2 [rows ::std::vec::Vec<\_>, columns ::cq\_storage::TupleColumns<\_>]}
for \code{radix\_run}); the instance spelling ends before that argument and
the checked analysis appends the declared spelling of the recorded fact
(the tuple of vectors rustc derives from the row type, so no arity is spelled).
The fact is the argument's only source: a spelling that states the layout, a
missing fact or a fact on a token without the slot is rejected. Host readers
and key-only membership storage keep the type's default layout.
The payload is the filtered schema, else the result's carried columns
(\code{cq\_lang\_structures::demand}, the same column demand printers carry),
without the key. A reader's need is the carried columns of the probe or merge
reading the index.
\[
\Rule{IX-ItemColumns}{\mathsf{columns}(I)=(C_1,\ldots,C_m)\quad 0\le j<|I|}
 {\forall i.\ |C_i|=|I|\quad (C_1[j],\ldots,C_m[j])=I[j]}
\]

\paragraph{Device radix runs.}
\code{DeviceRadixRun<W,O,C>} (\code{gpu-datalog-runtime}) is the device
counterpart of \code{RadixRun}. Keys are packed words $W$ whose
most-significant-first lane order is the \textsc{IX-OrderKey} embedding
(\textsc{DL-DevicePacking}); they are stored whole. A stable
least-significant-lane radix permutation clusters occurrences into distinct
keys $D$, offsets $O$ of the carrier type selected upstream (builds whose
item count exceeds the carrier are rejected), and gathered item columns.
The directory is an exact radix prefix: for $r>0$ recorded bits, entry $p$ is
the first slot whose top $r$ bits of $k-\min D$ at the span's resolution are
at least $p$; a lower-bound search inside that bucket is exact, also for
absent keys. Reads over all published runs take the key/offset/directory view
only; item columns are a separate view. Ratio, directory bits and merge tile
size are caller parameters; grids follow \textsc{GPU-LAUNCH-OCCUPANCY}.

\Rule{GPU-RadixRun}{
 \mathsf{stableCluster}(I,K)=(D,O,V)\quad \mathsf{packedOrderKey}(K)\quad

 {\forall i.\ C_i'[j]=C_i[\pi(j)]\quad (C_1'[j],\ldots,C_m'[j])=I[\pi(j)]}
\end{mathpar}
Full-key set construction has a distinct witness: every complete key occurs
once, so its descriptor records implicit offsets $O[i]=i$ and stores no offset
lane or item-source map. Occurrence construction, including \code{C=()},
retains materialized group offsets. A shared offset accessor consumes the
descriptor's recorded representation; it does not inspect keys or infer
uniqueness. Diagnostic host downloads alone may materialize the unit offsets.


A \code{RadixLayout<K,V,W,O,C>} is the typed relational view of one

\paragraph{Canonical references.}
A canon result is stored in its \emph{canonical} index: an ordinary member of
the result's index set, chosen by index selection (SRDatalog's
\code{select\_indices}/\code{canonical\_index}). Structures records only a
reference to it, never a strategy, store or separate provider kind:
\code{r canon = rows;} names the result's rows record, whose provider build
yields distinct complete rows (\textsc{PL-Distinct}; default
\code{::cq\_storage::dedup::Sort}, the sorted array);
\code{r canon = [K];} names an existing one-level complete-row Built entry;
\code{r canon = host;} names the load-verified host carrier of a direct
complete host rename. \code{r head = Type;} types the answer relation's
identity index the same way; it exists exactly when Physical records the
return-boundary obligation (\textsc{PH-HeadDedup}).
\begin{mathpar}
\Rule{STR-Canon}{(c=\mathsf{rows}\land\mathsf{mode}(r)\ne pipe\land
  r\text{ records rows})\ \lor\\
 (c=[K]\land K\text{ is the full heading}\land\mathsf{mode}(r)=let\land
  \mathsf{built}(r)=\{[K]\}\land
  \text{every read of }r\text{ is existence-only and unscanned})\ \lor\\
 (c=\mathsf{host}\land\mathsf{mode}(r)=pipe\land\mathsf{directHostScan}(r)
 \land\mathsf{loadVerifiedPrefixCarrier}(r))}
 {\mathsf{canonical}(r,c)\text{ is admissible}}
\end{mathpar}
A Built reference is the result's only storage: its build need not be
duplicate-free, since existence reads observe support. The host carrier pairs
immutable rows with the exact prefix comparison verified at load. Rust checks
the carrier capability; the compiler checks the direct complete host-scan
shape, never a Rust type spelling. No projection, filter, join, computed head
or other downstream operator inherits this evidence. Full-row equality must
imply equal prefixes; equal-prefix runs are still sorted and uniqued by
complete-row identity: prefix order never establishes uniqueness. The
default rows provider \code{dedup::Sort} collects the complete boundary
stream, uses Rust \code{Ord} comparison via \code{sort\_unstable\_by}, then
adjacent unique; Tasks uses its parallel sort. Compared fields may be opaque
user Rust types, and wide rows need not implement a tuple-level \code{Ord} or
\code{Hash}. The order/identity laws remain representation premises.
Catalog selection may retype the rows provider to another \textsc{PL-Distinct}
provider, but never turn a host reference into rows.

Rows records are values, not shared buffers:
\begin{mathpar}
\Rule{STR-RowsByValue}{\mathsf{mode}(r)=let\quad

\end{mathpar}
A rows record is held as storage for an empty-key stream read that replays the
relation, or with more than one consumer (scan reads plus Built entries).
Filtered builds replay their direct source, so an unscanned filtered result
never holds rows; only a canon result's unheld rows record may sit beside
filtered storage.

Selection writes the reference:
\begin{mathpar}
\Rule{SEL-Canon}{r=\mathsf{canon}(\ldots)}

Returned results record \code{ret head = ::cq\_storage::dedup::Sort}.

Authored advice may record a different \textsc{PL-Distinct} rows provider.
\code{dedup::Packed} is the sorted run keyed by the packed \code{OrderKey} of
every column. Its build measures each column's ordinal span while collecting,
packs the span-relative ordinals most significant column first into one word
together with the row position, sorts the words and reads the rows in word

and identity are those of the tuple order the printed comparator denotes; it

\paragraph{Default hash representations.} Selection records
\code{::cq_storage::HashSet<_>} for general built membership and candidate-key
enumeration; membership-only projections use the adaptive provider above.
These sets answer consumer membership probes, not self-deduplication.
This alias names
\code{std::collections::HashSet<K, cq_storage::HashState>};
\code{HashState} uses keyed aHash. Payload reads record
\code{::cq_storage::HashIndex<'_,_,_>}; its definition uses the same fast
hash state. A deferred host membership fallback records token \code{keyset}
(\code{::cq_storage::dispatch::KeySet<_>}); its declared \code{choice 1}
argument is printed from the served reader's recorded Physical eager/lazy
choice (\textsc{STR-ReaderChoice}), so no spelling restates laziness. Its
key set uses that state. Trie levels and the staging and hash forms of
\code{AdaptiveKeySet} likewise fix their hash representation in the named
runtime type. The printer passes recorded provider tokens to capability
construction without choosing the resulting Rust implementation; retyping to
\code{std::collections::HashSet<_>} retains the standard hasher.
Counter builds retain their deterministic measurement collections and fixed
seeds; their hash-finish counts cover runtime internal collections and host
hash operations, not sort canonicalization. CPU Datalog's
\textsc{DL-InsertNew} uses the recorded canonical provider's membership and
insertion operations on the committed and round-local NEW layouts, not a
separate hash-seen store.

\code{HashIndex} stores exact keys and arena slots in a hashbrown Swiss table
using the recorded keyed hash state, plus a contiguous arena of first payloads.
Hash collisions always require full key equality.
Only keys with additional occurrences allocate a shared tail.
The directory and arena grow by doubling; once the first $2^{16}$ source rows
carry distinct keys, initialization reserves the source's remaining lower size
bound at once. That reservation never exceeds the footprint of the same rows
with distinct keys, and the stored keys, slots and buckets are unchanged.
Initialization consumes the source once, on first access, and is shared by
cloned handles. A standalone lookup cursor copies the first payload and owns
its tail; it survives dropping the index and advances independently.
Membership tests the directory directly, without constructing a cursor.
The \code{IndexRead::probe<N>} protocol has a scalar default and preserves outer
order, within-bucket source order and bag multiplicity. \code{HashIndex} realizes
\code{N=128} by hashing all keys, prefetching candidate buckets, then resolving
exact matches; \code{N=1} retains scalar demand with no lookahead or prefetch.
Both retain one index handle per stream and enumerate payloads without per-row
reference-count operations. An empty outer stream does not initialize the index.
For single-level probes over borrowed rows, the staging pass records the former
fixed lookahead as \code{stage = batch 128} on a total host scan spine
(rename, relational select/point/range and projection).
Section~\ref{sec:backend} gives the checked evaluation-unit decision; absent
stage entries mean scalar demand. Already-reduced/joined streams, opaque guards
and branches retain scalar demand by default; computed rows and curried access
retain their existing lookup protocol. The printer consumes the recorded
decision. No runtime statistics or adaptive choice is used, and bounded
lookahead preserves the recorded operator plan and free-variable bindings.
Candidate counts remain exact occurrence counts (upper bounds for distinct
candidate enumeration), without enumerating a bucket. Retained-capacity
counters account for the directory, arena and live tail buffers separately.

equal. Lineage, read coverage and summary obligations are rederived independently.
Retype selectors \code{kind(selection)} and \code{kind(keyset)} preserve origin,

includes keysets, not positional selections. Losing interval membership requires an explicit row-summary

\paragraph{Covered join filters.}
An entry \code{s join_filter = Type build b [k] covering j
marker ::cq_load::ColumnAt<n> policy P;} records a structure's Rust type, the scan
occurrence, the filtered key column, host key column and exact covering
operator. A scan may carry several entries, one per covering operator and key
column. The core neither classifies approximate algorithms nor recognizes their names.
\textsc{STR-JoinFilter} independently checks that \code{j} is an eager probe or
semijoin of \code{b} on a key $K\ni k$ served by a single-level exact key index,
that the build is total, and that the scan reaches \code{j} through an
exclusive pipe spine whose every result carries $k$: renames, projections,
declarative selections and left operands of eager probes and semijoins.
The recorded single-level key layout, not the provider's Rust type name,
establishes eligibility. Recorded \code{Keys} support describes the exact stored
key layout. With neither realization flag, projected \code{Build} consumes
\code{Keys::distinct\_keys} only after activation, the recorded default.
Source \code{run\_filter} and realization \code{borrowed\_filter} are distinct
provider facts. Explicit borrowing requires a scalar complete stored layout and
\code{RunFilterSource}. Explicit \code{attached\_filter} instead requires an
incremental \code{BuildSidecar} builder attached through the exact
\code{BuildWithSidecar} provider; the two realization facts are mutually
exclusive. Rust discharges these capabilities, not provider-name recognition.
Rows of the scan with $k\notin\pi_k(b)$ produce, along that spine, only rows
with the same $k$, which \code{j} drops; so the filter keeps a superset of the
rows \code{j} can keep ($R\ltimes b\subseteq\sigma_F(R)\subseteq R$). A key bound
only by an intermediate build is not a scan column and is rejected.
Retained, scoped, opaque and occurrence-expanding boundaries other than those
left operands are rejected. An anti join cannot cover
a filter. Removing the exact operator leaves an invalid entry: a conservative
filter can never be the only check of the constraint.

For the projected scalar keys $S$ supplied by distinct-key enumeration,
observed by attached construction or borrowed at publication, the capability laws are
\[
 \begin{aligned}
 T:\code{ConservativeMembership<K>} &: \quad k\in S\implies T.\mathsf{test}(k),\\
 T:\code{ExactMembership<K>} &: \quad k\in S\iff T.\mathsf{contains}(k).
 \end{aligned}
\]
Every exact type also implements conservative membership by a blanket
implementation. Neither capability is a uniqueness proof. Runtime weakening
to an always-true test is permitted by the one-sided law; false negatives are
never permitted. A conservative \code{may_contain_in(lo,hi)} may return false only
when the closed interval contains no build key. Its default retains every
block; the exact-to-conservative blanket uses this default. Missing host block
metadata also retains the block. Exact keyset reads retain their separate
\code{ExactIntervalMembership} capability. For sidecars rustc checks
\code{require::conservative::<K,T>}; borrowed \code{RunFilterView} implements
\code{ReadPredicate} only, avoiding overlap with the exact-membership blanket.
\code{RunFilterPredicate} wraps an optional borrowed view and preserves identity
when inactive. All three paths obey the same no-false-negative read law;
semantic provider laws remain premises.
External structures may supply stronger block summaries without changing the
covering obligation. False positives are eliminated by the unchanged probe.
For a positional static read directly over the rename/project spine, realization
intersects both block summaries and tests the static row predicate before the
join key. The optional counters \code{join_filter_tested} and
\code{join_filter_passed} measure that key-filter boundary; subsequent residual
conditions and relational readers can reduce the surviving count further.
\begin{mathpar}
\Rule{STR-JoinFilter}{
 j\in\{\mathsf{probe}[K](l,b),\mathsf{semi}[K](l,b)\}\ \text{eager}\quad
 k\in K\quad \mathsf{exactKeyIndex}(b,K)=P\quad
 \mathsf{declaresKeys}(b,K)\quad P:\code{Keys}\\

 \mathsf{totalBuild}(b)\quad
 \mathsf{marker}(s,k)=C\\
 \mathsf{recordedProjectedBorrowedOrAttachedBuild}(P,T,K,k)\quad
 \mathsf{conservativeReadLaw}(F,k)\quad
 \pi_k(b)\subseteq\{x\mid F.\mathsf{test}(x)\}
}{
 s\;\mathsf{joinFilter}(F,b,k,j,C)\text{ is admissible}
}
\end{mathpar}
Here $\mathsf{exclusiveSpine}_k$ contains only one-use pipe renames,
projections, declarative selections and left operands of eager probes and
semijoins, each carrying $k$, without canon or fused scopes; the scan's
lineage maps $k$ to a host column.
The selected source provider declares exact distinct-key enumeration through
\code{Keys}; the default projected realization consumes it only after activation.
Explicit borrowed and attached realizations satisfy their respective capabilities
without that enumeration. Any lawful implementation can satisfy these premises;
retyping must preserve the declarations and Rust trait obligations.
A routed token (STR-Routed) preserves exact key enumeration as well: each
complete key routes to exactly one native index, and enumerating all its native
keys gives the same global key support, including the one-index identity
representation. Its selected provider must still declare and satisfy the
\code{Keys} contract; a provider name alone does not establish support.
The filter's build, covering operator, scan lineage and marker obligations
remain unchanged.
A retained-cursor probe remains an exact covering read: its earlier eager
semi performed the same-key lookup. The original covering operator and its
exclusive-spine proof are retained, not redirected across an opaque Rust or
canonical boundary.
The recorded type is checked syntactically as a Rust type, and its capabilities
are checked by rustc, rather than by a provider-name whitelist. External
\code{retype(s join_filter => T)} changes only the recorded types of that scan.
\code{join_filter(s)} may explicitly add default exact structures for every
admissible covering operator of \code{s} not yet recorded (including total
unfiltered builds); it records positional-host advice and undergoes the same
contract and correspondence checks.
Every entry records exactly one activation policy $P$:
\code{always}, or \code{abandon p of B keys S}, which activates the filter only
while the covering build's exact key count read through $S$ is at most $p\%$ of
the positional base $B$. $S$ is \code{key\_count} (\code{Keys::key\_count}) or a
declared exact optional Keys statistic accessor, whose absence selects identity.
\textsc{STR-FilterPolicy} checks legality only; which policy is profitable
belongs to \textsc{SEL-FilterPolicy}, and the checker does not rerun it.
\begin{mathpar}
\Rule{STR-FilterPolicy}{
 P=\mathsf{always}\ \lor\ \bigl(P=\mathsf{abandon}(p,B,S)\quad 1\le p\le 100\quad
 \mathsf{lineageBase}(b)=B\in\mathsf{positionalBases}\\

\subsection{Authored CPU blocked scan bindings}

The optional \code{blocks} packet belongs to the existing encoded contract.
It adds source geometry and schema-slot obligations, scan representation
references, exact predicate decisions, and consumer reads. It does not own
another family or domain table: every column refers to an encoded declaration
and representation identity. The explicit selection spelling is
\code{blocks(R \{ block\_rows 1024; summary none; columns [a: bytes u64]; \})}.
All source columns must appear exactly once. Family and native carrier are
authored provider premises, never inferred from a Rust type or expression.
Logical type and code-domain identities come from the actual declaration
table. The native carrier is a rustc/provider obligation. The runtime checks
the immutable table binding, aligned lengths, geometry, domain and snapshot.

\begin{mathpar}
\Rule{STR-Blocks}{
 \mathsf{scan}(o)=R \quad
 \mathsf{schemaSlots}(R)=\mathsf{slots}(B) \quad
 \mathsf{logicalIds}(R)=\mathsf{logicalIds}(B)\\
 \mathsf{serves}(P,o) \quad
 \mathsf{repr}(c)=(P,R,o,c,s,d,\mathsf{S1},f,w) \quad
 f\in\{\mathsf{Plain},\mathsf{Bytes}\}\\
 b>0 \quad b\bmod1024=0 \quad b\leq 2^{32}-1 \quad
 \mathsf{widths}(\mathsf{Plain},w)=\{w\} \quad
 \mathsf{widths}(\mathsf{Bytes},w)=\{0,1,2,w\}\cap[0,w]
}{
 B,o \vdash \mathsf{blockedScan}(R,s)
}
\end{mathpar}
The abstraction concatenates decoded blocks in original occurrence order.
Summary capability means an enclosing min/max for that same immutable source.
Geometry and permissible physical widths are checked independently of the
encoder; the actual residual width remains runtime header data. Domain
namespaces reify explicit binder identities, scoped by this source provider:
logical-only $i$ maps to $2i+1$, code-domain $d$ to $2d+2$, with the declared
dictionary version or zero. This is not a cross-query dictionary equivalence.

     \Rightarrow \mathsf{monotone}(E)) \quad

Equality includes inequality and membership; order requires monotonicity.
Plain and Bytes advertise both laws. Missing dictionary literals remain Empty
for equality and insertion ranks for order under RT-Translate; integers from
different code domains are not comparable merely because their widths agree.
The record names the original Physical predicate, including every conjunct,
disjunction arm and cross-column comparison. Window and Point are checked
exact templates; Formula retains the entire algebra, with pruning disabled
and an explicit physical decode-to-global-code test. Each demanded column is
read once for the live row before evaluating the full formula. Necessary unary
envelopes cannot discharge a correlated formula. Window and Point admit both
encoded residual testing and explicitly selected physical decode-to-code tests.
Adding a frame base reconstructs a global ordinal, not an authored Rust value.

\paragraph{Reads, ownership and the checkpoint boundary.}
Each opaque Bind/Guard records exactly its original free-variable demand,
excluding already-owned computed fields. Owned reads construct scoped values;
borrowed temporary reads are permitted only for Guard, never escaping into a
Bind or final answer. Genuine final reads name the actual answer and exact
head demand; a Physical return alone does not establish final publication.
An outer compiler may instead transport a checked consumer requirement
$(c,H,V)$: original consumer identity, ordered head-variable identities, and
the subset read for logical values by its checked Context. Structures binds
this requirement once, independently of representation choices. Its head
must match the Physical head, including captures hoisted outside row headings.
It neither implies canonicality nor discharges the original set boundary.

For such an external consumer, base fields in $H\setminus V$ receive a
\code{PreserveCarrier}/\code{Ordinal} packet naming $c$. These are global
injective \emph{value codes}: $E(x)=E(y)\iff x=y$ under the original source,
domain, snapshot and S1 equality law. Neither occurrence positions nor
block-relative residuals satisfy this obligation, and no primary-key premise
is required. Already-owned computed fields retain their original carrier;
captures remain host values and require no row read. Logical demands in $V$
belong to the separate \code{OpaqueRustRead} role, never
\code{FinalHostAnswer}. At this checkpoint external consumers may read
computed values or captures only: an encoded base-value demand is rejected
until a checked borrowing/ownership protocol can serve the outer fold.
An owned reconstruction cannot be passed to a consumer expecting a borrowed
source field. Internal Bind/Guard reads still use their authorized opaque
Rust reads, including arithmetic that computes an outer measure.

The checker derives both exact role packets directly from $(c,H,V)$ and
Physical row/capture identities, checks field lineage and injectivity, and
rejects extra, missing or reassigned fields. Correspondence preserves the
original requirement, rejecting simultaneous edits to it and its selected
packets. The printer emits the selected actions; it does not infer consumers
or reconstruct ignored values.

Canonical reads name the canonical result with purpose
\code{PreserveCarrier} and action \code{Ordinal}, covering every noncomputed
logical heading field. They authorize no inverse codec. Canonical equality is
equality of the full logical heading (ordinal keys plus owned computed values),
not equality of occurrence positions; equal witnesses at different positions
still deduplicate by value. Comparator rows are explicitly selected for this
boundary, with one position retained after dedup.

The first executable checkpoint carries \code{Repr::Positions} through Rename,
Project, every declarative predicate, Bind and Guard, and comparator canonical
rows. A Group may consume owned computed operands. A group key or aggregate
argument that reads an encoded base field is rejected before printing; it
requires a future explicit relational carrier/group protocol, not an opaque
read or an inverse-codec fallback. Computed-only grouping remains supported.
Any blocked occurrence reaching a join, index, noncanonical
retained store, fused scope or restricted Rename (source atom literals) is
rejected by the Structures checker before printing. A blocked source also
rejects runtime \code{host\_set} certification through the borrowed-row
protocol; an already-discharged uniqueness premise remains admissible.
This is an explicit checkpoint boundary, not a
claim of complete blocked join/index support. Unknown and unadvised hosts keep
the prior Structures decisions. Correspondence checks Physical preservation;
the language checker derives source, predicate, canonical and consumer
coverage independently, without invoking selection or requiring its preferred
Plain/Bytes, pruning or code-test choice.
