\section{Physical lowering through native Access refinement}
\label{sec:access-refinement}
This section specifies the implemented direct physical edge. It accepts named RA
and emits Rust containing existing Access plans; it does not add a whole-program
language. Its current domain consists of \code{i64} array rows, Unit, Rename,
Project, Semijoin and NaturalJoin, with variable-only output of at most twelve
fields. The generic RA language and canonical physical edges retain their own
domains. In particular, compiling one integer fact-star instance does not establish
support for arbitrary host expressions or all declared Rust types.

\subsection{Logical valuation and compiler-local information}
For input database $I$, let $D_I(r)$ denote the set assigned to named RA result $r$.
No physical information is needed to define $D_I$. During lowering, the compiler
additionally maintains
\[
 \Gamma(r)=(P_r,e_r,\ell_r),\qquad
 \mathcal M(r,s,Q)=e_K.
\]
Here $P_r$ is a selected row-provider macro, $e_r$ a dominating Rust value, and
$\ell_r$ its ordered layout. $s$ is the sorted shared heading, $Q$ a selected
configured key-resource macro. Its lexical binding closes over its collection and
other implementation choices. The resource map records an
already constructed Rust value $e_K$. These are ordinary compiler data structures;
there is no serialized environment, fresh logical resource relation, or additional
RA operator. The representation premise is
\[
 \gamma_{P_r}(e_r,\ell_r)=D_I(r).
\]
Rename inherits the input representation; Semijoin inherits the left representation
and selects handles. Unit, Project and NaturalJoin materialize using a selected
result provider. Positions are derived from headings and layouts, not repeated in
an intermediate query syntax. Resource reuse requires the same \emph{current RA
version} $r$, $s$ and configured binding $Q$. Path spelling is a conservative
identity in a fixed lexical scope, not equivalence discovery between aliases. The candidate-scan policy is absent from this key.
The implementation does not infer equivalence of differently named versions or
reuse a stale superset without a separate proof.

\subsection{Native operation syntax and local contracts}
The fragment grammar belongs to \code{cq-ir::physical_provider}. Its relevant
extension is
\[
\begin{array}{rcl}
 o&::=&\mathsf{build}\ \{A\}\\
  &\mid&\mathsf{contains}\ (e_K)\ (e_k)\\
  &\mid&\mathsf{may\_match}\ (e_K)\ (e_B)\ (e_c)\\
  &\mid&\mathsf{probe}\ (e_W)\ (e_k)\\
  &\mid&\mathsf{candidates}\ P\ \{e_v\}\ (e_m)\\
  &\mid&\mathsf{materialize}\ x_o\ x_v\ (e_A).
\end{array}
\]
$A$ is an existing Access plan; $P$ a Rust macro path; the $e$ terms are native
Rust expressions. Other provider fragments implement type, input, row, scan,
selection and block operations. Materialization binds an owner $x_o$ and represented
view $x_v$ from the support of its row iterable $e_A$. The selected frontend parses this
typed syntax and administrative options separately. Storage paths, continuations,
collection types and optional observations are bound by configured lexical macros;
they are not part of each operation's denotation. A block materializer additionally
requires a bound packing-size expression; the generic operation carries no size
operand. Its row expression and packing expression each evaluate once at
construction. Non-materializing operations do not evaluate packing configuration.
Native materializers collect the row support into their own set representation.

For a current view $v$, write $H(v)$ for its selected handles and $\rho(h)$ for the
represented row. Handles are decoded against their originating view; block handles additionally
carry store identity and coordinates. A lawful provider enumerates current handles
once. Candidates pass those handles unchanged to selection, whose result represents
exactly their rows. A block selection retains the original payload, while native
sets may copy survivors into a new set with different physical addresses. Neither
may resurrect a row removed from the current view. Let
\[
 K=\{\rho(h)|_s\mid h\in H(v_r)\},\qquad
 p_K(h)\equiv\rho(h)|_s\in K.
\]
Exact key construction establishes $\mathsf{contains}(e_K,k)\Leftrightarrow k\in K$.
For a candidate producer $C$ and metadata predicate $m$, its required law is
\begin{equation}\label{eq:candidate-cover}
 \{h\in H(v_l)\mid p_K(h)\}
 \subseteq \set(C(v_l,m))\subseteq H(v_l),
 \qquad C(v_l,m)\text{ has no duplicate handles}.
\end{equation}
This law is relative to the exact residual $p_K$. It is not a promise that an
arbitrary metadata predicate is safe, nor that candidates alone denote a semijoin.

\paragraph{Zone metadata.}
For nonempty $K$, coordinate summary $Q_K(j)$ encloses every key coordinate $j$.
For immutable block $b$, $B_b(c)$ encloses the original payload coordinate $c$.
Writing $c_j$ for the left physical position of shared field $j$,
\[
 m_K(B_b)= (K\ne\varnothing)\ \land\
 \bigwedge_j\bigl(Q_K(j).\min\le B_b(c_j).\max
              \land B_b(c_j).\min\le Q_K(j).\max\bigr).
\]
A block containing a row whose key lies in $K$ necessarily passes this test.
The original block bounds also enclose every current selected subset; recomputing
tight bounds is unnecessary for soundness. An empty $K$ rejects all blocks. For
zero shared fields, a nonempty $K$ contains the empty key and the empty conjunction
is true. Composite keys still require exact tuple membership: coordinate overlap
cannot prove that one RHS tuple supplies all matching coordinates.

\subsection{Implementation rules}
Write $A_r$ for an Access scan of the current $\Gamma(r)$ and $\pi_s A_r$ for
projection in its native output expression. This notation introduces no named RA
Project. $\operatorname{supp}$ denotes the set of values in a stream.
Each rule below maps to an implementation symbol in \code{rules.tsv};
\code{physical_rules.tsv} additionally maps it to the algorithm using it.
Provider laws and adequate Rust expansion remain premises of these rules.

\begin{mathpar}
\Rule{AF-Bind}{\gamma_P(e,\ell)=D_I(r)\quad e\text{ dominates its uses}}
 {\Gamma[r\mapsto(P,e,\ell)]\text{ represents }r}
\and
\Rule{AF-Build}{\Gamma(r)=(P,e,\ell)\quad s\subseteq\att(r)\\
 Q.\mathsf{build}(\pi_s A_r)\text{ establishes exact }K}
 {\operatorname{emit}(e_K=Q.\mathsf{build}\{\pi_s A_r\});\quad
  \mathcal M[(r,s,Q)\mapsto e_K]}
\and
\Rule{AF-Reuse}{\mathcal M(r,s,Q)=e_K\quad
 e_K\text{ is immutable, live and established}}
 {\operatorname{resource}(r,s,Q)=e_K}
\and
\Rule{AF-Keys}{K=\operatorname{supp}(A)\quad
 T\text{ collects exact key membership}}
 {\mathsf{exact\_keys}_T.\mathsf{build}\{A\}\Downarrow e_K
  \quad \mathsf{contains}(e_K,k)\Leftrightarrow k\in K}
\and
\Rule{AF-Zones}{K=\operatorname{supp}(A)\quad
 T\text{ collects exact keys}\quad Q_K\text{ observes all of }A}
 {\mathsf{zone\_keys}_T.\mathsf{build}\{A\}\Downarrow(e_K,Q_K)
  \quad \mathsf{contains}\text{ exact}\quad m_K\text{ conservative}}
\and
\Rule{AF-Scan}{P.\mathsf{rows}(v)\text{ enumerates }H(v)\text{ once}}
 {\mathsf{scan\_rows}.\mathsf{candidates}\ P\{v\}(m)
  \Downarrow P.\mathsf{rows}(v)}
\and
\Rule{AF-Prune}{P.\mathsf{blocks}(v)\text{ partitions current handles}\\
 \neg m(B_b)\Rightarrow\forall h\in H(v)\cap b,\ \neg p_K(h)}
 {\mathsf{prune\_rows}.\mathsf{candidates}\ P\{v\}(m)
  \Downarrow\mathop{\mathrm{concat}}_{b:\,m(B_b)}P.\mathsf{block\_rows}(b,v)}
\and
\Rule{AF-Semi}{K=\pi_s D_I(r)\quad \Gamma(l)\text{ represents }l\\
 C,m,p_K\text{ satisfy }\eqref{eq:candidate-cover}}
 {P_l.\mathsf{select}(v_l,\{h\in C(v_l,m)\mid p_K(h)\})
  \simeq D_I(l)\ltimes D_I(r)}
\and
\Rule{AF-Hash}{A\text{ enumerates }(\mathsf{key}(x),x)\text{ once per current }x}
 {W=\mathsf{hash\_witnesses}.\mathsf{build}\{A\}
  \quad W.\mathsf{probe}(k)=\langle x\mid(k,x)\in A\rangle}
\and
\Rule{AF-Nested}{A\text{ is lawfully repeatable and enumerates current rows once}}
 {W=\mathsf{nested\_witnesses}.\mathsf{build}\{A\}=\lambda().A
  \quad W.\mathsf{probe}(k)=\langle x\mid(k,x)\in W()\rangle}
\and
\Rule{AF-Join}{W.\mathsf{probe}(k)\text{ enumerates exactly RHS witnesses}\\
 A=\langle a\cup b\mid a\in D_I(l),\ b\in W.\mathsf{probe}(a|_s)\rangle}
 {\operatorname{supp}(A)=D_I(l)\bowtie D_I(r)}
\and
\Rule{AF-Store}{\operatorname{supp}(A)=D_I(t)\quad
 P.\mathsf{materialize}(A)\text{ establishes a live owner and exact view }v}
 {\gamma_P(v,\ell_t)=D_I(t)}
\and
\Rule{AF-Stream}{\operatorname{PipelineWF}(p)\quad p=p_0;d\\
 d=\mathsf{Distinct}(u)\text{ is the sole-use terminal node}}
 {\operatorname{stream}(p)=\operatorname{iter}(p_0,u)\quad
  \operatorname{supp}(\operatorname{stream}(p))=\sem p}
\and
\Rule{AF-Realize}{\operatorname{RAWF}(D)\quad D\text{ is in the declared domain}\\
 \text{each definition preserves }\Gamma\text{ by the preceding rules}}
 {\operatorname{physical}(D;\text{options})=\mathsf{Rust}[\mathsf{Access}]
  \quad \operatorname{answer}=D_I(\operatorname{output}(D))}
\end{mathpar}
AF-Stream emits the pre-Distinct iterator sequence $\operatorname{iter}(p_0,u)$:
it removes the terminal node from the implementation, not from the validated
source language. The canonical iterator endpoint retains Distinct; the set endpoint
folds it into collection. Exact collection preserves support under repeated keys,
and lawful summaries continue to cover every observed key. The stock coordinate
summary is additionally idempotent. Semijoin selection consumes handles directly
into its mask or set, without an intermediate handle HashSet. Candidate and witness
traversals rely on unique provider enumeration and preservation of the pre-Distinct
sequence; support equality alone would allow an arbitrary endpoint to duplicate
values. A key collector that consumes only a prefix cannot establish AF-Keys.
Zone construction drains its observation stream after collection so metadata
covers all source keys, but this does not repair an inexact key collection.
AF-Store requires ownership to dominate consumption: the generated witness owner
and operand references remain in the enclosing definition scope until the result
provider has consumed the join stream. Returning an iterator from an inner scope
that owns its witness resource would violate this premise. For block storage,
materialization collects unique rows and then calls the selected build trait with
its bound size, evaluated once. Size changes layout, not the represented row set.

\subsection{Algorithms and where control is emitted}
\begin{algorithm}[t]
\caption{Direct RA realization with compiler-local $\Gamma,\mathcal M$}
\label{alg:access-direct}
\begin{algorithmic}[1]
\Require Valid admitted RA and explicit physical options
\State Derive layouts, field positions and inherited providers (AF-Bind)
\State Group semijoin demands by $(\text{current RHS},s,Q)$
\For{definition $t=o$ in RA dependency order}
 \For{key resource demanded by this definition}
  \State At first use, emit projected-current-RHS Access construction (AF-Build)
  \State Otherwise use the established identical resource (AF-Reuse)
 \EndFor
 \If{$o=l\ltimes r$}
  \State Emit Candidates followed by exact Contains in one Access plan (AF-Semi)
  \State Select the resulting handles in the current left view
 \ElsIf{$o=l\bowtie r$}
  \State Bind RHS witness ownership before left-driven Probe Access (AF-Join)
  \State Materialize the set of joined rows with the result provider (AF-Store)
 \ElsIf{$o$ is Unit or Project}
  \State Construct the unit set or projected Access and materialize (AF-Store)
 \Else \State Bind the renamed input view (AF-Bind)
 \EndIf
\EndFor
\State Emit selected continuations and the result API (AF-Realize)
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{Independent native expansion procedures selected by lexical aliases}
\label{alg:access-leaf}
\begin{algorithmic}[1]
\Procedure{ExactKeys}{$o$}
 \State Expand Build to exact collection, or Contains to membership (AF-Keys)
\EndProcedure
\Procedure{ZoneKeys}{$o$}
 \State Expand Build to exact keys and bounds; Contains/MayMatch use them (AF-Zones)
\EndProcedure
\Procedure{ScanRows}{$\mathsf{candidates}\ P\{v\}(m)$}
 \State Emit current Rows; discard metadata predicate tokens (AF-Scan)
\EndProcedure
\Procedure{PruneRows}{$\mathsf{candidates}\ P\{v\}(m)$}
 \State Emit Access: Blocks, metadata guard, current BlockRows (AF-Prune)
\EndProcedure
\Procedure{HashWitnesses}{$o$}
 \State Expand Build to buckets, or Probe to exact bucket iteration (AF-Hash)
\EndProcedure
\Procedure{NestedWitnesses}{$o$}
 \State Expand Build to a closure, or Probe to repeated scan/filter (AF-Nested)
\EndProcedure
\Procedure{StreamPipeline}{$p$}
 \State Emit its pre-Distinct sequence with the support law (AF-Stream)
\EndProcedure
\end{algorithmic}
\end{algorithm}
These procedures are independently invoked implementations, not branches of a
central chooser or runtime catalogue. Lexical macro selection determines which
procedure is called. Each nested Access plan uses the existing checked Pull edge
and its configured Pipeline endpoint. Implementation modules are
\code{cq-access::candidates::scan}, \code{candidates::prune},
\code{keys::exact}, \code{keys::zone}, \code{witnesses::hash} and
\code{witnesses::nested}; each exposes its own \code{compile} entry.
Provider modules \code{cq-providers::hash}, \code{sorted} and \code{block}
own coherent representation protocols. No Boolean strategy dispatcher selects
among these implementations.

\paragraph{Selection and expansion.}
AF-Scan discards unused predicate tokens, so it does not require a \code{may_match}
implementation. AF-Prune expands the block operations and metadata predicate.
Forcing pruning on a native row provider fails at unsupported operations or Rust
trait checking; selecting exact-only keys for pruning fails at \code{may_match}.
There is no silent fallback or global capability registry. The generated Rust
contains ordinary iteration, guards, collection and borrowing. \code{cq-storage}
contains immutable payload and metadata, independent selections, operation traits,
summaries and passive counters; it does not execute relational operators.
The plain direct host emits an unobserved \code{run}; the explicitly selected
observed host emits a \code{run} returning the answer and statistics. Only the
observed host supplies the optional \code{work (expression);} prefix to runtime
operation bindings; type operations remain plain. Implementations discard unused
observer expressions, including candidate scan and deferred witness construction.
Counter definitions belong to the observed host and do not select relation storage.
Neither host requires a global packing-size argument. Callable hosts can capture
ordinary caller values used by configured packing expressions.

\subsection{Preservation and evidence}
\begin{lemma}[Exact completion of candidates]
If exact membership and \eqref{eq:candidate-cover} hold, candidate traversal followed
by its exact residual denotes the semijoin on the current operand versions.
\end{lemma}
\begin{proof}
Every emitted handle belongs to the current left view and passes exact membership,
so it has a current RHS witness. Conversely, every current left handle with such a
witness belongs to the candidate set and passes the residual. No handle is emitted
twice. The provider's selection law therefore establishes precisely the reduced
view, including empty relations and empty separators.
\end{proof}
\begin{lemma}[Conservative zone rejection]
The coordinate overlap predicate above satisfies AF-Prune when bounds enclose
the original block and the summary encloses every current RHS key.
\end{lemma}
\begin{proof}
If a current row $h$ has a matching RHS key $k$, then at every shared coordinate
$k_j$ belongs both to $Q_K(j)$ and to $B_b(c_j)$ for the block containing $h$.
Their intervals overlap. Thus rejecting a block cannot reject any exact match.
Restricting the view cannot invalidate enclosure by its original block bounds.
\end{proof}
\begin{theorem}[Conditional direct-edge preservation]
For admitted RA, lawful selected providers, correct layout/resource wiring, total
pure host operations and adequate Rust expansion, direct lowering preserves the
set result of every definition and the ordered output tuple.
\end{theorem}
\begin{proof}
Induct on RA definition order. Input bindings and materialization establish their
representation relations. Resource construction uses the established current RHS;
reuse preserves that meaning and lifetime. The first lemma proves Semijoin, while
exact witness enumeration proves NaturalJoin. Unit, Rename and Project use their
ordinary set laws. Derived output positions preserve the authored tuple order.
\end{proof}
The independent emitted-code audit checks the supplied lowering's source bindings,
field maps, resource identity, lexical selections and ordering. Native operation
checks and Rust compilation address separate boundaries. Neither establishes the
semantic laws of arbitrary user macros or complete Rust contextual adequacy.
\code{physical_model.py} exhaustively checks a finite candidate/mask model against
an independent nested-loop oracle, including unchanged original metadata and
composite/empty keys. It is bounded semantic evidence, not a proof of generated
Rust, an optimizer model, or a runtime query interpreter.
