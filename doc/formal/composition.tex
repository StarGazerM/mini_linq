\section{Pass protocol and composition}
\label{sec:composition}\label{sec:staging}
A macro invocation carries a complete program and an explicit queue of remaining
pass paths, each with argument tokens read only by that pass.
\begin{mathpar}
\Rule{ST-Entry}{\pi=\mathsf{resolve}(configuration,defaults)\quad\pi\ne[]}
 {\code{mini_linq::compile!}\{configuration;\ T\}
  \longrightarrow\mathsf{start}(\pi,T)}

\Rule{ST-Next}{\operatorname{parse}_L(T)=s\quad\mathsf{WF}_L(s)\\
 f(s,args)=t\quad\mathsf{WF}_M(t)\quad M\ne Rust\quad\pi=k(args')::\pi'}
 {\mathsf{pass}_f(args,\pi,T)
  \longrightarrow k!\{args';\ \pi';\ \mathsf{quote}(t)\}}

\Rule{ST-Context}{\mathsf{pass}_f(args,\pi,\mathsf{quote}(s))\longrightarrow T'}
 {C[\mathsf{pass}_f(args,\pi,\mathsf{quote}(s))]\longrightarrow C[T']}

\Rule{ST-Sequence}{q=\mathsf{sequence}(s)\quad\mathsf{check}(s,q)\\
 \mathsf{checkGrading}(q,host)\quad e=\mathsf{translatePull}(q)\quad\pi=[]}
 {\mathsf{sequence};\mathsf{sequential};\mathsf{translatePull}(s)
  \longrightarrow\mathsf{quote}_{Rust}(e)}

\Rule{ST-Endpoint}{e=\mathsf{declaredPrintInput}(configuration,defaults)\\
 e=\mathsf{Structures}\Rightarrow\neg\mathsf{authoredSequence}(configuration)}
 {\mathsf{resolve}(configuration,defaults)\text{ includes Sequence phases iff }e=\mathsf{Sequence}}

\Rule{ST-Observe}{\pi_b=\mathsf{prefix}_b(\mathsf{resolve}(c,d))\quad
 \mathsf{checkedRun}(\pi_b,s)=t}
 {\mathsf{observe}(b,r,c,s)\longrightarrow r!\{\mathsf{quote}(t)\}}

\Rule{ST-Realization}{K=(c,v)\ \lor\ K=(p,s[,q])\\
 K=(c,v)\Rightarrow\mathsf{checkVO}(c,v)\\
 K=(p,s[,q])\Rightarrow
  (\mathsf{checkStructures}(p,s)\land(q\in K\Rightarrow\mathsf{checkSequence}(p,s,q)))}
 {\mathsf{admitStack}(K)}

\Rule{DR-Explain}{b\le h\quad
 \mathsf{observe}(b,\code{core::stringify},\varnothing,s)=a_b}
 {\mathsf{explain}(s,\mathsf{through}=h)[b]=a_b}

\code{cq_stage::pass} checks source and target contracts; \code{cq_stage::rewrite}
also runs the language's \code{check_rewrite}. Correspondence checks belong to the
pass. Failures emit one Rust expression block containing one
\code{compile_error!}; combined checker/candidate messages retain their order
and use the first diagnostic's span. The rejection does not invoke a printer
or leak adjacent diagnostic macros into expression syntax. On success, rustc
checks types, ownership and trait obligations of the generated code.
The VO continuation carries $(c,v)$: CQ and its valuation annotation are
separate programs. VO consumers receive $(c,v,args)$ and rewrites return both.
The selected printed VO contains only its valuation, never the CQ prefix.
From Physical onward a continuation carries the realization stack:
$p$, $(p,s)$, or $(p,s,q)$. Each member is a separately printed program.
ST-Realization checks that annotation references resolve in the separately
supplied upper programs before a consumer runs and after a producer returns.
Structures consumers take $(p,s,args)$; Sequence consumers take $(p,s,q,args)$.
Rewrites return all stack members, including any legitimately changed upstream
provider facts. Ordinary language contracts and rewrite correspondence remain
unchanged. Authored programs initialize the stack in dependency order; subsequent
continuations always print the separate stack. Observation and calibration
describe only the selected annotation, not its transport envelope.
\begin{lstlisting}
pipeline {
    surface = [Path(tokens), ...];
    plan = Path(tokens); ix = Path(tokens); lower = Path(tokens);
    physical = [Path(tokens), ...]; select = Path(tokens);
    structures = [Path(tokens), ...];
    represent = Path(tokens); stage = Path(tokens);
    sequence = Path(tokens); decompose = [Path(tokens), ...];
    grade = Path(tokens); print = Path(tokens);
}
\end{lstlisting}
The order is surface, plan, ix, lower, Physical rewrites, select, Structures
rewrites, represent, stage, sequence, decompose, grade, print. The shipped defaults
are \code{plan}, \code{index_demands}, \code{lower}, \code{select},
\code{represent}, \code{stage}, \code{sequence}, \code{plan_sequential},
\code{sequential}, and \code{translate_pull}. The default decomposition
\code{plan_sequential} is selected during configuration resolution, only when
sequence, grade and decomposition are implicit and no plan, Physical rewrite,
selection, Structures rewrite, representation or staging advice is authored.
An authored decomposition replaces that default. ST-Entry executes the resolved
queue unchanged: no pass-name matching or insertion occurs after resolution.
ST-Sequence is the terminal CPU path; decomposition is a list of Sequence rewrites.
The typed \code{print_input = structures} terminal declaration bypasses
default Sequence phases and rejects authored sequence, grade, or decompose
phases. Otherwise the configured/default Sequence phases are retained.
The invariant is that aliasing a terminal cannot alter its input language:
no macro path spelling participates in resolution. Each pass declares its
actual source and target through \code{pass<L,M>}; those checked boundaries
reject a terminal whose actual language disagrees with its declaration.
\code{translate_pull} emits both ordinary and profile-counter variants.
The workload corpus and fuzz configuration use this target by default.
An authored fact-free program may enter at any compatible macro with
\code{arguments \{..\}; pipeline \{..\}; <program>}. Passes receive no
configuration beyond their arguments: every choice is in the program text.

\paragraph{Diagnostic stage observation.}
The facade accepts \code{observe \{ boundary = grade; stage = ::core::stringify; \}}
before the ordinary \code{pipeline \{..\}} configuration. The selected boundary
is an output of the same resolved queue, with all preceding arguments and
rewrites unchanged: \code{cq}, \code{relational_plan},
\code{index_requirements}, \code{physical}, \code{structures},
\code{represent}, \code{stage}, \code{sequence}, \code{decompose},
\code{grade}, or \code{final_rust}. Physical and Structures observation includes
their configured same-language rewrites. A boundary absent from a selected
terminal route is rejected. CQ observation checks the source after surface
expansion. Complete Sequence input admits Sequence, decomposition/planning,
grading and terminal observation only.

The additional \code{vo} boundary exposes the default planner's shared checked
valuation prefix: $\mathsf{plan}=\mathsf{elaborate}\circ\mathsf{prefixValuation}$.
It requires an omitted CQ planning phase, rather than guessing the internal
language of an authored planner from its path. Custom planners must expose their
own internal boundaries.
The continuation carries \code{pipeline \{..\} observe \{receiver\}} until the
prefix ends. Source, target, correspondence and context checks still precede
observation. The receiver gets the payload alone, not the continuation envelope.
Even terminal Rust is captured after translation, before rustc type-checks or
executes that expression; diagnostic output is not Rust execution evidence.
The workload \code{explain} command generates these facade invocations for
each boundary through the requested stopping point, preserving earlier artifacts
and reporting the first failing boundary. It owns no second planning composition.


\paragraph{Programmatic GPU driver inputs.}
The TPC-H catalog resolves workload labels to serializable pipeline facts before
compilation. The compiler receives no workload/profile label. Its input records
\code{target = device | host}, \code{publication = host | device}, and a
\code{recipe} containing retention selectors, membership choices, expansion
selectors, partition/segment sizes and items. Missing target means device;
missing publication means explicit host publication. The automatic recipe
selects the shared rule-based planner; an absent schedule selects decomposition.
Completed replay pipelines contain expanded invocations and Sequence advice,
with the recipe cleared; the report retains the original recipe separately.

DR-StageSource is the TPC-H frontend boundary. Each query has an authored
\code{queries/<name>.stages} program: table/dictionary/opaque-host producers,
named captures (including date operands), CQ stages, owned publications and
ordered terminal projections. Input bindings identify preceding publications
or declared producers; no Rust source file is traversed. The checker compares
declared schema tokens and domain identities, never interprets types or
reconstructs producer expressions. Dictionary domains reach shared CQ
operand normalization; host code-domain conversion uses the shared runtime
domain interface. A date payload executes on the host, not in the compiler.
Terminal projections consume stored column slots and explicit dictionary
publication domains; constants are opaque host-once values. Stage-source text
is retained beside per-stage Sequence and publication records.

DR-ProjectedSet is an IO boundary, not compiler evidence: every compiler input
already denotes a set. The ordinary resident loader and compressed catalog
select representatives of complete projected rows before encoding and upload.
Unequal column lengths are rejected. A strictly increasing projection needs no
row-selection buffer; otherwise row indices are sorted and deduplicated, and
already-unique projections keep their original columns without copies.
Only identical ordered projections share immutable resident tables. Independently
checked duplicate-free projections also share unchanged base-column allocations;
survivor-selected projections never reuse those full-row allocations. Repeated
column names share their one allocation within a projection. DR-ProjectionReuse
uses the measured distinctness of a cached subset of columns to establish
distinctness of a larger projection, without rereading cached columns. It
uses neither authored keys nor column types. Independent column caching alone
cannot establish projected-row uniqueness. Domain encoding in the compressed
catalog is injective on the loaded values and preserves this set.
DR-HostSet canonicalizes the actual typed tuples, including host fallback.
DR-PreparedSet canonicalizes opaque-host and dictionary producers after their
final domain adaptation, once before stage execution. Earlier stage publications
are already engine set outputs and are not canonicalized again at load time.
All these operations occur outside query timers; no trusted-key declaration or
compiler context fact substitutes for canonicalizing the supplied rows.

DR-Target propagates rejection unchanged: it never retries another machine or
deletes authored advice. DR-Publication derives extrema validity from aggregate
kinds and propagates recorded nullable columns through publication inputs, not
from Rust type spelling. Nullable outputs use the host transfer protocol;
device publication without validity support is rejected. Generated carriers
and downstream input bindings consume the same recorded placement.
DR-GroupedPublication records a resident grouped answer's conversion: the
column slots and each key's bounds source (resident column metadata or one host
scan of a host relation; aggregates and keys without input bindings take the full
domain). Table loader placements follow the selected target; staged inputs carry
their producer's publication placement. Missing input placements are errors.
Independently of the producer, the checker requires each slot to name its head
argument's key or aggregate, and each input bounds record to bind that key at
the named positive atom field with residency equal to the recorded input
placement. Input bounds on aggregate slots are rejected. The wrapper prints
that record; it adds no device fence, and its timing remains host wall time.
DR-Recipe uses only explicit selectors and geometry, applying the existing
checked rewrites. Workload labels occur only in catalog registration.
DR-Registry shares one Physical/Structures registry between proc-macro adapters
and programmatic execution. It accepts registered bare names and
\code{cq_rewrites::name} paths; unknown paths are errors rather than suffix
aliases. Argument packets use \code{cq_stage::Invocation}; planning arguments
use \code{cq_planning::PlanOptions} and the shared Plan-Prefix composition.

\paragraph{Context envelopes at invocation boundaries.}
The rules above retain the fact-free protocol. When a source already records
discharged host facts or a consumer fact (Section~\ref{sec:context}), its
invocation must instead carry an explicit \code{context \{..\};} envelope
between the optional arguments and the pipeline. The envelope must equal
the recorded source facts in both directions: it may neither omit a recorded
fact nor add an unrecorded one. Locally certified host facts are not envelope
facts. A lower/select argument packet may introduce facts into a fact-free
source; naming facts in such a packet never substitutes for the required
envelope on an already-factful source. The enclosing compiler that emits a
hole invocation must write that envelope and prove its facts.

Each invocation consumes and checks its own envelope. In \textsc{ST-Next},
the emitted invocation derives a fresh envelope from the recorded facts of
$t$, its next source, rather than blindly forwarding the consumed envelope;
it omits the envelope if those facts are empty. Physical facts carried by
containment into Structures and Sequence preserve the envelope when those
facts are unchanged. Ordinary passes and rewrites may preserve or drop facts,
not introduce them; only the lower/select packet boundary authorizes
introduction. Missing or inexact envelopes and unauthorized introductions
are rejected as \textsc{CTX-Entry} failures.

An enclosing checked context may additionally attach an
\code{output_consumer} requirement to the remaining pipeline: an original
consumer identity, the complete ordered head identities, and the subset whose
logical values it reads. This is not a member of $\Gamma$ and authorizes no
canonical-consumer or host-set fact. Intermediate passes forward the typed
requirement without interpreting it. The selection entry binds it once into
Structures' original consumer obligations and compares that packet exactly
against the transported requirement; ordinary passes cannot introduce or
replace it. Structures checks the head against Physical, including host-once
captures, and its rewrites preserve the original packet. Thus changing both
selected reads and the claimed demand does not establish correspondence.

Optional features under \code{features/} share the root development workspace
for build reuse while depending only on public core APIs: planners, rewrites,
surface extensions (aggregation,
correlated subqueries, recursion as Rust contexts around checked
core invocations), a push printer, a stacked IR, a diverged RA surface,
composition, inspection and workloads. Workspace membership does not permit
core-to-feature dependencies; the dependency gate checks that direction
independently. \code{tools/check_external.py} packages the core and builds and
tests each feature outside the repository, and rejects a fixture that only
builds in-tree. Packaging fixtures retain intentional standalone workspaces;
GPU/oxide and Metal packages use separate experimental workspaces.

\begin{theorem}[Conditional composition]
\label{thm:composition}
If $f:L\to M$ and $g:M\to N$ terminate on their domains, $f$ produces only inputs
$g$ admits and establishes $g$'s representation preconditions, and both preserve
a common observation under compatible closing contexts, then so does $g\circ f$.
\end{theorem}
\begin{proof}Compose the representation relations and observation equalities;
domain inclusion makes $g$ defined; context adequacy lifts the argument to macro
invocations.\end{proof}

\paragraph{Set aggregate contexts.}
The aggregate context records owned head columns, constant-group proof and
\code{cq_storage::HashState}. Its hole resumes the remaining pipeline with an
empty context, so CK-Return (an inferred key or a recorded \code{return canon}
and its canonical index) makes returned rows a set under every checked terminal.
The extension folds that stream once and never claims \code{consumer = canonical},
because count and sum observe multiplicity.
Every selected terminal must preserve that canonical return, including its
multiplicity; a terminal deliberately repeating canonical rows violates the
printer obligation. The aggregate does not repair such a terminal with a second
set boundary.
The context's checked grouping keys and measure operands derive its logical
value demand; generated Rust is not analyzed for that purpose. Every original
head field, including ignored witnesses, remains part of the complete set
identity. An ignored base field may therefore publish an injective value code
under the independent representation contract, but never a row-position
identity in place of a value. No primary-key premise is needed for such codes,
and duplicate complete value tuples still collapse before the fold.
Read group and measure fields retain their logical-value obligation; a blocked
representation that cannot honor the fold's borrowing contract is rejected,
not silently converted to a different publication mode. Host-captured keys and
owned computed measures retain their original realization. These requirements
do not change the empty optimization context in \textsc{EXT-SetFold}.
\begin{mathpar}
\Rule{EXT-SetFold}{\Gamma_{\rm hole}=\emptyset\quad\textsc{CK-Return}(hole)\quad
 Q:\mathcal P_{\rm fin}(Row)}
 {\mathsf{aggregate}(Q)=\mathsf{fold}(Q)}

\Rule{EXT-ConstantGroup}{\forall k\in K.\ k\text{ is bound by a top-level }\code{let}\text{ recorded by A-Capture}}
 {\mathsf{groupFold}_K(Q)=\mathsf{optionalAccumulator}(Q)}
\end{mathpar}
The premise uses the CQ capture producer's closedness, never the shape of the
\code{let} initializer, so a literal and any other closed key are treated alike.
Constant grouping emits \code{SingleGroup}, which stores zero or one key and
measure tuple without hashing. Empty input still has no group. Computed measures
are borrowed for cloning at the fold, rather than materialized as another CQ
input. General groups use the recorded fast hash state, including their reusable
answer storage. None of these facts implies input-row or primary-key uniqueness:
the core's necessary result deduplication remains.
