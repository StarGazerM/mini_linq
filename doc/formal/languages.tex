\section{Languages and local judgments}
\label{sec:languages}
CQ rules end in semicolons; Rust comparison guards are recognized under
the relational premises below. Other Rust expressions are opaque leaves
with lexical dependency checks. This specification covers
positive queries without aggregates. It defines the admitted language, not
every form accepted by a current parser.
\subsection{Lexical dependency analysis}
The helper computes $\fv_S(e)=(F,o)$: a finite set of visible value names and
an opacity bit. For logical environment $B$, define
\[
 \uses(e,B)=\begin{cases}B&o=\mathsf{true},\\ F\cap B&o=\mathsf{false},\end{cases}
 \qquad
 \operatorname{known}(e,Q)=\begin{cases}\emptyset&o=\mathsf{true},\\F\cap Q&\text{otherwise}.\end{cases}
\]
Here $Q$ contains all syntactically logical names and $e\checkmark_B$ means
$\operatorname{known}(e,Q)\subseteq B$. The liveness bound $\uses$ cannot be
replaced by the diagnostic $\operatorname{known}$. In
$A\vdash e\rightsquigarrow(F,o)$, $A$ contains lexical binders; unions combine
names and disjoin opacity. Rust attributes, macros, local items, and verbatim
syntax are opaque. Qualified path components and field/method names are
not simple value uses; const-generic expression children are visited.
\begin{mathpar}

\Rule{FV-Name}{x\notin A}{A\vdash x\rightsquigarrow(\{x\},\mathsf{false})}

\Rule{FV-Bound}{x\in A}{A\vdash x\rightsquigarrow(\emptyset,\mathsf{false})}

\Rule{FV-Children}{A\vdash e_j\rightsquigarrow(F_j,o_j)\quad(1\le j\le n)}
 {A\vdash c(e_1,\ldots,e_n)\rightsquigarrow(\bigcup_jF_j,\bigvee_jo_j)}

\Rule{FV-Closure}{A\cup\binds(\bar p)\vdash e\rightsquigarrow(F,o)}
 {A\vdash |\bar p|e\rightsquigarrow(F,o)}

\Rule{FV-For}{A\vdash e\rightsquigarrow u\quad A\cup\binds(p)\vdash b\rightsquigarrow v}
 {A\vdash\mathsf{for}\ p\ \mathsf{in}\ e\ b\rightsquigarrow u\cup v}
\end{mathpar}
FV-Children covers nonbinding constructors, including pattern/type expression
children. Blocks visit each initializer and let-else branch in the old scope,
then add pattern bindings for subsequent statements. Match scrutinees use
$A$; each arm's guard/body uses $A\cup\binds(p)$. Condition scopes use:
\begin{mathpar}

\Rule{FV-CondLet}{A\vdash e\rightsquigarrow u}
 {A\vdash\mathsf{let}\ p=e\rightsquigarrow_c(u,A\cup\binds(p))}

\Rule{FV-And}{A\vdash e_1\rightsquigarrow_c(u,A_1)\quad A_1\vdash e_2\rightsquigarrow_c(v,A_2)}
 {A\vdash e_1\mathbin{\&\&}e_2\rightsquigarrow_c(u\cup v,A_2)}

\Rule{FV-Cond}{A\vdash e\rightsquigarrow u\quad e\text{ is neither case above}}
 {A\vdash e\rightsquigarrow_c(u,A)}
\end{mathpar}
Condition bindings reach the then/loop body, never else or outer statements.
$\binds(p)$ lists syntactic identifier patterns in order, deduplicating
raw-normalized names; Rust resolves constant-pattern ambiguity.
\begin{lemma}[Lexical upper bound]
For transparent syntax whose patterns have the intended binding resolution,
every free simple value-name occurrence outside $A$ is in $F$. Consequently
$\uses(e,B)$ contains its logical free names in $B$. For opaque syntax, the
same containment follows from returning all of $B$.
\end{lemma}
\begin{proof}
Induct simultaneously on expressions, statements, and conditions. Names are
bound or recorded; constructors union child results. Each binder extends only
its body scope; initializers and else branches retain the old scope. FV-And
threads the first condition's scope into the second. These cases cover binder
overrides; opacity returns all of $B$. Macro expansion and pattern resolution
remain hypotheses.
\end{proof}

\subsection{The compiler's CQ language and Rust extensions}
Beyond classical CQ (Section~\ref{sec:valuations}), the compiler admits native
Rust expressions, guards, and bindings; these extend AHV Definition~4.2.1:
\[
\begin{aligned}
q&=h(\bar e)\mathrel{:-}c_0,\ldots,c_{n-1};\\
c&::=R(\bar a)\mid\mathsf{if}\ e\mid\mathsf{let}\ p[:\tau]=e\mid\mathsf{block},\\
a&::=x\mid\_\mid e.
\end{aligned}
\]
Bare single-segment paths bind logical variables; other expressions compute.
A query needs a positive atom. Undeclared bare heads must be body-bound;
computed outputs need a declared or known projected type. Result declarations
are not inputs.
The judgment $\Sigma;B\vdash c\Rightarrow B'$ checks a clause's written scope.
Atom arguments are checked left to right; $\Sigma;B\vdash\bar a\Rightarrow B'$
folds these argument rules and requires $|\bar a|=|\Sigma(R)|$:
\begin{mathpar}

\Rule{CQ-Var}{}{\Sigma;B\vdash x\Rightarrow B\cup\{x\}}

\Rule{CQ-Expr}{e\checkmark_B}{\Sigma;B\vdash e\Rightarrow B}

\Rule{CQ-Atom}{R\in\dom\Sigma\quad |\bar a|=|\Sigma(R)|\quad
 \Sigma;B\vdash\bar a\Rightarrow B'}{\Sigma;B\vdash R(\bar a)\Rightarrow B'}

\Rule{CQ-Guard}{e\checkmark_B}{\Sigma;B\vdash\mathsf{if}\ e\Rightarrow B}

\Rule{CQ-Bind}{e\checkmark_B\quad N=\set(\binds(p))\quad N\cap B=\emptyset}
 {\Sigma;B\vdash\mathsf{let}\ p[:\tau]=e\Rightarrow B\cup N}
\end{mathpar}
CQ-Expr includes wildcard with no uses and excludes bare variables. Starting
at $B=\emptyset$ gives a structural scope check, not Rust typing.
An atom admits rows agreeing with existing bindings and normalized relational
identities; a guard retains true environments and a let extends them by its
pattern result. Compose these steps in the Kleisli meaning of
Section~\ref{sec:scope}, propagating panic through the whole evaluation.
The total relational specialization agrees with classical $q(I)$.
\paragraph{Core block grammar and scope.}
\begin{lstlisting}
Clause ::= Atom | if Expr | let Pat [: Type] = Expr | Block
Block  ::= { Body } ( | { Body } )+
         | { Body } ( else { Body } )+
\end{lstlisting}
Branches are nonempty; a single branch and mixed operators fail parsing.
Nesting admits either operator inside the other. Multiple rules for one head
are core sugar for one top-level union with fresh positional head columns.
Each rule has fresh local names. Variable heads with the same repetition
pattern use relational renaming; other heads require declared output types
and per-arm Rust bindings. Opaque syntax receives lexical aliases rather
than identifier substitution inside its tokens.
\begin{mathpar}
\Rule{CQ-Block}{n\ge2\quad\forall j,\ \Sigma;B\vdash B_j\Rightarrow B_j'\\
 I=(\bigcap_j B_j')\setminus B\quad \forall x\in I,\ \tau_j(x)=\tau_k(x)}
 {\Sigma;B\vdash\mathsf{block}(B_1,\ldots,B_n)\Rightarrow B\cup I}
\end{mathpar}
Names in only some branch bindings are local and cannot reappear in a suffix
or head. VO carries recursive step sequences and fixed occurrence paths
\code{R@c.j.k}, extended by branch/clause pairs at each nesting level. A
Rust-free block is one planning hyperedge over $F\cup I$ at its clause index;
a Rust block is pinned by the union of branch Before requirements.

\subsection{Rust comparison guards}
Let $Q$ contain every query binder, $B\subseteq Q$ the written bound names,
and $P$ the closing host parameters. CQ parses Rust expressions with Syn;
there is no separate comparison grammar. The following is a recognition
judgment over that Rust AST:
\begin{lstlisting}
t ::= query-variable | *query-variable | &query-variable
    | literal | -numeric-literal | bare-host-identifier
C ::= t == t | t != t | t < t | t <= t | t > t | t >= t
    | C && C | C || C | !C | (C)
\end{lstlisting}
Parentheses may surround operands too. A bare name in $Q$ is a query variable;
any other bare identifier must resolve in the enclosing Rust scope $P$.
Guard-local pattern bindings are not host parameters. A query name used before
its binder fails scope checking. Attributes, arithmetic, calls, methods,
casts, indexing, blocks, macros, qualified paths and field access are opaque.
Only query names admit one shared reference or dereference wrapper.
Rust desugars equality comparisons to \code{PartialEq::eq}/\code{ne}, and order
comparisons to the corresponding \code{PartialOrd} methods. We recognize these
trait operations under the existing admissibility premises, not arbitrary
Rust behavior. Write $\vars(\theta)$ for the recognized query names.
\begin{mathpar}
\Rule{ORD-Admissible}{\tau:\code{Ord}\quad
 \leq_\tau\text{ total, terminating and consistent with Leibniz identity}}
 {\tau\text{ admits relational order}}

\Rule{CQ-Comparison}{\vars(t_1,t_2)\subseteq B\quad
 t_1,t_2\text{ well typed and admissible}\quad
 op\in\{==,\ne,<,\leq,>,\geq\}}
 {\Sigma;B;P\vdash t_1\ op\ t_2\Rightarrow B}

\Rule{CQ-GuardRecognize}{e\text{ has only recognized comparisons and boolean nodes}\\
 \text{all comparison operations satisfy the Eq/Ord premises}}
 {\mathsf{recognize}_{Q,P}(e)=\theta\quad\sem e=\sem\theta}
\end{mathpar}
Every recognized comparison is terminating and cannot panic under the
premises. Rust short-circuit \code{\&\&}/\code{||}, boolean \code{!} and
parentheses therefore have the classical connective meaning on this fragment.
Negation uses comparison complements and De Morgan's laws. Normalization
retains paired inclusive bounds, literal equality disjunctions and nested
boolean branches in the existing internal constraint IR; no distributive DNF
expansion is needed. Later IRs spell parameters \code{@name}. Parameters are
borrowed once outside query loops. Equality is Leibniz identity; floats fail
its admissibility. Ord is required even for a scan implementation.

A mixed \code{||} or \code{!} expression is entirely opaque. Only the top-level
conjunction may split, by CQ-GuardSplit below. Thus \code{if *od < cutoff}
becomes a relational constraint; \code{if f(*od) || *od < cutoff} remains one
pinned Rust guard, as does \code{if *od + 1 < 5}.

\subsection{Normal form and valuation plans}
\label{sec:nf-vo}
CQ-NF is a restriction of \code{cq::Program}; VO adds an explicit valuation
schedule to that normalized program. In NF every atom argument is a distinct
bare variable and every output argument is a variable. A shared name across
atoms is a natural-join variable and stays unchanged. Only repeats within one
atom occurrence and
literals produce relational identities at the atom's written position.
Computed arguments produce positioned opaque binds and identities; computed
heads become final binds. Relational comparisons and boolean structure remain
central clauses. NF checks their scope and syntactically known Eq/Ord failures;
Rust checks unknown aliases and user types. These mechanical checks do not
prove admissibility.

VO extends partial valuations with subatoms and carries each central constraint
exactly once after its variables bind. Relational steps may commute and hoist
across Rust; a Rust node keeps its chain position and every source Before
relational predecessor, including comparisons. A split atom is complete only
when its full correlated row has been checked. A reduction
\code{reduce R@0 with S@1(b, _)} is a relational semijoin; no guard reduction
exists. Reduction erasure preserves every other step exactly. The explicit
Written route retains source order for the executable reference; optimizing
routes place ready constraints before further generators. Elaboration pushes
constraints onto an atom supplying all their columns, or selects the current
prefix when no such atom exists.
Ordering and splitting are separate choices constrained by coverage and
Before: Coarse uses one full subatom per atom; Fine introduces at most one
new variable per subatom. Blocks carry recursively checked arm schedules.

The transported syntax is:
\begin{lstlisting}
VO ::= CQProgram valuation { Step* }
Step ::= R@path(x, _, ...); | x = y; | Constraint;
       | if Expr; | let Pat [: Type] = Expr;
       | reduce R@path with S@path(...);
       | block @path(columns) { Step* } (| { Step* })+;
       | block @path(columns) { Step* } (else { Step* })+;
\end{lstlisting}
Equality and Constraint here are internal relational syntax. Numeric paths
identify fixed NF occurrences; each nested level adds branch/clause pairs.

\subsection{Named relational algebra (RA prime)}
The complete program owns its relation declarations $\Sigma$, named SPJR
using immutable definitions, and explicit
Unit/Semijoin, central Select, and opaque Rust Guard/Bind. The token payload is a standalone named DAG:
\begin{lstlisting}
RA ::= relational { Decl* (r = Op;)* output r as Head; }
Op ::= unit | rename R@path {source -> variable, ...}
     | natural_join l with r | semijoin l with r
     | project r keep {columns} | select r if (Theta)
     | guard r if (Expr) [Environment]
     | bind r with Pat [: Type] = (Expr) [Environment]
     | union r1, r2, ... [BlockOrigin] | anti [F] l, r
Environment ::= scope[names] [@path]
BlockOrigin ::= block @path free[F] interface[I]
                [fallback] [over prefix] [domain input]
\end{lstlisting}

The mathematical operator core is:
\[
\begin{aligned}
d&::=r=o;& A&::=d_1;\ldots;d_m;\mathsf{output}\ r\ \mathsf{as}\ h(\bar e),\\
o&::=\mathbf1\mid\delta_m(R)\mid r\bowtie s\mid r\ltimes s
 \mid\pi_Ur\mid\sigma_\theta r\\
 &\quad\mid\operatorname{guard}_e r\mid\operatorname{bind}_{N,e}r\mid\bigcup_j r_j\mid r\triangleright_F s.
\end{aligned}
\]
$\Delta(r)=(V,T,C)$ records sort, symbolic Rust types, and computed attributes.
The rules show sorts; type/origin metadata is propagated below.
\begin{mathpar}

\Rule{RA-Unit}{}{\Sigma;\Delta\vdash\mathbf1:\emptyset}

\Rule{RA-Rename}{R\in\dom\Sigma\quad m:\operatorname{cols}(\Sigma(R))\cong V}
 {\Sigma;\Delta\vdash\delta_m(R):V}

\Rule{RA-Join}{\Delta(r).V=V\quad\Delta(s).V=W}
 {\Sigma;\Delta\vdash r\bowtie s:V\cup W}

\Rule{RA-Semi}{\Delta(r).V=V\quad s\in\dom\Delta}
 {\Sigma;\Delta\vdash r\ltimes s:V}

\Rule{RA-Project}{\Delta(r).V=V\quad U\subseteq V}
 {\Sigma;\Delta\vdash\pi_Ur:U}

\Rule{RA-Select}{\Delta(r).V=V\quad \theta\checkmark_{V,P}}
 {\Sigma;\Delta\vdash\sigma_\theta r:V}

\Rule{RA-Extend}{\Delta(r).V=V\quad e\checkmark_V\quad N\cap V=\emptyset}
 {\Sigma;\Delta\vdash\operatorname{bind}_{N,e}r:V\cup N}

\Rule{RA-Def}{\Sigma;\Delta\vdash o:\delta\quad r\notin\dom\Delta}
 {\Sigma\vdash(\Delta,r=o)\Rightarrow\Delta[r\mapsto\delta]}
\end{mathpar}
Rename inherits positional column types with $C=\emptyset$; Unit has empty
maps. Other operators restrict/merge maps to their output sort, preferring
left type spelling on overlap. Extend adds written types (possibly inference placeholders)
and marks $N$ computed; operand computed sets are unioned/restricted. Rust
must establish concrete type compatibility. Ordinary Guard/Bind payloads
check visible logical uses. An explicit Environment instead checks a
valid numeric path and distinct listed names available in the input heading;
Rust resolves the expression in that recorded lexical scope. Local RA checks
compatible Rust ancestry (union combines branch chains); elaboration/rewrite
correspondence checks source-tree paths, payloads and Before facts.

Names/listed attributes are unique; operands precede uses and every definition
is reachable from output. Output expressions pass visible-use checks; a bare
head's attribute set equals its sort, while computed heads may use a subset.
Declarations and output metadata are part of RA. Elaboration checks agreement
with the source CQ head, fixed occurrences, structural relational facts and
Rust Before obligations; the RA contract checks only this program.
Evaluation uses the partial operators of Section~\ref{sec:scope}, not an
unconditional eager evaluation of every DAG definition: ordered fallback
only evaluates selected arms. A computed output is also a partial map.
References name immutable set-valued definitions, without promising a
materialized collection or a reusable iterator; every traversal needs its
own cursor state and must respect the Rust ancestry obligations.
\subsection{Index demands}
The normative syntax and construction rules are in
Section~\ref{sec:ix}. IX is $(A,D)$: the unchanged RA
plan $A$ and named index definitions $D(i)=(r,C,supply)$, where supply is
stream, const, or range. Here $r$ is an
exact immutable result version. $C$ records its required join-column ordinals
in the logical heading $H(r)=\ord(\Delta(r).V)$; physical row layout is supplied
separately. An empty $C$ requests the unit-valued index for a Cartesian product.

Local validity checks source versions, column ranges, unique descriptors,
and that every demand matches a join/semijoin right operand, an anti right
operand on its explicit free key, or a point/range select input with its
matching supply.
The analysis correspondence requires complete demand coverage in first-use
order with \code{iN} names. Physical lowering
checks that its probe/semi operands have matching IX demands.
An empty annotation does not authorize a repeated-scan fallback.
The full judgment is $\mathsf{WF}_{IX}(A,D)$
of Section~\ref{sec:ix}, and
\[
 \sem{A,D}_{IX}=\sem A_{RA}.
\]
\subsection{Physical and Structures}
Physical is a complete standalone program with declarations, detailed operators,
read modes and output metadata. Lowering reads those operators back as RA and
checks correspondence with the RA contained in IX. Structures extends Physical
and records built, host-fallback, retained-row and dedup types; native host
reads dispatch by type. Their local
contract rules and immediate-source correspondence checks are stated separately
in Section~\ref{sec:pass-contracts}. Complete token grammars are also given in
the documentation of the language crates under \path{languages/}.

\subsection{Union and antijoin in RA prime}
\begin{lstlisting}
r = union r1, r2, ... block @path free[F] interface[I];
r = anti [F] left, original;
\end{lstlisting}
A block origin additionally records ordered fallback, a correlated prefix
\code{over p}, or a finite free-column \code{domain p}, when applicable.
Elaboration projects every operand to the identical common heading. Opaque
Rust environments record \code{scope[names] @c.j.k}, fixing their written
lexical inputs and source tree paths. A context semijoin may refer to prefix
Rust without moving that Rust into the arm; the given path distinguishes them.
\begin{mathpar}
\Rule{RA-Union}{\forall j,\ H(r_j)=H}
 {H(\mathsf{union}(r_1,\ldots,r_n))=H\quad
 \sem{\mathsf{union}(r_1,\ldots,r_n)}=\bigcup_j\sem{r_j}}

\Rule{RA-Anti}{F\subseteq H(r)\cap H(s)}
 {H(\mathsf{anti}_F(r,s))=H(r)\quad
 \sem{\mathsf{anti}_F(r,s)}=\sem r\mathbin{\triangleright_F}\sem s}
\end{mathpar}
Checks compare supplied structural branch identities, exact occurrences,
headings, constraints, negative references, tree paths and Before facts.
They perform no search, equivalence decision or homomorphism construction.
