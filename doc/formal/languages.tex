\section{Languages and local judgments}
\label{sec:languages}
CQ and Access rules end in semicolons; Rust expressions are opaque leaves
except for the lexical dependency checks below. This specification covers
positive queries without aggregates. It defines the admitted language, not
every form accepted by a current parser.
\subsection{Lexical dependency analysis}
The helper computes $\fv_S(e)=(F,o)$: a finite set of visible value names and
an opacity bit. For logical environment $B$, define
\[
 \uses(e,B)=\begin{cases}B&o=\mathsf{true},\\ F\cap B&o=\mathsf{false},\end{cases}
 \qquad
 \operatorname{known}(e,Q)=\begin{cases}\emptyset&o=\mathsf{true},\\F\cap Q&\text{otherwise}.\end{cases}
\]
Here $Q$ contains all syntactically logical names and $e\checkmark_B$ means
$\operatorname{known}(e,Q)\subseteq B$. The liveness bound $\uses$ cannot be
replaced by the diagnostic $\operatorname{known}$. In
$A\vdash e\rightsquigarrow(F,o)$, $A$ contains lexical binders; unions combine
names and disjoin opacity. Rust attributes, macros, local items, and verbatim
syntax are opaque. Qualified path components and field/method names are
not simple value uses; const-generic expression children are visited.
\begin{mathpar}

\Rule{FV-Name}{x\notin A}{A\vdash x\rightsquigarrow(\{x\},\mathsf{false})}

\Rule{FV-Bound}{x\in A}{A\vdash x\rightsquigarrow(\emptyset,\mathsf{false})}

\Rule{FV-Children}{A\vdash e_j\rightsquigarrow(F_j,o_j)\quad(1\le j\le n)}
 {A\vdash c(e_1,\ldots,e_n)\rightsquigarrow(\bigcup_jF_j,\bigvee_jo_j)}

\Rule{FV-Closure}{A\cup\binds(\bar p)\vdash e\rightsquigarrow(F,o)}
 {A\vdash |\bar p|e\rightsquigarrow(F,o)}

\Rule{FV-For}{A\vdash e\rightsquigarrow u\quad A\cup\binds(p)\vdash b\rightsquigarrow v}
 {A\vdash\mathsf{for}\ p\ \mathsf{in}\ e\ b\rightsquigarrow u\cup v}
\end{mathpar}
FV-Children covers nonbinding constructors, including pattern/type expression
children. Blocks visit each initializer and let-else branch in the old scope,
then add pattern bindings for subsequent statements. Match scrutinees use
$A$; each arm's guard/body uses $A\cup\binds(p)$. Condition scopes use:
\begin{mathpar}

\Rule{FV-CondLet}{A\vdash e\rightsquigarrow u}
 {A\vdash\mathsf{let}\ p=e\rightsquigarrow_c(u,A\cup\binds(p))}

\Rule{FV-And}{A\vdash e_1\rightsquigarrow_c(u,A_1)\quad A_1\vdash e_2\rightsquigarrow_c(v,A_2)}
 {A\vdash e_1\mathbin{\&\&}e_2\rightsquigarrow_c(u\cup v,A_2)}

\Rule{FV-Cond}{A\vdash e\rightsquigarrow u\quad e\text{ is neither case above}}
 {A\vdash e\rightsquigarrow_c(u,A)}
\end{mathpar}
Condition bindings reach the then/loop body, never else or outer statements.
$\binds(p)$ lists syntactic identifier patterns in order, deduplicating
raw-normalized names; Rust resolves constant-pattern ambiguity.
\begin{lemma}[Lexical upper bound]
For transparent syntax whose patterns have the intended binding resolution,
every free simple value-name occurrence outside $A$ is in $F$. Consequently
$\uses(e,B)$ contains its logical free names in $B$. For opaque syntax, the
same containment follows from returning all of $B$.
\end{lemma}
\begin{proof}
Induct simultaneously on expressions, statements, and conditions. Names are
bound or recorded; constructors union child results. Each binder extends only
its body scope; initializers and else branches retain the old scope. FV-And
threads the first condition's scope into the second. These cases cover binder
overrides; opacity returns all of $B$. Macro expansion and pattern resolution
remain hypotheses.
\end{proof}

\subsection{The compiler's CQ language and Rust extensions}
Beyond classical CQ (Section~\ref{sec:valuations}), the compiler admits native
Rust expressions, guards, and bindings; these extend AHV Definition~4.2.1:
\[
\begin{aligned}
q&=h(\bar e)\mathrel{:-}c_0,\ldots,c_{n-1};\\
c&::=R(\bar a)\mid\mathsf{if}\ e\mid\mathsf{let}\ p[:\tau]=e,\\
a&::=x\mid\_\mid e.
\end{aligned}
\]
Bare single-segment paths bind logical variables; other expressions compute.
A query needs a positive atom. Undeclared bare heads must be body-bound;
computed outputs need a declared or known projected type. Result declarations
are not inputs.
The judgment $\Sigma;B\vdash c\Rightarrow B'$ checks a clause's written scope.
Atom arguments are checked left to right; $\Sigma;B\vdash\bar a\Rightarrow B'$
folds these argument rules and requires $|\bar a|=|\Sigma(R)|$:
\begin{mathpar}

\Rule{CQ-Var}{}{\Sigma;B\vdash x\Rightarrow B\cup\{x\}}

\Rule{CQ-Expr}{e\checkmark_B}{\Sigma;B\vdash e\Rightarrow B}

\Rule{CQ-Atom}{R\in\dom\Sigma\quad |\bar a|=|\Sigma(R)|\quad
 \Sigma;B\vdash\bar a\Rightarrow B'}{\Sigma;B\vdash R(\bar a)\Rightarrow B'}

\Rule{CQ-Guard}{e\checkmark_B}{\Sigma;B\vdash\mathsf{if}\ e\Rightarrow B}

\Rule{CQ-Bind}{e\checkmark_B\quad N=\set(\binds(p))\quad N\cap B=\emptyset}
 {\Sigma;B\vdash\mathsf{let}\ p[:\tau]=e\Rightarrow B\cup N}
\end{mathpar}
CQ-Expr includes wildcard with no uses and excludes bare variables. Starting
at $B=\emptyset$ gives a structural scope check, not Rust typing.
Under $\mathcal H_{\rm rel}$, an atom admits rows agreeing with existing
bindings, repeated positions, and computed arguments, then binds new names;
a guard retains true environments and a let extends them by its pattern
result. Compose from $\mathbf1$ and take the set of ordered head results to
define $\sem q_I$. This agrees with classical $q(I)$ on its domain and gives
no effectful evaluation-order semantics.
\subsection{Named relational algebra}
This IR represents named SPJR using immutable definitions, adding explicit
Unit/Semijoin and Rust Select/Extend:
\[
\begin{aligned}
d&::=r=o;& A&::=d_1;\ldots;d_m;\mathsf{output}\ r\ \mathsf{as}\ h(\bar e),\\
o&::=\mathbf1\mid\delta_m(R)\mid r\bowtie s\mid r\ltimes s
 \mid\pi_Ur\mid\sigma_er\mid\operatorname{ext}_{N,e}r.
\end{aligned}
\]
$\Delta(r)=(V,T,C)$ records sort, symbolic Rust types, and computed attributes.
The rules show sorts; type/origin metadata is propagated below.
\begin{mathpar}

\Rule{RA-Unit}{}{\Sigma;\Delta\vdash\mathbf1:\emptyset}

\Rule{RA-Rename}{R\in\dom\Sigma\quad m:\operatorname{cols}(\Sigma(R))\cong V}
 {\Sigma;\Delta\vdash\delta_m(R):V}

\Rule{RA-Join}{\Delta(r).V=V\quad\Delta(s).V=W}
 {\Sigma;\Delta\vdash r\bowtie s:V\cup W}

\Rule{RA-Semi}{\Delta(r).V=V\quad s\in\dom\Delta}
 {\Sigma;\Delta\vdash r\ltimes s:V}

\Rule{RA-Project}{\Delta(r).V=V\quad U\subseteq V}
 {\Sigma;\Delta\vdash\pi_Ur:U}

\Rule{RA-Select}{\Delta(r).V=V\quad e\checkmark_V}
 {\Sigma;\Delta\vdash\sigma_er:V}

\Rule{RA-Extend}{\Delta(r).V=V\quad e\checkmark_V\quad N\cap V=\emptyset}
 {\Sigma;\Delta\vdash\operatorname{ext}_{N,e}r:V\cup N}

\Rule{RA-Def}{\Sigma;\Delta\vdash o:\delta\quad r\notin\dom\Delta}
 {\Sigma\vdash(\Delta,r=o)\Rightarrow\Delta[r\mapsto\delta]}
\end{mathpar}
Rename inherits positional column types with $C=\emptyset$; Unit has empty
maps. Other operators restrict/merge maps to their output sort, preferring
left type spelling on overlap. Extend adds written types (possibly holes)
and marks $N$ computed; operand computed sets are unioned/restricted. Rust
must establish concrete type compatibility.

Names/listed attributes are unique; operands precede uses and every definition
is reachable from output. Output expressions pass visible-use checks; a bare
head's attribute set equals its sort, while computed heads may use a subset.
Physical lowering requires nameable output types. CQ annotations supply schema
and API metadata, never permission to re-plan.
Evaluation folds definitions into $\mathcal E$, using the operators of
Section~\ref{sec:scope} and positional Rename, then returns
$\{\bar e(t)\mid t\in\mathcal E(r)\}$. References denote the same immutable
result; this denotation imposes no physical materialization schedule.
\subsection{Indexes and their uses}
The normative syntax and construction rules are in
Section~\ref{sec:ix-physical-redesign}. IX is $(A,D,U)$: the unchanged RA
plan $A$, named index definitions $D(i)=(r,C)$, and references
$U(j.\mathsf{right})=i$ from consuming operator positions. Here $r$ is an
exact immutable result version. $C$ records its required join-column ordinals
in the logical heading $H(r)=\ord(\Delta(r).V)$; physical row layout is supplied
separately. An empty $C$ requests the unit-valued index for a Cartesian product.

Local validity checks source versions, column ranges, unique descriptors,
and exact coverage of every admitted join position. In particular, it does
not accept an empty annotation as permission to rediscover requirements or
execute a repeated-scan join. The full judgment is $\mathsf{WF}_{IX}(A,D,U)$
of Section~\ref{sec:ix-physical-redesign}, and
\[
 \sem{A,D,U}_{IX}=\sem A_{RA}.
\]
\subsection{Bound Physical programs}
Physical selection is separate from IX analysis. It consumes the open provider
definitions $\Omega$, policy $\eta$, and explicit host declarations,
and produces $P=(IX,\Phi,\Lambda)$. Here $\Phi=(\Phi_R,\Phi_I)$ binds relation
versions and required index identities to external provider instances.
The domain of $\Phi_I$ is exactly $\dom D$. The map $\Lambda$ selects one
external lowering for every RA definition result, including Rename and Unit.
Free host inputs have relation bindings but no lowering entry: their production
is not an RA definition in this program.

The serialized Physical program retains IX and appends the \code{physical}
block specified in Section~\ref{sec:ix-physical-redesign}, with
\code{relations}, \code{indexes}, and \code{lowerings} bindings. This is
an inspectable selected program, not emitted loops or construction code.
Its erasure is the original IX and its meaning is unchanged:
\[
 \operatorname{erase}(IX,\Phi,\Lambda)=IX,\qquad
 \sem{IX,\Phi,\Lambda}_{\mathsf{Physical}}=\sem{IX}_{IX}.
\]
Well-formedness requires the selected declarations to agree on operator domains,
exact source versions, written index uses, and output representations.
Declarations supply the physical definitions available to compilation; neither
a path's spelling nor Rust type inference supplies those definitions. There
is no closed hash/sorted enumeration at this boundary.

The representation environment $\Gamma$ gives semantic meaning to physical
relations and current views. A carrier may be a borrowed row, a tuple of
borrowed fields, or a stable handle. Its decoding must agree with the exact RA
version. Index preparation may reuse an index already embodied by that relation
or construct an auxiliary representation. Selection does not change the RA
join columns or the references in $U$. Realization consumes Physical and follows
$\Lambda$ and $\Phi$; it has no policy parameter, does not select a replacement
lowering, and rejects unmet premises. Answer equivalence alone is insufficient:
compilation must bind and use the realizations specified by the selected program.

\subsection{Local Access regions}
An Access plan $h(\bar x)\Rightarrow e_h\mathrel{:-}\bar a$ has clauses
$\ell\Rightarrow\mathsf{bind}\ p\leftarrow e$ or
$\ell\Rightarrow\mathsf{if}\ e$. Labels describe logical occurrences,
guards, or bindings; Rust leaves supply concrete sources and operations.
The clause sequence may be empty; it then supplies exactly one empty binding.
For ordered bindings $\bar B$, $\operatorname{new}(\ell,B)$ lists first
positive-label names outside $B$, in label order. Write $p\sim\bar N$ when
$p$ is the simple tuple pattern $(\bar N)$, or $\bar N=[x]$ and $p=x$ is
one simple identifier pattern. Both forms bind precisely the listed names;
Rust checks the source item's shape.
\begin{mathpar}

\Rule{AC-Enumerate}{\bar N=\operatorname{new}(\ell,B)\ne\emptyseq\quad
 p\sim\bar N}
 {\bar B\vdash\ell\Rightarrow\mathsf{bind}\ p\leftarrow e\Rightarrow\bar B\concat\bar N}

\Rule{AC-If}{\operatorname{new}(\ell,B)=\emptyseq}
 {\bar B\vdash\ell\Rightarrow\mathsf{if}\ e\Rightarrow\bar B}

\Rule{AC-Guard}{\ell=\mathsf{if}\ e_0\quad e_0\checkmark_B}
 {\bar B\vdash\ell\Rightarrow\mathsf{if}\ e\Rightarrow\bar B}

\Rule{AC-Bind}{\ell=\mathsf{let}\ p_0=e_0\quad e_0\checkmark_B\quad
 \bar N=\binds(p_0)\quad |\set(\bar N)|=|\bar N|\quad \set(\bar N)\cap B=\emptyset\\
 p\sim\bar N}
 {\bar B\vdash\ell\Rightarrow\mathsf{bind}\ p\leftarrow e\Rightarrow\bar B\concat\bar N}
\end{mathpar}
AC-Enumerate/If concern positive labels; an empty label uses If. AC-Bind permits
empty bindings while evaluating their source. Head label names must be bound.
Freshness and logical-label RHS availability hold for direct quotations too, but
label/leaf agreement and singleton binding sources are edge obligations
(or assumptions for quoted plans). Rust checks name resolution and types in
concrete leaves and macros. For example, the source of
\code{bind rows <- (rows.iter())} may refer to the outer host variable
\code{rows}; the new item binding starts after the source expression.

Access has a schedule-independent support denotation under the pure relational
host assumptions $\mathcal H_{\rm rel}$. Starting from the singleton empty
environment, a Bind clause extends each current environment with the rows of
its Rust source; an If clause retains precisely the environments satisfying
its predicate. The head maps surviving environments to result values:
\[
\begin{aligned}
 E_0&=\{\emptyset\},\\
 E_{k+1}&=\{\rho\cup[p\mapsto t]\mid\rho\in E_k,\
              t\in\sem e(\rho)\}
              &&\text{for a Bind clause},\\
 E_{k+1}&=\{\rho\in E_k\mid\sem e(\rho)=\mathsf{true}\}
              &&\text{for an If clause},\\
 \sem{h(\bar x)\Rightarrow e_h\mathrel{:-}\bar a}
    &=\{\sem{e_h}(\rho)\mid\rho\in E_{|\bar a|}\}.
\end{aligned}
\]
The notation $[p\mapsto t]$ means successful pattern binding. Rust sources
may enumerate duplicate witnesses; set observation removes multiplicity.
The source is scoped under preceding bindings, before $p$ is introduced.
\code{bind} prescribes neither a Rust loop nor an iterator adapter. Pull
consumers demand each source lazily; eager consumers traverse it during region
execution. Both implement the support equation above, subject to their distinct
operational observations.
Physical lowering must prove that these concrete sources and predicates
implement the associated RA operator. The provider declarations and compilation
rules in Section~\ref{sec:ix-physical-redesign} establish that obligation for
each admitted realization. The core does not first prescribe a left-row scan
and then ask every provider to substitute one point-lookup expression.

This boundary does not prescribe a Pipeline IR or a push/pull lowering.
Whether a later transformation converts lazy enumeration into eager
execution remains outside the present contract. No such transformation may
alter the written index-use associations or weaken exact lookup semantics.
