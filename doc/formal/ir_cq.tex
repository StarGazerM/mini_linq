\section{CQ and its normal form}
\label{sec:cq}\label{sec:languages}

\paragraph{Grammar.}
CQ clauses use derived parsing; expressions, patterns and types are
\code{syn::Expr}, \code{syn::Pat} and \code{syn::Type}. Macros stay opaque
token trees~\cite{host-synmacro}.
\begin{lstlisting}
Program ::= struct Name; Decl* Rule+
Decl    ::= relation R(ColumnDecl, ...) [= (Expr)];
ColumnDecl ::= c ":" Type ["[" LogicalTypeId "]"] ["in" ["[" DomainId "]"] "(" Expr ")"]
Rule    ::= h(Expr, ...) :- Clause, ... ;
Clause  ::= R(Arg, ...) | !R(NegArg, ...) | Guard | where P
          | let Pat [: Type] = Expr | for Pat in Expr | Block
Guard   ::= "if" Expr
NegArg  ::= bound-variable | literal | closed-expression | _
Arg     ::= x | _ | Expr
Block   ::= { Body } ( | { Body } )+  |  { Body } ( else { Body } )+
\end{lstlisting}
Bare single-segment paths bind logical variables; other arguments compute.
Several rules for one head are sugar for one rule whose body is a top-level
union over fresh positional head columns; each rule gets fresh local names,
opaque syntax receives lexical aliases rather than token substitution.
The declaration table interns logical type spellings once into
\code{LogicalTypeId}; explicit ids survive printing and are never reinterpreted.
Equal spellings with explicitly different ids are distinct logical declarations.
Downstream codec lookup uses the recorded id, not the opaque \code{Type} payload.
A trailing \code{= (Expr)} supplies the host value. An optional column
\code{in (D)} records the column's code domain: a query-closed host value
implementing \code{cq\_storage::CodeDomain} whose codes the column stores.
The type stays opaque. The declaration table interns the opaque spelling of
$D$ once, sharing a domain id across input and output declarations.
Recorded IR prints \code{in [id] (D)} and reparsing preserves that id.
The id and untouched runtime payload ride in every IR carrying declarations.

\paragraph{Lexical dependencies.}
$\fv_S(e)=(F,o)$ returns visible value names and an opacity bit; with logical
environment $B$, $\uses(e,B)=B$ if $o$ else $F\cap B$, and the diagnostic
$\operatorname{known}(e,Q)=\emptyset$ if $o$ else $F\cap Q$. Write $e\checkmark_B$
for $\operatorname{known}(e,Q)\subseteq B$. Attributes, macros, local items and
verbatim syntax are opaque; qualified path segments and field/method names are
not value uses.
\begin{mathpar}
\Rule{FV-Name}{x\notin A}{A\vdash x\rightsquigarrow(\{x\},\mathsf{false})}

\Rule{FV-Bound}{x\in A}{A\vdash x\rightsquigarrow(\emptyset,\mathsf{false})}

\Rule{FV-Children}{A\vdash e_j\rightsquigarrow(F_j,o_j)\quad(1\le j\le n)}
 {A\vdash c(e_1,\ldots,e_n)\rightsquigarrow(\bigcup_jF_j,\bigvee_jo_j)}

\Rule{FV-Closure}{A\cup\binds(\bar p)\vdash e\rightsquigarrow(F,o)}
 {A\vdash |\bar p|e\rightsquigarrow(F,o)}

\Rule{FV-For}{A\vdash e\rightsquigarrow u\quad A\cup\binds(p)\vdash b\rightsquigarrow v}
 {A\vdash\mathsf{for}\ p\ \mathsf{in}\ e\ b\rightsquigarrow u\cup v}

\Rule{FV-CondLet}{A\vdash e\rightsquigarrow u}
 {A\vdash\mathsf{let}\ p=e\rightsquigarrow_c(u,A\cup\binds(p))}

\Rule{FV-And}{A\vdash e_1\rightsquigarrow_c(u,A_1)\quad A_1\vdash e_2\rightsquigarrow_c(v,A_2)}
 {A\vdash e_1\mathbin{\&\&}e_2\rightsquigarrow_c(u\cup v,A_2)}

\Rule{FV-Cond}{A\vdash e\rightsquigarrow u\quad e\text{ is neither case above}}
 {A\vdash e\rightsquigarrow_c(u,A)}
\end{mathpar}
Blocks visit initializers and let-else branches in the old scope, then add
pattern bindings; match arms add their pattern bindings; condition bindings
reach only the then/loop body.
\begin{lemma}[Lexical upper bound]
For transparent syntax with the intended pattern resolution, every free simple
value name outside $A$ is in $F$, so $\uses(e,B)$ contains the logical free names
of $e$ in $B$; for opaque syntax this holds because all of $B$ is returned.
\end{lemma}
\begin{proof}Simultaneous induction on expressions, statements and conditions;
each binder extends only its body scope. Macro expansion and pattern resolution
remain hypotheses.\end{proof}

\paragraph{Scope rules.}
$\Sigma;B\vdash c\Rightarrow B'$ checks one clause in written scope; clauses
fold left to right. An atom matches a tuple simultaneously: let
$\mathsf{bare}(\bar a)$ be its bare variable arguments and
$\mathsf{computed}(\bar a)$ its remaining arguments. Computed arguments see
the incoming scope and all bare binders of this atom, regardless of column
position, but never binders from later clauses. This is intentional:
A-Local evaluates an atom-dependent expression after matching the tuple;
permuting relation columns must not change its scope.
\begin{mathpar}
\Rule{CQ-Var}{}{\Sigma;B\vdash x\Rightarrow B\cup\{x\}}

\Rule{CQ-Expr}{e\checkmark_B}{\Sigma;B\vdash e\Rightarrow B}

\Rule{CQ-Atom}{R\in\dom\Sigma\quad |\bar a|=|\Sigma(R)|\quad
 B'=B\cup\mathsf{bare}(\bar a)\quad
 \forall e\in\mathsf{computed}(\bar a).\ e\checkmark_{B'}}
 {\Sigma;B\vdash R(\bar a)\Rightarrow B'}

\Rule{CQ-Guard}{e\checkmark_B}{\Sigma;B\vdash\mathsf{if}\ e\Rightarrow B}

\Rule{CQ-Bind}{e\checkmark_B\quad N=\set(\binds(p))\quad N\cap B=\emptyset}
 {\Sigma;B\vdash\mathsf{let}\ p[:\tau]=e\Rightarrow B\cup N}

\Rule{CQ-For}{e\checkmark_B\quad N=\set(\binds(p))\quad N\cap B=\emptyset}
 {\Sigma;B\vdash\mathsf{for}\ p\ \mathsf{in}\ e\Rightarrow B\cup N}

\Rule{CQ-Block}{n\ge2\quad\forall j,\ \Sigma;B\vdash B_j\Rightarrow B_j'\\
 I=(\bigcap_j B_j')\setminus B\quad \forall x\in I,\ \tau_j(x)=\tau_k(x)}
 {\Sigma;B\vdash\mathsf{block}(B_1,\ldots,B_n)\Rightarrow B\cup I}
\end{mathpar}
The generator RHS is checked in the old scope: its own pattern names are not
in scope until subsequent clauses (and the head). As for scalar binds, rustc
checks an irrefutable pattern and concrete binding types; for generators the
pattern destructures \code{IntoIterator::Item}, not the collection.
There is no surface generator type annotation. Finiteness and purity are
semantic premises, not properties established by the structural scope check.
An atom using a generator-supplied name requires that name already bound.


\paragraph{Explicit relational predicates.}
Let $Q$ contain every query binder and $B$ the names bound at this clause.
Unlike Rust guards, \code{where} has its own grammar and denotation:
\begin{lstlisting}
t ::= query-variable | literal | closed-Rust-expression
P ::= x == t | x != t | x < t | x <= t | x > t | x >= t
    | x in [t, ...] | x in t..t | x in t..=t | x == y
    | P && P | P || P | (P)
\end{lstlisting}
The left-hand $x$ is a bound query variable. Closed Rust operands are stored
as \code{Term::Closed(syn::Expr)}, not identifier/field-path parameters.
They are evaluated once on the host, outside row loops; internal languages
print them as \code{@(Expr)}. A query-dependent Rust expression is not a term.
The same CQ-Closed judgment applies to atom operands: a query-closed expression
restricts that occurrence exactly as a literal does. Normalization introduces
a fresh atom column and a relational equality to the unchanged closed operand,
not an opaque row binding (A-Closed). Row-dependent atom expressions retain
their A-Prefix/A-Local binding placement.
\begin{mathpar}
\Rule{ORD-Admissible}{\leq_{\mathcal R}\text{ total, terminating and consistent with identity}}
 {\mathcal R\text{ admits relational order}}

\Rule{CQ-Closed}{\fv(e)\cap Q=\emptyset}
 {Q\vdash e:\mathsf{Closed}}

\Rule{CQ-Comparison}{x\in B\quad\vars(t)\subseteq B\quad
 t\text{ a variable, literal or CQ-Closed operand}\\
 op\in\{==,\ne,<,\leq,>,\geq\}}
 {\Sigma;B;Q\vdash x\ op\ t:\mathsf{Predicate}}

\Rule{CQ-Where}{\vars(P)\subseteq B\quad
 P\text{ follows the relational grammar; each closed operand satisfies CQ-Closed}}
 {\Sigma;B\vdash\mathsf{where}\ P\Rightarrow B}
\end{mathpar}
Membership denotes a disjunction of representation equalities; ranges use
representation order with the written open or closed upper endpoint.
Conjunction and disjunction are classical connectives, not Rust evaluation.
The representation laws are premises, and rustc checks required trait bounds;
no \code{syn::Type} spelling establishes or refutes them.
At a column with code domain $D$, every operand of a comparison, membership,
range or atom position is compared as a code: normalization translates it into
a capture of $D$'s code (A-Domain, Section~\ref{sec:passes}). There is no
string comparison, string literal form or string scan in any later IR.

\paragraph{One Rust expression.}
Every \code{if}, \code{let} and \code{for} expression is opaque, pure and total
by premise. It is never split, recognized, rewritten or type-checked by this
compiler, including arithmetic and comparison syntax. Its original expression
and lexical bindings survive printing unchanged. Only its conservative free
variables govern placement; lexical opacity requires the whole environment.
Only explicit \code{where} produces relational constraints, join equalities,
point/range/membership reads, filter ranks, reduction supports and derived
domains. Atom literals and normalization identities remain occurrence facts.

\paragraph{Normal form.}
CQ$_{\rm NF}$ restricts the same \code{cq::Program}: every positive atom argument is a
distinct bare variable or a literal, every head argument a variable. Negated
atoms retain bound variables, constants and wildcards and never bind names.
Shared names across atoms are natural-join variables. Literals remain in their atom: they
restrict the corresponding declared columns and drop those columns from the
occurrence's heading. They bind no variable and are not guards. Repeats within
an occurrence become relational identities at the atom's position; computed
arguments become positioned binds plus identities; a row-dependent computed head
becomes a final bind.

\paragraph{Captures.}
A query records its host-once values in
\code{capture \{ let p[:T] = e; if e; \}} after the body and group. A capture
reads no query variable and binds host names, never valuation columns; every
later IR carries the list unchanged. A top-level query-closed \code{let} or
\code{if}, a closed head operand and a closed aggregate argument are captures
(A-Capture). A query-closed branch \code{let}/\code{if} is a fresh capture
whose branch binder or guard stays in place as a capture reference
\code{let p = capture c} / \code{if capture c} (A-CaptureRef), so union
interfaces keep their binders. A \code{let} capture is printed once as an owned
value with a reference binder. Every move closure that reads it owns a
\code{Clone::clone(\&value)} made at closure creation and rebinds its reference.
An \code{if} capture gates the whole answer (IF-Capture).
Capture binders are in scope when checking the body and head. After hoisting,
their occurrences on either side of a relational \code{where} predicate are
closed host operands, including equalities resolved before hoisting. Such a
predicate remains a relational restriction, not an opaque Rust guard; its
capture value is evaluated once without recognizing or rewriting Rust.
A-Domain records a distinct typed capture
\code{domain k:T in [id] (D) = f(t)}, with $f\in\{\mathsf{exact},\mathsf{lower},\mathsf{upper}\}$.
Only its Rust realization prints \code{::cq\_storage::domain::f(\&(D), \&(t))}.
An authored \code{let} containing that identical Rust call remains opaque.
Normalization and WF-Domain inspect only the typed record, allowed function
and recorded domain id, never Rust expression equality or the generated call.
This uniform rule applies at every closure nesting level and in every
translator; direct reads use the original value. Rust requires \code{Clone}
where a closure needs a copy. \code{Copy} values need no allocation;
non-\code{Copy} values pay their own clone cost per closure instance.
Authors may explicitly wrap large values in \code{Rc} or \code{Arc}.
The compiler introduces neither shared handles nor capture-induced collection.

\paragraph{Contract.}
$\mathsf{CQScope}(s)$ is the scope rules plus:
(1)~relation and column names unique, declared arity positive, no attributes;
(2)~body atoms name declared inputs at their arity;
(3)~lets and generators do not shadow bound names; the body has an atom; the head has positive arity;
(4)~a declaration named by the head is the result: matching arity, no host value;
without it, head arguments are bound bare variables of known type;
(5)~blocks have equal interface types and no escaped local names;
(6)~negated atoms obey CQ-Neg (Section~\ref{sec:guards-design}); aggregation
and unexpanded \code{name!\{..\}} clauses are rejected;
(7)~relational predicates follow the \code{where} grammar, use bound query
names and have query-closed Rust operands; types are checked only by rustc.
\begin{mathpar}
\Rule{WF-CQ}{\mathsf{CQScope}(s)}{\mathsf{WF}_{CQ}(s)\Downarrow\ok}

\Rule{WF-Capture}{\fv(e_c)\cap Q=\emptyset\quad\mathsf{binders}(c)\cap Q=\emptyset\quad
 \text{binders distinct}\\
 \text{each }\code{capture c}\text{ reference names a }\code{let}\text{ capture binder}}
 {Q\vdash\mathsf{captures}\Downarrow\ok}

\Rule{WF-NF}{\mathsf{WF}_{CQ}(s)\quad\text{every nested positive atom has distinct variables or literals}\\
 \text{head arguments are bound variables or captures}\quad
 \text{no top-level or branch query-closed }\code{let}/\code{if}\text{ remains}}
 {\mathsf{WF}_{NF}(s)\Downarrow\ok}

\Rule{WF-Domain}{\forall x.\ \text{all positive occurrences of }x\text{ sit at columns with one recorded domain id }d_x\ (\text{or none})\\
 \text{every closed operand compared with }x,\ d_x\ne\bot,\text{ names a typed capture }\mathsf{Domain}(k,T,f,d_x,D,t)\\
 f=\mathsf{exact}\text{ for }=,\ne;\quad f\in\{\mathsf{lower},\mathsf{upper}\}\text{ for }<,\geq\quad
 \text{a declared answer domain id equals its head variable's }d_x}
 {\mathsf{WF}_{Dom}(s)\Downarrow\ok}
\end{mathpar}
Representation admissibility and Rust totality remain semantic premises.

\paragraph{Meaning and rewrite check.}
The meaning is Section~\ref{sec:denotation}: compose the desugared body in
written order. Its total relational specialization agrees with classical
$\sem q_I$. CQ records no decisions. A same-language CQ rewrite must be AST
identity; raw-token surface expansions run before the CQ contract and have no
semantic contract of their own.
