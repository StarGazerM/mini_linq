\section{Introduction}
\label{sec:introduction}
A conjunctive query specifies satisfying valuations while leaving join order,
indexes and tuple enumeration to a compiler. MiniLinq exposes those choices
through independently usable languages embedded in Rust: CQ, named relational
algebra, index requirements, local access plans and iterator pipelines.
A pass transforms one language into another; lower-language quotations can
also enter the compiler directly. Physical compilation emits ordinary Rust
containing local quotations for later macro expansion.

This architecture extends the representation independence illustrated by
Ascent and BYODS~\cite{paper-byods} to compilation decisions. Replacing
storage, a join algorithm, or an execution discipline should require changing
the passes that own those decisions. Each IR must retain its own local
contract, so independently authored lower programs remain valid inputs.
Section~\ref{sec:staging} states the corresponding composition requirement.

Native Rust expressions make the planning problem richer than classical CQ.
An atom such as \code{U(f(k,y),g(x,z),w)} has three physical columns but
mentions five logical variables. Its first two arguments require values
from other clauses; its third can supply a new value. A let introduces a
directional dependency, and a guard may become applicable inside an earlier
join subtree. Lexical dependencies determine availability, while movement
and projection additionally need semantic assumptions about the host code.

We specify the implemented compiler through:
\begin{enumerate}
\item A worked acyclic query through every IR, including composite keys,
both Yannakakis sweeps, filter pushdown and projection.
\item Administrative rules and deterministic algorithms for graph analysis,
dependency scheduling, RA construction, indexing and local lowering, with
their invariants and conditional preservation arguments.
\item Independent query/RA oracles, compiled execution tests, and mutation
checks that distinguish answer correctness from the intended planning steps.
\end{enumerate}

The focus is correspondence between the compiler and these rules. Classical
join theory supplies the graph results~\cite{ahv,notes}; Rust parsing supplies
host syntax. Neither proves correctness for arbitrary effectful Rust.
The relational claims assume total, deterministic, representation-independent
host computations. An implemented lazy/materialized counterexample shows why
this restriction matters. Negation, aggregation and broader optimizer search
remain outside successful lowering. Pull execution and eager push-to-set execution
are implemented alternatives with distinct demand contracts; WCOJ remains a separate
design obligation.
