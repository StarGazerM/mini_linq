\section{Checked pass pipelines and composition}
\label{sec:staging}
A macro invocation transports a complete program and an explicit queue of
remaining pass paths. Each path may carry argument tokens interpreted only by
that pass. Let $T$ be raw tokens, $s,t$ typed programs, $\pi$ a queue, and
$\mathsf{quote}$ token serialization.
\begin{mathpar}
\Rule{ST-Entry}{\pi=\mathsf{resolve}(configuration,defaults)\quad\pi\ne[]}
 {\code{mini_linq::compile!}\{configuration;\ T\}
  \longrightarrow\mathsf{start}(\pi,T)}

\Rule{ST-Next}{\operatorname{parse}_L(T)=s\quad\mathsf{WF}_L(s)\\
 f(s,args)=t\quad\mathsf{WF}_M(t)\quad M\ne Rust\quad\pi=k(args')::\pi'}
 {\mathsf{pass}_f(args,\pi,T)
  \longrightarrow k!\{args';\ \pi';\ \mathsf{quote}(t)\}}

\Rule{ST-Terminal}{\operatorname{parse}_{Structures}(T)=s\quad
 \mathsf{WF}_{Structures}(s)\\
 e=\mathsf{print}(s,args)\quad\pi=[]}
 {\mathsf{pass}_{print}(args,\pi,T)\longrightarrow\mathsf{quote}_{Rust}(e)}
\end{mathpar}
ST-Entry resolves named phases and starts the first selected macro on raw
tokens; when the surface list is empty, that macro is the planner.
The default \code{mini_linq!} uses the same queue with default configuration.
CQ parsing and its contract occur at the planner, after surface expansion.
ST-Next is \code{cq_stage::pass}: it checks source and target contracts.
The generic \code{pass} wrapper does not call an independent correspondence
check: that belongs to the callback/constructor. Default planning calls order
and elaboration checks, default lowering and selection constructors call
their checks, and the index constructor checks only local IX (its independent
first-use check is separately callable);
\code{cq_stage::rewrite} additionally invokes the language's
\code{check_rewrite}. Parse, contract, transformation, and queue failures emit
\code{compile_error!}. A nonterminal language requires a remaining pass;
a terminal Rust expression requires an empty queue. Rust subsequently checks
the generated expression's types, ownership, and runtime trait obligations.

\paragraph{Named grammar and explicit queues.}
The facade accepts the following grammar, where parentheses are optional:
\begin{lstlisting}
pipeline {
    surface = [Path(tokens), ...];
    plan = Path(tokens); ix = Path(tokens); lower = Path(tokens);
    physical = [Path(tokens), ...]; select = Path(tokens);
    structures = [Path(tokens), ...]; print = Path(tokens);
}
\end{lstlisting}
The resolved order is surface, plan, ix, lower, Physical rewrites, select,
Structures rewrites, print. Omitted single phases use
\code{plan_written}, \code{index_demands}, \code{lower}, \code{select}, and
\code{print_pull} under \code{mini_linq::passes};
omitted lists are empty. The protocol does not register or choose external
pass names. An authored IR can enter directly at a compatible macro:
\begin{lstlisting}
Path! {
    arguments { tokens };
    pipeline { Next(tokens), Printer };
    <complete program>
}
\end{lstlisting}
The arguments packet is omitted when empty. Each continuation receives only
its arguments, the remaining queue, and the complete target program.
Physical records operators, modes, canonical boundaries, and intersection or
semijoin choices. Structures records built types and levels, host fallbacks,
retained rows, and dedup state. The printer consumes these recorded decisions.

\paragraph{Rust contexts and external consumers.}
Ordinary Rust contexts contain checked query invocations. The pass expansion
replaces the invocation in place:
\[
\Rule{ST-Context}{\mathsf{pass}_f(args,\pi,\mathsf{quote}(s))\longrightarrow T'}
 {C[\mathsf{pass}_f(args,\pi,\mathsf{quote}(s))]\longrightarrow C[T']}.
\]
The protocol does not check arbitrary Rust closing contexts: rustc supplies
name resolution, typing, and lifetime checking. The input/output and
environment interfaces are specified in Section~\ref{sec:pass-contracts}.
The \path{features/composition/} consumer writes a complete named pipeline over
heterogeneous borrowed hosts. Other standalone feature workspaces insert
planners, rewrites, languages, surface expansions, and printers through the
same public protocol. Planners record VO/RA choices; rewrites use exported
language checks; the own-dialect push printer consumes Structures and rejects
merge and smallest-candidate choices it cannot realize. Surface consumers
expand negation into completed membership inputs, aggregation into folds over
distinct core answers, correlated exists/scalar into per-row core invocations
(with a scalar cardinality panic), and recursion into an external set fixpoint.
These are Rust contexts over public input/output/environment interfaces,
not new core IR operators or privileged pipeline registrations.
The out-of-tree gate packages the core and builds/tests
every consumer without core source paths; an in-tree escape fails the gate.

\begin{theorem}[Conditional composition]
\label{thm:composition}
Suppose $f:L\to M$ and $g:M\to N$ terminate on their declared domains,
$f$ produces only inputs admitted by $g$, and $f$ establishes the representation
and runtime preconditions required by $g$. If both preserve a common observation
under compatible closing contexts, then $g\circ f$ preserves that observation.
\end{theorem}
\begin{proof}
Compose the intermediate and final representation relations and their
observation equalities. Domain inclusion establishes that $g$ is defined.
Closing-context adequacy permits the same argument for macro invocations.
\end{proof}
Semantic preservation and authored expansion agreement remain independent
obligations. Structural checks do not prove host adequacy or reproduce every
construction choice; completed answer sets do not establish effect traces.
