\section{Denotation model}
\label{sec:denotation}\label{sec:scope}

\subsection{Valuations and named algebra}
\label{sec:valuations}
Following AHV~\cite[Sections 3.1--3.3, 4.2]{ahv}, fix disjoint sets of
attributes $\att$, variables $\var$, relation names and values $\data$. A schema
$R[U]$ has finite sort $U\subseteq\att$; a named tuple is $t:U\to\data$, and
$t[V]$ restricts it. The compiler also records declared column order and Rust
types $\Sigma(R)=\langle A_0:\tau_0,\ldots,A_{k-1}:\tau_{k-1}\rangle$; positional
rows use this order. A valuation $\nu:X\to\data$ extends to constants by
$\nu(a)=a$. With an injection $\iota:\var\to\att$, a conjunction $C$ of atoms
has the valuation relation~\cite{notes}
$\Val_I(C)=\{\widehat\nu\mid I\models C[\nu],\ \dom\nu=\vars(C)\}$.
For $L:V$ and $M:W$:
\[
\begin{aligned}
 L\bowtie M&=\{t:V\cup W\to\data\mid t[V]\in L,\ t[W]\in M\},&
 \pi_UL&=\{t[U]\mid t\in L\},\\
 L\ltimes M&=\pi_V(L\bowtie M),& \mathbf1&=\{\langle\rangle\},
\end{aligned}
\]
renaming $\delta_m$ for injective $m$, and for $F\subseteq V\cap W$ the antijoin
$L\triangleright_FM=\{l\in L\mid\nexists m\in M.\ l[F]=m[F]\}$.
Then $\Val_I(C_1\land C_2)=\Val_I(C_1)\bowtie\Val_I(C_2)$, and for head variables
$\bar h$ with $H=\set(\bar h)$,
$\sem q_I=\operatorname{out}_{\bar h}(\pi_H\Val_I(C))$ where
$\operatorname{out}_{\bar h}$ fixes answer order and repeated positions.
In a positive atom, literal positions restrict the declared relation before
its other columns are renamed: for source-column bindings $C$ and the remaining
column map $m$, its relation is $\delta_m(\pi_{\dom m}\sigma_C I(R))$.
Literal columns therefore do not bind variables. This is an occurrence read,
not a subsequent guard; dependent argument binds see only its matching rows.


\subsection{The written-order denotation}
Let $T X=\operatorname{Set}_{\rm fin}(X)$, $\eta(x)=\{x\}$ and
$A\bind f=\bigcup_{x\in A}f(x)$ for $f:X\to TY$.
Atoms and relational identities return their matching extensions.
For fixed host captures $h$, write $v_h(t,\rho)$ for a query value $\rho(t)$,
a literal value, or the once-host-evaluated value of a closed operand.
With representation equality $=_{\mathcal R}$ and order $\leq_{\mathcal R}$:
\[
\begin{aligned}
 \sem{\mathsf{where}\ P}_h(\rho)
   &=\{\rho\mid\sem P_h(\rho)\},\\
 \sem{x==t}_h(\rho)&=(\rho(x)=_{\mathcal R}v_h(t,\rho)),\\
 \sem{x<t}_h(\rho)&=(\rho(x)<_{\mathcal R}v_h(t,\rho)),\\
 \sem{x\ \mathsf{in}\ [t_1,\ldots,t_n]}_h(\rho)
   &=\bigvee_i(\rho(x)=_{\mathcal R}v_h(t_i,\rho)),\\
 \sem{x\ \mathsf{in}\ a..b}_h(\rho)
   &=(v_h(a,\rho)\leq_{\mathcal R}\rho(x)<_{\mathcal R}v_h(b,\rho)).
\end{aligned}
\]
Inclusive ranges replace the last $<$ by $\leq$; the remaining comparisons
use the same equality/order, and $\sem{P\mathbin{\&\&}Q}=\sem P\land\sem Q$,
$\sem{P\mathbin{||}Q}=\sem P\lor\sem Q$.
A Rust guard returns $\{\rho\}$ or $\emptyset$ by its unchanged Rust
expression; a scalar Rust bind returns one extended valuation.
Starting at $\{\langle\rangle\}$, compose the desugared body in written order, then the
head. This is the reference meaning. The executable reference is Written/Coarse
VO from \code{cq_order::compile_written}, with recorded correlated blocks,
elaborated by \code{cq_elaborate::compile_written}, which forbids reductions,
splitting, reordering, hoisted blocks, predicate pushdown and alias solving.

For a generator, evaluate $e$ in the incoming environment $\rho$, convert it
with \code{IntoIterator::into_iter}, and exhaust its finite yielded sequence
$v_1,\ldots,v_n$. All these operations are pure and total by premise:
\[
 G_{p,e}(\rho)=\{\rho[p\mapsto v_i]\mid 1\le i\le n\},\qquad
 \sem{\mathsf{for}\ p\ \mathsf{in}\ e}(A)=A\bind G_{p,e}.
\]
The pattern is irrefutable and its names are fresh. Empty iteration removes
the incoming row; yielded order and duplicate witnesses are unobservable.
Scalar \code{let} is the singleton special case
$\eta(\rho[p\mapsto v])$, not iteration over $v$.
This is correlated unnest (the nested relational calculus's collection bind),
not aggregate nest: it neither groups rows nor collects an aggregate value.

\begin{definition}[Refinement]
A target refines a source when $\sem S_I=\sem T_I$ for every input $I$
satisfying the premises. We retain $\sqsubseteq$ as notation for this
answer-preservation obligation.
\end{definition}
Panics violate the totality premise rather than defining successful
optimization opportunities. Runtime allocation/device failures may still abort
execution, but must never produce truncated success. I/O, mutation, addresses,
destructor traces, evaluation counts, divergence and resource exhaustion are
outside the meaning. Runtime streams may repeat witnesses; explicit canonical
boundaries establish sets.

\subsection{Premises}
\label{sec:premises}
\begin{enumerate}
\item \textbf{Leibniz admissibility.} Representation equality decides value
identity for every column compared, joined, keyed, grouped or deduplicated.
The compiler does not classify host types to prove or reject this law.
\item \textbf{Order.} Representation order terminates and is a total order
consistent with identity. Rust checks required trait bounds, not these laws.
\item \textbf{Total functional Rust.} Every embedded Rust expression is pure,
total and depends only on its free query values and fixed host captures.
Query values are supplied as \code{\&T}; borrowing alone proves none of
these premises. A panic means the plan violates the contract.
\item \textbf{Finite pure generators.} Construction, iterator conversion and
polling terminate normally and yield finitely many values. Their set-valued
meaning depends only on free query values and fixed captures.
\item \textbf{Free-variable preservation.} Rust syntax and lexical bindings
are unchanged. Placement requires its free variables, conservatively the
whole lexical environment for opaque syntax, and imposes no relative order
between independent Rust expressions.
\end{enumerate}
\begin{lemma}[Motion]
A pure total Rust expression or relational predicate may be placed at any
point where all its free variables are bound, provided its outputs remain
available to every consumer and branch correlation is preserved.
\end{lemma}
\begin{proof}
Evaluation depends only on the retained free values. Moving across an
independent relational operation changes the intermediate evaluation domain
but not any complete witness or its computed values. Totality ensures every
such intermediate evaluation is defined; set union and join then give the
same result. The argument also applies to finite set-valued generators.
\end{proof}
Consequently any representative of representation-equal values is the value;
deduplication and canonical projection retaining all free variables are sound.
Planning records the chosen placement, and downstream refinements preserve it.
The host boundary is
\[
\Rule{H-Eval}
 {\Gamma_H;\Gamma_Q\vdash_H e:\tau\quad \rho\approx_{\Gamma_Q}\nu\quad
  \langle e,\rho,\sigma\rangle\Downarrow_H(v,\sigma',\alpha)}
 {\langle\mathsf{host}[e],\nu,\rho,\sigma\rangle\Downarrow(v,\sigma',\alpha)}
\]
where $\Gamma_Q$ gives logical types and representation modes, $\Gamma_H$ host
bindings and $\rho\approx\nu$ that Rust bindings represent $\nu$; rustc checks
the elaborated context. Totality is a premise on all admissible input values,
not just rows reached by one written-order plan; the compiler does not prove
it by analyzing arithmetic, types or expressions.

\subsection{Disjunctive blocks}
\label{sec:blocks}
A block runs at a prefix row $\rho$. Let $F$ be the prefix names used inside it
and $I$ the names bound in every branch; other branch bindings are local. Write
$L_j(\rho)=\pi_{F\cup I}\sem{B_j}(\rho)$.
\begin{mathpar}
\Rule{Block-Union}{\forall j,\ \sem{B_j}(\rho)\text{ is finite}}
 {\sem{\{B_1\}\mid\cdots\mid\{B_n\}}(\rho)=\bigcup_j L_j(\rho)}

\Rule{Block-Else}{\forall j<k,\ \sem{B_j}(\rho)=\emptyset\quad
 \sem{B_k}(\rho)\ne\emptyset}
 {\sem{\{B_1\}\ \mathsf{else}\ \cdots\ \mathsf{else}\ \{B_n\}}(\rho)=L_k(\rho)}
\end{mathpar}
Union branch order is not meaning, so any permutation or answer-determined
witness short circuit preserves the result. Fallback order is meaning: a
later branch contributes only where earlier ones are empty; if all are empty
the result is empty. Neither operator assumes disjoint branches or any key or
data property. Rust \code{||} inside a guard keeps Rust's meaning. Laws:
\[
 C\bowtie(L\cup M)=(C\bowtie L)\cup(C\bowtie M),\qquad
 B_1\ \mathsf{else}\ B_2=B_1\cup(B_2\triangleright_F B_1).
\]
Fallback arms are disjoint by construction. A union is statically disjoint only
if every pair of arms has some interface column with different proved literal
values. Positive semijoin reductions distribute into union arms and into the
positive uses of fallback arms; the negated operand of an antijoin is always the
unmodified named branch result.
