# Compiler names and their boundaries

Compiler crates use source-oriented `*-lowering` names; policy and composition
remain explicit. Runtime structures use data names. A macro's name identifies an
implementation or composition entry, while its caller-bound path can select a
different implementation with the same semantic contract. Names do not establish
that compatibility by themselves.

The inventory follows the [workspace manifest](../Cargo.toml),
[frontend exports](../crates/mini-linq/src/lib.rs) and
[feature declarations](../crates/mini-linq/Cargo.toml). It includes all **44 exported
procedural macros**, including exports generated by `native_entry!`.

## Crates and implementation modules

| Crate | Implemented boundary or responsibility | Implementation modules |
| --- | --- | --- |
| [cq-ir](../crates/cq-ir/src/lib.rs) | Syntax, validity and structural facts; no lowering policy | `cq`, `relational_plan`, `index_requirements`, `rust_access_plan`, `iterator_pipeline`, `native` |
| [cq-query-lowering](../crates/cq-query-lowering/src/lib.rs) | CQ → RA, including scheduling, YA and derivations | `written_order`, `clause_prefix`, `hypergraph` |
| [cq-index-policy](../crates/cq-index-policy/src/lib.rs) | RA → IX, preserving RA and selecting equality demands | `base_demands`, `result_demands`, `no_demands` |
| [cq-relation-lowering](../crates/cq-relation-lowering/src/lib.rs) | RA or IX → Rust with Access/Native, including layout, lifetimes and hosts | `base_hash`, `prefix_hash`, `materialized_hash`, `configured`, `borrowed_nested` |
| [cq-native-lowering](../crates/cq-native-lowering/src/lib.rs) | Native → Rust or further Native/Access invocations | `rows`, `candidates`, `keys`, `witnesses`, `pairs` |
| [cq-access-lowering](../crates/cq-access-lowering/src/lib.rs) | Access → Pipeline, or Access → eager Rust | `to_pipeline`, `to_set_loops` |
| [cq-pipeline-lowering](../crates/cq-pipeline-lowering/src/lib.rs) | Pipeline → Rust, with a selected observation | `distinct_iter`, `collect_set`, `support_iter`, `exists` |
| [cq-compose](../crates/cq-compose/src/lib.rs) | Typed recipes and dispatch over existing functions | `indexed` and public typed compositions |
| [cq-storage](../crates/cq-storage/src/lib.rs) | Runtime data structures, operation traits and counters | Blocks, selections, summaries and replay; no relational interpreter |
| [mini-linq](../crates/mini-linq/src/lib.rs) | Proc-macro frontend, parsing, dispatch and continuation paths | `entry`, `workload`, and administrative input parsers |

`cq-query-lowering` is not a separate RA optimizer: it schedules while producing
RA from CQ. `cq-index-policy` chooses requests, including no demands; it is not
merely factual analysis and allocates no index. Native and Access lowerings run
during compilation; their generated operations run during query execution.

`mini-linq-course` is the teaching/example root; [cq-workloads](../workloads/Cargo.toml)
is the query/data catalog. [cq-xtask](../xtask/Cargo.toml) is a separate tooling
workspace for generation, explanation and differential checks. None is an IR stage.

Within an implementation, `compile` lowers, `check_domain` checks admission, and
`check` checks source/target correspondence where supplied. Host-specific names
such as `compile_program` and `compile_callable` distinguish Rust output shapes.
The `hypergraph` implementation keeps policy (`strategy`), administrative rules,
YA reduction and checking separate. Pipeline endpoints share `operators` for
Rust adapter emission. Native `rows::replay` admits only Build/Scan; its module
placement does not give it the entire row-set operation protocol.

## Caller-bound names and administrative paths

[Generated frontend paths](../crates/mini-linq/src/lib.rs),
[input bindings](../crates/mini-linq/src/entry.rs) and
[Native configuration](../crates/mini-linq/src/native_input.rs) specify these roles.

| Binding / configuration | Meaning |
| --- | --- |
| `mini_linq`, caller-authored `mini_linq::query` | A facade module alias and an optional user-chosen macro alias. `query` is not an exported macro. |
| `choose_index_policy`, `choose_relation_lowering` | Caller-relative stage slots with stock dispatcher implementations; a facade may bind a compatible explicit implementation directly. |
| Explicit CQ, index, relation, `access_to_*` and `pipeline_to_*` paths | Other generated caller-relative continuations. Their names may identify an implementation or observation; all replacements owe the actual boundary contract. |
| `inputs::R`, `replay_resource`, `storage` | Per-input Native macro, replay Native macro and Rust storage path. Only the first two are macros. |
| Native `access_iter` | An Access-to-iterator continuation used by the selected operation; it is not a Pipeline input or a runtime iterator value. |
| Native `storage`, `keys`, `work`, `packing` | Storage path, collection type path, observer expression and packing expression, where admitted by the selected operation. |

[Configured relation directives](../crates/mini-linq/src/relation_input.rs) select
`inputs`, `result_rows`/`result_bindings`, `candidates`/`candidate_bindings`,
`keys`/`key_sets`, and `pairs`/`pair_bindings`; `access` selects its Access
continuation. `counter_storage` belongs to observed hosts. Native `storage`
selects operation data structures. Native operations `scan` and `materialize`,
and Pipeline `join`, remain language syntax, not administrative directive names.

## Distinct boundaries retained by these names

- Configured lowering accepts **RA**, while hash and borrowed lowerings accept
  **IX**. They are not interchangeable implementations of one identical input API.
- Pull emits **Pipeline**; push emits **Rust**. They can satisfy the same set
  observation at a composed Access hole, but do not implement one identical edge.
- Native implementations admit partial operation domains and may emit further
  Access/Native calls. A provider name does not prove universal capability.
- Logical planning does not consume later storage/execution choices. The naming
  convention does not add planning feedback, wrappers or new compiler stages.
