# GPU SIMT study, packed-run audit, and library-first design

## 1. Execution and cooperation

- SIMT executes a common instruction for the active lanes of a 32-thread warp; divergent paths execute with different masks, not as 32 independent scalar processors. Independent thread scheduling does not authorize implicit warp-synchronous memory communication. [CUDA model][G], [warp primitives][W].
- SIMD-like decoding requires a regular data decomposition: uniform control, lane-affine adjacent addresses, independent lane streams, and a common shift/mask/straddle decision for each decode step. Interleaving plus width specialization supplies these properties; merely invoking a scalar extractor in 32 threads does not. [FastLanes §2.1–2.2][F], [FastLanes-GPU §4–5][FG].
- Nuance: a variable shift with different operands per lane can still issue as one SIMT instruction; it does not itself serialize 32 paths. It prevents immediate specialization and, in row-major extraction, accompanies lane-dependent word positions/straddles. The expensive dependent load→shift chain and control divergence must be measured separately. [G], [FG §3], our [decode counters][M].
- On SM60+, a global warp access is serviced by the distinct 32-byte sectors touched: 32 aligned consecutive u32 loads require four sectors, eight consecutive u32 loads one; alignment or scattered addresses can increase this. A low sector/request ratio can also mean broadcast or few active lanes, not high useful bandwidth. [CUDA best practices §10.2.1][BP].
- u32 arithmetic is appropriate for proven block-local bit offsets and ≤32-bit residuals; pointers, global row counts, wide logical keys and wrapping checksums may still need u64. Two 32-bit registers carry a u64, and this toolchain implements u64 shuffles as two b32 shuffles. Do not narrow values without an invariant. [oxide warp.rs:438–549][O], [M].
- Dependency chains constrain latency hiding even at nearly 100% L2 hits. Our state-137 shuffled packed lookup has 342.688 us, 62.89% occupancy, 64 registers/thread; the plain-only specialization achieves 281.248 us, 98.20%, 28 registers. These are our NVTX-selected measurements, not architecture-independent constants. [M], artifacts `base-137-prefix_shuffled-packed`, `a-137-prefix_shuffled-plain`.

### Warp primitives: contracts and costs

| Primitive | Semantics and cost model | Appropriate replacement |
|---|---|---|
| Indexed/up/down/xor shuffle | Register exchange inside a named mask; b32 costs one shuffle instruction, b64 two in this toolchain; latency depends on architecture/dependencies, not an assumed “2 cycles”. All named non-exited lanes must participate and source lanes must be valid. [W][O] | Broadcast bounds, tree reductions, scans; replaces shared store+load+barrier only within the group. |
| Ballot / any / all | Predicate→mask or vote; one warp collective plus surrounding predicate/control instructions. A membership mask is computed before divergent work, not inferred later from `active_mask()`. [W][O] | Empty-group exits, group comparison outcomes, stable compaction rank. |
| Match-any | Returns participating lanes with the same label; sm70+; then popcount/first-set-bit/shuffle can aggregate same-output atomics. Neither latency nor benefit is free; number of labels matters. [W][O] | Group equal probe/output IDs; avoid one atomic per row when labels repeat. |
| Lane masks + popcount / first-set-bit | `popcount(ballot & lanemask_lt)` gives stable lane rank; `trailing_zeros` elects the first set lane only for nonzero masks. One ballot plus integer bit operations, not a block scan. [W][O] | Small-admission selected-row compaction; masked-group leader selection. |
| Warp reduce / scan | A 32-lane software butterfly or Kogge–Stone scan uses five exchanges plus combines; u64 doubles shuffle instructions. SM80+ has single-instruction integer b32 `redux` reductions, but not a general u64 scan. [O], [CG] | Min/max per field, checksum reduction, per-warp counts; cross-warp composition still needs shared storage/barriers. |

### Groups and synchronization

- Thread blocks share scratch and synchronize with block barriers; every required member must reach a collective. Warp tiles of 2/4/8/16/32 have fixed group-relative ranks; sub-warp groups increase independent queries per warp but can diverge between groups. [CG][CB].
- Coalesced groups capture currently active lanes, possibly noncontiguous; “coalesced” describes participation, not a promise of coalesced memory addresses. Labeled/binary partitions collectively group equal labels or Boolean predicates. Masks/rank translation are part of correctness. [CG][W].
- Group `sync` provides rendezvous and memory visibility within its scope; shuffle/vote are not substitutes for arbitrary shared-memory ordering. A warp primitive cannot synchronize another warp. Grid barriers require cooperative launch/residency constraints; ordinary independent kernel launches provide stream-ordered global boundaries instead. [CG][W].
- Cluster groups and distributed shared memory require sm90+ and are unavailable on the measured sm89 RTX 6000 Ada. They are not a repair for this study's scheduling problem. [G][O] (`cluster.rs`).
- Use a sub-warp for a small K-ary node or one independent decode-lane group; a warp for contiguous range work; a block for a shared decoded/merge tile or local reorder; a grid for balanced task distribution. More lanes per query reduce independent probes; larger live vectors and scratch reduce residency. Choose from time, useful active instructions, sectors and occupancy together, not occupancy alone. [H][HA][FG][LB], [M].

### Literature mapped to this workload

- Henneberg–Schuhknecht: adjacent pivots plus sub-warp K-ary comparison/ballot, bounded concurrency, pinned upper levels and charged local probe ordering. Our scalar three-pivot attempt is **not** cooperative K-ary search and does not establish that technique's failure. [H], [M] §C.
- Harmonia: narrowed groups trade wasted comparisons against query divergence; partially sorting only significant bits can cost less than a full local sort. Our 256-key bitonic experiment charged all barriers and regressed cache-resident lookups, so its failure is not evidence against every partial-order scheme. [HA] §4, [M] §E.
- FastLanes: round-robin independent lane streams, stored word-interleaved; a thread becomes a lane. Specialize width outside the vector loop so each step has constant shifts/masks and a statically resolved straddle. Consume mini-vectors immediately instead of retaining 32 decoded values per thread. [F][FG].
- Shanbhag/Crystal: load compressed tiles coalescently into shared memory and fuse decode with query consumption; precompute shared metadata. This is distinct from FastLanes: their `decodeElement` still uses lane-dependent scalar bit positions and a u64 extraction. Shared staging alone does not create interleaved SIMD. [T], [TC].
- Local [device-columns/tile.rs](../../device-columns/src/tile.rs) provides a concrete interleaved addressing reference: 16 u64 lane streams, dynamic width, physical-position mapping and predicated reads. It is not the requested u32 width-specialized decoder; port the layout principle, not its remaining scalar shift/straddle path. [INFERENCE from the inspected `unpack`, lines 175–190].
- ModernGPU/Osama: prefix-sum actual range lengths, then inverse upper-bound maps work atoms to source tiles; preserve duplicate offsets for empty ranges. Warp scans and ballot+popcount compaction complement, rather than replace, grid load balancing. [MG][LB][W].

## 2. RCCL inventory and kernel audit

Pinned RCCL `a74cb59fb86ad0b78cf7cb4e1b76cf6cd21a858c` was inspected, including all requested cub files, Thrust range/search/execution surfaces and the four request/capability documents. Code takes precedence over stale checklist prose. [R][RQ][RT][RD][RC].
- **R1 already exists:** `rccl_thrust::{lower_bound,upper_bound,equal_range}` plus `_by`, `_async` forms over `LowerReadRange`, exact-length u64 outputs and completion-retained borrows; no `TemporaryValue` key requirement. Its existing backend is per-thread binary search, two stripes/256-thread tile. Cooperative/fenced compressed-range optimization and workload integration remain open. [R] (`rccl-thrust/src/search.rs`), [RQ] lines 197–244.
- **R2 is missing at the audited pin:** checked range-count preparation plus stable load-balanced expansion/reduction; wrapping scan is insufficient for overflow validation. Public lower/upper search is not absent merely because an earlier paragraph of the request says “currently private”. [RQ] lines 25–40,113–131; [RT] lines 76–79.
- Existing substrate: `DeviceReadAt`, `DeviceMap`, `DeviceZip`, `DevicePermutation`, arithmetic/constant/offset/stride/reverse and writable adaptors; Thrust lowering retains range borrows. `warp_reduce<T,N>` supports u64/f64 as two b32 exchanges; internal `block_scan_sum_128/256` supports u32/u64 inclusive/exclusive/aggregate sums. Device scan has pooled workspace `_in`; compaction/select/unique/stable partition reuse scan. [R] (`range.rs`, `warp.rs`, `block_scan.rs`, `scan.rs`, `compaction.rs`).
- Merge/set/radix/histogram engines already exist; Thrust exposes merge/set compositions and sync/async execution. Fancy compressed-range merge breadth, generic record combinations, public block scan/radix-sort contracts and checked expand remain incomplete. Histogram even/range supports allocator-owned workspaces and shared/global privatization; it is not a FOR min/max primitive. The radix histogram defect is a separate alternating-buffer selection bug in `radix.rs`, not `histogram_backend.rs`. [R][RT][RC], [defect reproducer][BUG].

## 3. Library-first design and acceptance order

All following API spellings are **proposals**, not claims of implemented primitives. General mechanisms belong in RCCL; run fences/headers/cutoff, publication, set/ratio law and relational checksum meaning stay in mini_linq. No RCCL compiler, proc macros, public architecture/policy types, whole-run unpack, or erased device closures. [RD][RQ].

Primary B layout design [INFERENCE from F/FG]: start with 256 rows, 8 independent u32 lanes ×32 values/lane; column payload is `8*width` u32 words, exactly `256*width` bits for a full block. Four 8-lane subgroups can own independent vectors; do not claim a full warp is uniform when its groups take different width branches. Compare a warp-uniform 32-lane padded-256 variant and an exact 1024-row/32-lane variant, reporting actual xalan bytes and frame-width effects; partial blocks need explicit tail storage. For row r: lane=r%L, step=r/L, word=(step*width/32)*L+lane; random access costs one or two u32 loads plus variable u32 extraction, while the scan path has statically resolved steps. Metadata and suffix-search costs count too.

The three mandatory B controls are the original row-major binary, the measured leaner scalar u32 candidate (`b-*`), and interleaved width-specialized decoding under the **same** scheduler and NVTX scopes. Compare active instructions/row, uniform/divergent branch targets, branch PC samples, sectors/request, registers/occupancy, default-build time, bytes and admission; compare sorted/shuffled/membership at xalan and 2^28 states 90/112. Retain interleaving only if scans improve without losing lookup time or footprint. No SIMD label substitutes for those measurements. [M], user acceptance contract.

Measured priority is scan/decode and reusable scheduling first (baseline packed xalan scan 89.625 ms; scale112 14.971 ms), then shuffled lookup dependencies (44.434 ms xalan), then sorted/membership and charged locality; admission changes are limited to format production and duplicated general mechanics. The private scheduler prototype is a performance reference, not the intended library boundary. Existing measured/rejected variants are preserved in [M]; prior kernels stop changing until this notes/audit/design commit lands.
