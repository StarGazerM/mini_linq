Raw samples, provenance, counts, exactness evidence, page faults and diagnostic kernel totals:

## Same-workload headline

On the same local RTX 6000 Ada, **xalan field-flow fixpoint is 0.880 s in
`srd-doop-gpu` versus 1.187 s in live SRDatalog**, ratio **0.741
[0.598, 0.943]** (ours/SRD, five paired rounds). Both evaluate the same
43-IDB field-flow program and passed complete tuple comparison against the
CPU implementation. This is a fresh measurement, not the Oct 26 default-query
reference range and not a comparison against a different MiniLinq revision.

**The user stopped further runs.** Xalan completed five rounds; Batik completed
only one. Batik is an exactness-checked observation, **not a five-pair timing
result**; no Batik ratio or CI is claimed. Cassandra was not measured. Thus this
report replaces the historical cross-engine timing anchor for xalan only,
not with a new statistically supported Batik result.

| Dataset | Samples per engine | `srd-doop-gpu` fixpoint s | Live SRD field-flow fixpoint s | Ours/SRD [95% CI] |
|---|---:|---:|---:|---|
| xalan | 5 | 0.879856 | 1.186655 | 0.741 [0.598, 0.943] |
| batik | 1 | 1.929317 | 1.844103 | Not estimated: one pair |

The xalan effect is not within 5% of unity, so no small-effect or linker-layout
claim is made. The CI is wide and host load varied substantially; this is not
an unloaded-machine or steady-state guarantee. No default or planner was changed.

## Boundaries and phases

All entries are medians in seconds (Batik: the single observation). **The
end-to-end columns are boundary-confounded and must not be divided to claim a
cross-engine speedup.** Our evaluation starts after fact loading and CUDA
context creation, includes setup/upload, fixpoint and output download/decoding,
and excludes textual export. SRD native lifecycle includes initialization,
CSV loading, prepare/upload, fixpoint, count collection, TSV download/export
and shutdown. Its export combines transfer and text formatting; no separate
D2H-only measurement exists. Whole-process times, including validation/export
where applicable, are retained in JSON but are not the headline metric.

## Protocol and provenance

- MiniLinq binaries rebuilt from unmodified **`dbe4c2cbf14c360c50a43ec36792f00a43f7dc0b`**
  with Rust 1.99.1, `cargo oxide build --arch sm_89 -- --release -p doop-gpu
  -p srd-doop-gpu`, CUDA 13.0. Executable hashes are in JSON.
- Live SRD is `srdatalog-python` **`fab849f672d43af2a6a1e8a1727ec065201e3720`**,
  using prebuilt **field-flow, baseline-plan** libraries in
  `/tmp/bench-1102/srd-work/builds/{xalan,batik}/field_flow`. Library and input
  checksums were checked by the worker before execution. These libraries use
  CUDA 12.9 (`ldd` resolves `libcudart.so.12` there); CUDA 13 lacks the legacy
  texture header required to build them. The separate historical SRDatalog
  checkout at `953cd1a` was not the executed source.
- Both field-flow engines use
  `/data/doop-bench/doop-vs-srdatalog-20261026/fresh-corpus/prepared/{xalan,batik}`.
  Original DOOP uses `/data/doop-bench/doop-data/{xalan,batik}`.
- Fresh processes; three-engine order rotates each round. Each process holds
  only `/tmp/mini_linq-gpu.lock`, checks `nvidia-smi --query-compute-apps=pid`
  is empty before launch, and records `/proc/loadavg` and GNU-time major/minor
  page faults. All retained processes exited normally; no foreign tenant was
  present at their preflight. No claim of continuous external-tenant monitoring
  is made. Recorded one-minute load averages span **1.95–40.87**, including CPU
  oracles; background work was not excluded by a CPU timing lock.
- First sample of each field-flow engine: all **43/43 IDBs**, integer-normalized
  external sort and byte-for-byte comparison against `srd-doop-mini`, including
  duplicate/count checks. Later xalan samples: exact relation counts plus up to
  **1,000 actual oracle tuples per relation**, reservoir seed 1103, checked in
  the actual exported result (all rows for relations smaller than 1,000).
  This checks substantially more than 1,000 tuples across the complete answer.
  All checks passed. Exports and sorting scratch lived in `/dev/shm`, not `/data`.
- Ratio is median(ours)/median(SRD), paired bootstrap over all **5^5** resamples;
  percentile 95% interval. No unpaired historical range enters the calculation.
- The first orchestration hit its 3,600-second deadline while waiting for a GPU
  lock after xalan's SRD round 2. Completed validated samples were retained and
  the remaining rounds resumed without rerunning them. A later user stop ended
  collection after the first complete Batik round. No interrupted sample is
  included. Lock waits and external exactness scans make the collection span
  much longer than GPU execution time.

## Recorded-plan and expanded-code review

This is characterization of existing engines, not an optimization patch. After
measurement began, a separate diagnostic xalan profile and macro expansion were
requested and inspected. They do not alter or enter the unprofiled samples.
`CQ_GPU_SEQUENCE_DUMP` records the Physical, Structures and graded Sequence
plans; expanded Rust confirms the execution order. Evidence was preserved for
the planner investigation at `/data/design-notes/datalog-plan-evidence/srd/`.
Checked all-hole VO records are under
`/data/design-notes/datalog-plan-evidence/all-holes/field_flow/gpu/`.

Top five **query dispatches** by aggregate GPU time in the diagnostic profile
(not per-rule wall times; common runtime kernels are separate):

| Dispatch suffix | Rule / specialization | GPU ms | Launches |
|---|---|---:|---:|
| `7eab604efe628d96_53` | `VPT_Assign` | 32.106 | 205 |
| `79a98226f93352c2_86` | array-store specialization, hole 100 | 11.265 | 197 |
| `10ef27f8bcf169e8_100` | `VPT_FieldFlow` | 10.980 | 198 |
| `158bd25dd20d4935_55` | `VPT_Local` | 10.118 | 213 |
| `63a408a050bb2d92_92` | array-store specialization, hole 106 | 9.773 | 180 |

The assignment/field-flow variants stream the delta `(heap,frm)` root and probe
resident radix runs by `frm`; `VPT_Local` additionally tests method membership.
Plans record root spreading, 256-thread/four-item root tiles, prefix lookups,
identity integer representation, and previous-output capacity reservation.
Expanded device code performs prefix interval lookup, checked block scans,
parent-owner recovery and packed arena publication; membership filters update
liveness rather than expanding a duplicate-producing relation.

**Suspicious planner choice:** `AIPT_Store_ObjectArray` and
`AIPT_Store_StringArray`, source delta occurrence **3**, are from our default
`srd-doop-gpu` field-flow route (`engine!()`, `delta_first`, **no authored order,
no imported SRD order and no cardinality evidence**). Checked VO atom order is
**[3, 0, 1, 2, 4]**: delta `VarPointsTo(heap,frm)` binds `heap` at the root;
`ReachableSortedIndex[frm]` and `VarPointsTo[base]` expand before the
`Eligible{Object,String}ArrayHeap(heap)` membership at the last atom. Physical
r0 binds `heap`; r3/r5 flatten, r8 filters `baseheap`, and r10 finally filters
`heap`. Expanded Rust confirms that late test. This is semantically correct
but potentially repeats root-bound membership work after fanout. No speedup
from moving it is measured or asserted; such a change belongs to the planner
together with its other join decisions, not isolated authored advice.

The largest shared kernel is radix onesweep **pairs**, **131.533 ms / 21.9%**
of aggregate GPU kernel time. It remains **unattributed** to a relation or rule:
the trace has no NVTX-range or call-stack table, and its generic launch name is
not a rule identity. Aggregate kernel time (overlapping four streams and all
phases) cannot establish a host-gap duration; no host-gap attribution is claimed.
