## Protocol

Five warmups and 21 measured samples per variant, round-interleaved with rotating first variant; CUDA events. Every warmup and sample checked exactly. 5,000 paired-round bootstrap resamples yield 95% percentile CIs. `nvidia-smi` tenant records surround **every** timed sample; clocks and machine load are recorded per group. JSON contains all raw timings, tenant snapshots, environment and clock records.

## Layout, fairness and interpretation constraints

32-lane interleaved bit packing: lane l stores values l,l+32,... as one bit stream; 32-bit words transposed across lanes.
Compact FOR output: a metadata kernel computes base/width and byte sizes, CUB exclusive scan builds compact offsets, and one 32-thread CTA per block packs output; all three stages are timed. Output capacity and CUB scratch are preallocated; output validation decodes all values.
One generic decoder shared by all kernels. Same block/grid/reduction/merge primitive for every variant. No variant-specific launch tuning, no parameter search, no code-domain dictionary optimization. Plain/bytes/FOR/dict use uniform runtime layout dispatch.

A codec can save bytes and still lose: this implementation adds per-row metadata/address/decode instructions; dictionaries also add dependent gathers. These are mechanistic explanations, not measured stall breakdowns. Small resident inputs can benefit from Ada’s cache, so footprint-based rates need not correspond to DRAM bandwidth. Q6 short-circuit access reduces the benefit of compressing late columns. M3 explicitly charges decode and re-encode; M4 explicitly charges compressed transfer plus decode, but not host compression.

- Effective GB/s and floor fractions are modeled storage/access-byte metrics, not measured DRAM transactions. A separate hardware-counter pass is appended below. Cache-line overfetch, repeated cached metadata loads, dictionary cache reuse and co-rank searches are not physically measured.
- M1 count modeled bytes = entire encoded footprint including dictionary. Q6 model weights each column footprint by its actual short-circuit visit fraction, not cache-line-rounded traffic.
- M2 reports probes/s, not a bandwidth floor: binary search and variable expansion cannot be reduced to the full stored footprint per probe.
- M3 model counts plain input+output; FOR model counts encoded input plus decoded input write/read and merged output write/read plus compact output bytes, but excludes repeated merge co-rank reads and metadata scan traffic. Therefore its fraction is a lower-bound traffic model, not attained physical bandwidth.
- M4 floor = theoretical PCIe 4.0 x16 payload encoding limit 31.508 GB/s; end-to-end bytes variant includes all four metadata/data transfers plus decode and output writes. Host encoding excluded.

The counter collector resumes successful existing profiles. Primary runs without `--force` resume successful groups; `--only merge --force` reruns only M3. `run.py --summarize` regenerates the primary summary; subsequently run `profile.py` to reattach existing counter records.
